## 1. 双通道交叉校验定位

**文件**：`src/core/locate.js:31-171` · `locatePosition()`

### 1.1 解决什么问题

"学生卡在第几步"这个判断，交给模型会幻觉，交给关键词匹配又不认改写。
**两个通道各自都不够，但它们的失效方向不同** —— 这正好构成交叉校验的前提。

| 通道 | 实现 | 强项 | 失效方向 |
|---|---|---|---|
| A 关键词 | 学生原话 × 步骤 `cues` 字符串匹配（确定性、可复现） | 不认改写 | 漏判（学生换个说法就抓不到） |
| B 语义 | LLM 输出 `candidateStepIndex` | 覆盖改写 | 幻觉（推断出学生没说的步骤） |

### 1.2 形式化定义

设 $A$ = 通道 A 定位结果（可能为 $\varnothing$），$B$ = 通道 B 定位结果（可能为 $\varnothing$），
$h$ = 通道 A 的最大命中数。置信度 $\text{conf}$：

$$
\text{conf} =
\begin{cases}
0.9 & A = B \neq \varnothing \quad \text{（一致）} \\
\mathbf{0.55},\ A & A \neq \varnothing,\ B \neq \varnothing,\ A \neq B \quad \text{（冲突 ⇒ 采信原话）} \\
0.6 + \min(0.2,\ 0.05h) & A \neq \varnothing,\ B = \varnothing \\
0.6 & A = \varnothing,\ B \neq \varnothing,\ |\text{evidenceQuotes}| > 0 \\
0.2 & \text{其余（未定位）}
\end{cases}
$$

**关键设计：冲突时取 $A$（学生原话），而不是取 $\min(A,B)$。**

### 1.3 代码

```js
// src/core/locate.js:76-95
```

通道 A 的"同分取更靠后"规则（`locate.js:44-50`）—— 学生通常已推进到最远处：


### 1.4 为什么这么写（真模型实测修正的）

早期规则是"冲突时取更靠前的定位（min）"，理由是"保守"。用 glm-4-plus 跑评测发现**大量定位偏差，根因正是这条规则**：

| 场景 | 通道 A（关键词） | 通道 B（语义） | 旧规则取 | 结果 |
|---|---|---|---|---|
| sc-05 | 4 ✅ | 1（模型误判为"判断变化原因"） | 1 | ✗ |
| sc-06 | 3 ✅ | 1（模型误判） | 1 | ✗ |

学生的原话里有 `S=L1L2`、`磁通量` 这类明确线索，而模型的"面积在变"是它自己的推断。
**推断会错，原话不会错。** 改成采信 A 之后，定位命中率 72.7% → 100%。

配套的追问继承（`locate.js:122-136`）—— 防止"学生说然后呢、AI 就失忆"：

```js

  const prior = options.priorPosition;
  const valid = problem.solutionGraphs
    .find((g) => g.id === prior.graphId)
    ?.steps.some((s) => s.index === prior.stepIndex);
  if (valid) {
    graphId = prior.graphId;
    stepIndex = prior.stepIndex;
    // 继承来的定位不能给高置信：本轮学生其实没提供新信息
    confidence = Math.min(0.55, (prior.confidence ?? 0.6) * 0.8);
    carriedOver = true;
  }
}
```

而"追问继承"与"信息不足"必须区分开，否则学生会从零被反问（`route.js:85`）：

```js

if (diagnosis.sufficientInfo === false && !hasPriorContext) { /* 才走纯反问 */ }
```

## 2. 7 类卡点分类

**文件**：`src/core/locate.js:247-304` · `classifyStuckKind()`（文件内 `:240` 起是配套的信号表）

### 2.1 形式化定义

不是"卡住了/没卡住"的二分类，而是 **7 种互不相同的处境**。
分类函数按**优先级顺序**做决策（越靠前优先级越高，因为越靠前的判断越具体）：

| 序 | 类别 | 触发条件（形式化） | 应对方式 |
|---|---|---|---|
| 1 | `dead_end_path` | 发言命中"走不通"信号 | 换工具（`tool_switch`） |
| 2 | `finished` | $\text{step} \ge \text{total} \ \wedge\ |\text{mis}|=0 \ \wedge\ \text{conf} \ge 0.7 \ \wedge\ \neg\text{deadEnd}$ | 沉默 / 确认 |
| 3 | `direction_lost` | $\text{step} \ge \text{total} \ \wedge\ \text{deadEnd}$ | 方向提示 |
| 4 | `not_started` | $|\text{chain}|=0 \wedge |\text{laws}|=0 \wedge \text{step}=\varnothing$ | 结构化澄清 |
| 5 | `precondition_gap` | 错因 label/rootCause 命中 `/前提\|条件\|漏\|忘\|忽略\|误判\|混淆\|方向\|有效\|内阻\|均匀/` | 条件追问 ★ |
| 6 | `knowledge_gap` | $|\text{laws}|=0 \wedge \text{step}=\varnothing$ | 条件追问 |
| 7 | `direction_lost` | $|\text{laws}|>0 \wedge |\text{uncertainties}|>0$，或 $\text{step}=\varnothing \wedge |\text{laws}|>0$ | 方向提示 |
| 8 | `execution_error` | `hasComputationTrace` ∧ 无错因，或错因命中 `/计算\|代数\|单位\|数值/` | 邀请自查 |

### 2.2 代码

```js
// src/core/locate.js:247-304（节选，保留判定顺序）
export function classifyStuckKind(problem, observation, position, utterance = '') {
  const total = totalSteps(problem, position.graphId);
  const onDeadEnd = isDeadEndGraph(problem, position.graphId);

  // 学生明确表示"这条路走不通" ⇒ 无论定位在哪，都该引导换工具
  if (detectDeadEndSignal(utterance, observation)) return 'dead_end_path';

  // 已经走到最后一步且没有任何错因 ⇒ 让他自己收尾，AI 不做任何事。
  // 但死胡同路径上的"末步"不算完成 —— 学生需要的是换一个工具，而不是收尾。
  if (position.stepIndex != null && position.stepIndex >= total &&
      observation.candidateMisconceptionIds.length === 0 &&
      position.confidence >= 0.7 && !onDeadEnd) {
    return 'finished';
  }
  if (position.stepIndex != null && position.stepIndex >= total && onDeadEnd) {
    return 'direction_lost';
  }

  const noThinking = observation.reasoningChain.length === 0 &&
                     observation.laws.length === 0 &&
                     position.stepIndex == null;
  if (noThinking) return 'not_started';

  const misLabels = observation.candidateMisconceptionIds
    .map((id) => problem.misconceptions.find((m) => m.id === id)).filter(Boolean);

  // 有计算痕迹但错因指向概念 ⇒ 不是粗心，是前提没检查
  const preconditionMis = misLabels.filter((m) =>
    /前提|条件|漏|忘|忽略|误判|混淆|方向|有效|内阻|均匀/.test(`${m.label} ${m.rootCause}`));
  if (preconditionMis.length > 0) return 'precondition_gap';
  // ...（后续判定见文件）
}
```

### 2.3 为什么这么写（两个真实错判）

**坑 1：死胡同路径的末步被误判为 `finished`。**
题库里显式标注了某些路径"单独走会卡住"（例如"只走能量守恒"在恒力启动题上形成两未知量的死循环）。
朴素规则会判 `finished`，于是 AI 对学生说"你已经走到最后一步了，收尾交给你自己"——
**而学生正卡在死胡同里求助**。修法是引入 `isDeadEndGraph()`（`locate.js:211-217`）：

```js
export function isDeadEndGraph(problem, graphId) {
  const g = problem.solutionGraphs.find((x) => x.id === graphId);
  if (!g) return false;
  if ((g.steps?.length ?? 0) <= 1) return true;
  const text = `${g.name} ${(g.preconditions ?? []).join(' ')}`;
  return /死循环|无法解|单独使用|单独走|未知量过多|会卡住|死胡同|不是推荐/.test(text);
}
```

**坑 2：学生说"未知量太多解不出来"被归入 `direction_lost`。**
他需要的**不是**"再往下算一步"，而是"**换一个工具**"。
早期版本 L2 会顺着原路继续指（"你考虑恒力做功了吗"），对一个已在死胡同的学生毫无帮助。
因此单列 `dead_end_path` 与 `DEAD_END_SIGNALS`（`locate.js:227-245`）。

### 2.4 "信息不足"的判据必须落在学生发言本身

这是一个容易写错的地方：`sufficientInfo` 的判定基准**不能**用派生字段反推
（`locate.js:398-403`）：

```js
const utteranceHasSubstance = hasSubstantiveContent(utterance);
const hasDerivedContent =
  (observation.reasoningChain ?? []).some((r) => hasSubstantiveContent(r)) ||
  (observation.laws ?? []).length > 0;
const sufficientInfo = utteranceHasSubstance || hasDerivedContent;
```

**踩过的坑**：离线桩会把任何发言按标点粗切成 `reasoningChain`，于是"我不会"也切出一段；
而 `knowns` 是从题干已知量反查出来的，跟学生说了什么无关。两者都会让 `sufficientInfo` 误判为 `true` ⇒ 反问路径永不触发。

**另一个反方向的坑**：真模型对"思路够不够清楚"的标准比人严，多数场景会把 `sufficientInfo` 判成 `false`。
若直接采信，绝大多数场景第一轮都退化成反问 —— **功能上"安全"，产品上等于不干活**。
所以最终判据落在发言本身，模型的 `sufficientInfo` 被显式弃用：

```js
// src/core/locate.js:382-383
const modelSaysSufficient = observation.sufficientInfo;
void modelSaysSufficient;
```

## 3. 层级决策与两条硬护栏

**文件**：`src/core/route.js:61-207` · `decideLevel()` · `route.js:289-293` · `maxReachableLevel()`

### 3.1 核心：可达层级 = 最长连续前缀 + 1

这是**防跳级的数学定义**，也是本文件最值得看的一行逻辑。设历史已给层级序列 $L = [l_1, ..., l_n]$：

$$
\text{reachable}(L) = \max\{k \ge 0 : \{1,2,...,k\} \subseteq L\}
$$

$$
\text{level}_{\text{final}} = \min(\text{level}_{\text{desired}},\ \text{reachable}(L) + 1)
$$

```js
// src/core/route.js:289-293
export function maxReachableLevel(aiLevels) {
  let reachable = 0;
  while (aiLevels.includes(reachable + 1)) reachable += 1;
  return reachable;
}
```

**为什么不能只看前一级**（`route.js:284-291` 的注释，这是真实越级漏洞）：

> 护栏 A 原来只检查"目标层级的前一级是否出现过"。
> 当历史里出现 `[L2]` 这种**缺了 L1** 的序列时，L2 存在 ⇒ 允许升到 L3，
> 而 L1 从未给出 —— **学生直接拿到了最高级别的示范**。

### 3.2 两条护栏的代码

```js

    `从 L${beforeGuard} 回退到 L${next}（禁止跳级）`,

  } else {
    // 已在最高层且仍在同一卡点重复 ⇒ 不再"给提示"，改为要求学生复述自己的下一步
    reasons.push(`护栏B：L3 在同一卡点已给过 ${sameLevelSameStepCount} 次，不再继续给提示，改为要求学生复述自己的下一步`);
  }

```

**护栏 B 会反向破坏护栏 A ⇒ 必须二次校验**（`route.js:196-201`）：

```js
// ---- 最终再校验一次：护栏 B 的升一级不能反过来破坏护栏 A ----
const finalReachable = maxReachableLevel(aiLevels);
if (next > finalReachable + 1) {
  next = Math.max(1, finalReachable + 1);
  reasons.push(`护栏A（二次校验）：回退到 L${next}`);
}
```

### 3.3 迟滞（hysteresis）：抑制升级与抑制重复给提示

```js
// src/core/route.js:148-161
let next;
if (maxGiven == null) {
  next = 1;
  reasons.push('首次给出提示，从 L1 条件追问开始');
} else if (trying && !stillStuck) {
  // 学生在尝试，先不升级，把问题问得更聚焦一点（仍算 L1 变体）
  next = Math.min(maxGiven, Math.max(1, maxGiven));
  reasons.push('学生表示正在尝试，暂不升级，改为更聚焦的条件追问');
} else if (stillStuck || explicitHelpSeeking) {
  next = Math.min(3, maxGiven + 1);
  reasons.push(`学生仍卡住${explicitHelpSeeking ? '（显式求助）' : ''}，从 L${maxGiven} 升到 L${next}`);
} else {
  next = Math.min(3, Math.max(1, maxGiven));
  reasons.push('无明显升级信号，维持当前层级，避免过度帮助');
}
```

配套两组信号词表（`route.js:40-59`）：`STILL_STUCK_SIGNALS`（"还是不会""再给一点"…）触发升级，
`TRYING_SIGNALS`（"我试试""我想想""懂了"…）**抑制**升级 —— 后者是为了不打断正在自己想的学生。

### 3.4 状态抑制（不等于拒答，而是"该沉默时沉默"）

两条提前返回，都在常规递进之前（`route.js:64-115`）：

```js
// ① 学生已收口 ⇒ 不再给提示
if (diagnosis.stuckKind === 'finished') {
  return { level: null, suppressed: true, reason: '学生已推进到路径末段且无错因，不应再给提示' };
}

// ② 自主训练模式 + 未求助 + 无高置信卡点 ⇒ 静默观测
if (mode === 'self_training' && !explicitHelpSeeking) {
  const highConfidenceStuck =
    diagnosis.position.confidence >= 0.75 &&
    diagnosis.misconceptions.some((m) => m.confidence >= 0.8);
  if (!highConfidenceStuck) {
    return { level: null, suppressed: true, reason: '自主训练模式且学生未求助、无高置信卡点 ⇒ 保持静默观测' };
  }
}
```

注意阈值是**两个条件的合取**：定位置信 $\ge 0.75$ **且**存在错因置信 $\ge 0.8$。
只有一个高置信时仍然沉默 —— 避免"猜错还主动打断"。

### 3.6 策略矩阵：卡点 × 层级 → 策略

```js
  not_started:      { 0:'clarify_goal_and_knowns', 1:'clarify_goal_and_knowns', 2:'clarify_goal_and_knowns', 3:'clarify_goal_and_knowns' },
```

**注意 `execution_error` 的 L1 是 `self_check_invitation` 而不是直接示范。**
这里有一个被砍掉的早期设计（`route.js:137-148`）：

> 早期版本给"思路对但算错"开了特例：可直接给 L3 局部示范。用真模型跑评测后改掉，两个理由：
> ① L3 是产品里最强的提示。学生对一道**从未被提示过**的题直接拿到最强提示，违背"先自己想"的产品主张；
> ② 算术类失误本来就该由学生自己发现（"检查一下分母"比"我示范一遍"更有效）。
> **"学生说自己算错了"是一条极容易被利用的捷径** —— 只要声称算错就能拿到示范。

### 3.7 概念白名单的收窄顺序

`buildWhitelist()`（`route.js:309-343`）按**越靠前越贴近学生当前处境**的顺序构造，并且有一条硬约束：

```js
const ownConcepts = new Set(
  problem.solutionGraphs.flatMap((g) => g.steps.flatMap((s) => s.concepts)),
);
const push = (c) => { if (c && ownConcepts.has(c) && !ordered.includes(c)) ordered.push(c); };
```

> **白名单里的每一条都必须来自题目自身的图谱**，绝不允许出现题目没有的概念。
> 否则 draft 会写出跑题提示，而守卫的概念域检查会把它整体拦掉
> （两次都拦 ⇒ 直接掉到兜底模板，体验变差）。

顺序：① 当前步骤 concepts → ② 从命中错因的 `hintSeeds` 文本里**反查**概念（错因的本质往往就是某个概念没到位）→ ③ 下一步 concepts（允许"往前看一步"）。

## 4. 防泄题守卫：7 类确定性检查

**文件**：`src/core/guard.js:437-459` · `guard()` · 主入口

### 4.1 主入口：7 项检查的合取

```js
// src/core/guard.js:437-459
export function guard(text, problem, level, opts = {}) {
  const violations = [
    ...checkAnswerLeak(text, problem),          // 1 答案数值
    ...checkFormulaLeak(text, problem, level),  // 2 解法公式
    ...checkLevelOverflow(text, problem, level),// 3 层级越界
    ...checkSolutionDump(text),                 // 4 整段解法倾倒
    ...checkConclusion(text),                   // 收口句式
    ...checkConceptDomain(text, problem),       // 6 跑题
    ...checkSolutionInsight(text, problem, level), // 7 把结论说破 ★
  ];

  if (violations.length === 0) return { passed: true, violations: [] };

  const repaired = repairHint(text, problem, level, violations, opts);
  return { passed: false, violations, repairedText: repaired.text, repairStrategy: repaired.strategy };
}
```

**守卫不是"检查清单"，是一组关于"什么算说了答案"的判据。**
7 类里前 6 类是设计时预判的，**第 7 类是被真模型打出来的**。

### 4.2 检查 1：数值答案泄漏（双通道）

**通道 a（高精度）**：命中教研/读题链路维护的 `answerFingerprints` 正则。
**通道 b（高召回）**：从 `referenceAnswer` 里抽出所有"数值 + 单位"做兜底 —— 防"教研漏写指纹"这类人为疏漏。

```js
// src/core/guard.js:140-171
export function checkAnswerLeak(text, problem) {
  const violations = [];
  const t = chineseNumeralToArabic(normalize(text));   // ← 中文数字先转阿拉伯

  for (const fp of problem.answerFingerprints ?? []) {
    if (!fingerprintMatches(fp, t)) continue;
    violations.push({ kind: 'answer_in_text', detail: `命中答案指纹 /${fp}/`, match: clip(...) });
  }

  // 通道 b：从参考答案里抽数值-单位对
  for (const pair of extractValueUnits(problem.referenceAnswer)) {
    const { value, unit } = pair;
    // 只对"有单位的数值"做兜底，避免把题干的已知量也当成答案
    if (isGivenValue(problem, value)) continue;
    const re = new RegExp(`${escapeRe(value)}\\s*(?:${unitAlternatives(unit)})`, 'i');
    const m = t.match(re);
    if (m) violations.push({ kind: 'answer_in_text', detail: `参考答案数值泄漏：${value} ${unit}`, ... });
  }
  return violations;
}
```

**`chineseNumeralToArabic` 是必须的**：学生说"电荷量是一库仑"与指纹 `1 C` 必须能对上，
否则守卫会被自然语言绕过（`text.js:150-161`，`chineseNumeralToArabic`）。

**`isGivenValue` 的判定基准必须包含题干全文，而不只是 `problem.givens`**（`guard.js:587-597`）：

> 实测事故（导入题目）：题干里写"落地前 1 s 内下落的高度"，而模型生成的 `givens` 只列了 h、g，
> 没有列这个 1 s。于是守卫把"1 s"当成答案数值，凡是提到它的提示全被拦掉 ——
> 对学生表现为"**AI 一直在打太极，不肯说题目里的 1 秒**"。
>
> 规则本身是自洽的：**题干里已经写出来的数，不可能是答案。**

### 4.3 检查 7：把结论说破（最重要的一类）

这是**三层泄漏里最难的一层**：

| 层次 | 形态 | 由哪条检查负责 |
|---|---|---|
| 第 1 层 | 给出数值答案 | `checkAnswerLeak` |
| 第 2 层 | 给出解法表达式 | `checkFormulaLeak` |
| **第 3 层** | **不说数值、不给公式，但把"这个量扮演什么角色"说破** | **`checkSolutionInsight`** |

```js
// src/core/guard.js:207-225
export function checkSolutionInsight(text, problem, level) {
  if (level >= 3) return [];              // L3 是降级示范，允许说到这个颗粒度
  const insights = problem.solutionInsights ?? [];
  if (insights.length === 0) return [];

  const t = canonicalize(text);
  const violations = [];
  for (const fp of insights) {
    const m = t.match(safeRegex(fp, 'i'));
    if (m) {
      violations.push({
        kind: 'solution_insight',
        detail: `提示直接说出了本题的核心结论（L${level} 不允许）`,
        match: clip(m[0], 40),
      });
    }
  }
  return violations;
}
```

**实测事故（真模型 glm-4-plus）**——L1 层原本的回复：

> "电阻 R 和导体棒自身的电阻 **r** 组成了外电路和**内阻**。"

这句话**没有公式、没有数值**，形式上完全合规，原 6 类检查全部放行。
但学生漏的正是"导体棒有内阻" —— 等于把答案递过去了。

**判据是"指派"而不是"提及"**（`guard.js:197-200`）：

> ✅ 允许：`"谁是提供电动势的那一部分？它自身有没有电阻？"`（在问，没答）
> ❌ 拦截：`"导体棒是电源，r 是内阻"`（在答）

### 4.5 检查 3 的关键取舍：宁可少拦一次，也不要把教学语言拦成一片

公式探测用通用模式（`guard.js:55`）：

```js
const EQUATION_PATTERN = /[A-Za-z_ΔΦΒ][A-Za-z0-9_ΔΦΒ²^·×*/().\s]{0,20}[=＝][^=＝\n]{2,40}/;
```

但**形状检查会误伤正常引用**，所以配了一个"无害等号"判定（`guard.js:644-659`）：

```js
function isBenignEquality(snippet, problem) {
  const s = normalize(snippet);
  const rhs = (s.split(/[=＝]/)[1] ?? '').trim();
  if (!rhs) return true;
  if (/^[?？]/.test(rhs)) return true;              // "位移 x = ?"
  if (/^[\u4e00-\u9fa5]/.test(rhs)) return true;    // 右侧中文开头 ⇒ 不是公式
  // 只看右侧开头那个"数值 + 可选单位"
  const leading = rhs.match(/^(-?\d+(?:\.\d+)?(?:\s*[×x]\s*10\s*\^?-?\d+)?)\s*([A-Za-zΩμ°/²³·]*)/);
  if (!leading) return false;                        // 右侧以字母/符号开头 ⇒ 是公式
  return isGivenValue(problem, leading[1]);
}
```

**两段注释解释了为什么把判定收得这么紧**（`guard.js:619-643`，即 `isBenignEquality` 上方的注释块）：

> 早期版本允许"右侧是已知量数值"就放行，结果 `I = E/(R+r)` 因为含数字而被放过 ——
> 这正是"**守卫有漏洞**"的典型形态：**宽松规则会同时放过善意引用和恶意给公式**。
>
> 这里为什么要容忍"右侧后面还有别的内容"（如 `h = 20 m 和 g = 10 m/s²`）：
> `EQUATION_PATTERN` 的右侧是贪婪的，会一路吃到中文连词。
> 实测事故：L1 提示"题目给了 `h = 20 m` 和 `g = 10 m/s²`，你先看这两个量能求出什么？"
> 被判成 `level_overflow` —— 于是**引用题干本身都成了违规**，模型只能被迫说空话。

**这条检查是次级（secondary）的**：真正的答案拦截靠 `answerFingerprints`（primary）。
所以宁可少拦一次，也不要把正常教学语言拦成一片。

### 4.6 检查 6：跑题 —— 为什么最终选了"封闭词表"

这条规则抓的是**最伤产品可信度的错误**：对着"漏内阻"的电路题聊"动量定理"，
学生会立刻发现 AI 没看懂题。但实现走了两次弯路（`guard.js:287-300`）：

> ① 先试"单字白名单" —— 中文虚词太多，**守卫自己的兜底模板都被判跑题**；
> ② 再试"二元字组白名单" —— 由模板用语构成的白名单永远补不全，
>    因为"先别""你先""看看"这类组合是无穷的；
> ③ 最终方案：**封闭词表**。只维护一张"中学物理常见概念"词表，
>    当提示提到一个**本题领域里不存在**的词表词条时才拦。精确、可审计、零误伤教学用语。

```js
// src/core/guard.js:317-336

  const offending = PHYSICS_CONCEPTS.filter((term) => {
    if (!t.includes(term)) return false;

    return !domainText.includes(term);
  });
  // ...

```

而"本题领域"的定义必须包含 `topics`（`guard.js:343-367`）：

> 为什么补这一条：导入题（intake）的知识点是模型标的，有些术语只出现在 `topics` 里、
> 没有出现在题干或步骤里 —— **不补就会被自己的跑题检查拦掉**，
> 表现为"引擎对导入题频繁使用兜底模板"。

### 4.7 降级重写：按严重度分流的策略

```js
// src/core/guard.js:469-495
export function repairHint(text, problem, level, violations, opts = {}) {
  const kinds = new Set(violations.map((v) => v.kind));

  if (kinds.has('answer_in_text') || kinds.has('final_conclusion') ||
      kinds.has('concept_out_of_domain') || kinds.has('solution_insight')) {
    return { text: safeFallbackHint(problem, level, opts), strategy: 'safe-template' };
  }

  if (kinds.has('formula_leak') || kinds.has('level_overflow')) {
    const stripped = stripEquationFragments(text);
    // 剥离后重新校验，避免剥离不干净
    const recheck = [ ...checkAnswerLeak(stripped, problem), ...checkFormulaLeak(stripped, problem, level),
                      ...checkLevelOverflow(stripped, problem, level), ...checkSolutionDump(stripped),
                      ...checkConclusion(stripped) ];
    if (recheck.length === 0 && stripped.trim().length >= 6) {
      return { text: stripped, strategy: 'strip-equation' };
    }
    return { text: safeFallbackHint(problem, level, opts), strategy: 'safe-template-after-strip' };
  }
  // ...solution_dump → truncate；兜底 safe-template
}
```

策略分流规则（`guard.js:461-468`）：

| 违规类型 | 策略 | 理由 |
|---|---|---|
| `answer_in_text` / `final_conclusion` / `solution_insight` | **整句换安全模板** | 最危险，不冒险改写 |
| `formula_leak` / `level_overflow` | **剥离公式片段，保留问句** | 局部可救 |
| `solution_dump` | **截断到前两句** | 局部可救 |
| `concept_out_of_domain` | **整句换安全模板** | 跑题说明模型没理解题目，"局部删改"救不回来 |

**注意两种策略的本质区别**：`strip-equation` / `truncate` 保留模型自己的说法；
`safe-template` 是整句替换 —— 后者必须触发重试，否则学生会收到"万金油"。

### 4.8 安全兜底模板：永不泄题的最后一道防线

```js
// src/core/guard.js:525-540
export function safeFallbackHint(problem, level, opts = {}) {
  const step = opts.step ?? null;
  const kind = step?.kind ?? 'identify';
  const concept = opts.conceptWhitelist?.[0] ?? step?.concepts?.[0] ?? '这一步';

  switch (level) {
    case 0: return '先别急着算。你能把"题目给了什么"和"要求什么"各说一遍吗？说完我们再定方向。';
    case 1: return '你提到的这个规律，它成立需要的前提条件，题目里的条件满足了吗？先只检查前提，不用往下算。';
    case 2: return `方向提示：这一步的关键是${concept}与题目里另一个量之间的联系。先想清楚这个联系是怎么建立的，再考虑用什么式子。`;
    default: return kindActionFallback(kind, concept, opts.other);
  }
}
```

两个刻意的性质（`guard.js:515-524`）：

> ① **不依赖题目** ⇒ 对任意学科、任意新题目都成立（导入题目同样走这里）。
> ② **按 `step.kind` 分派 L3**：L3 是"示范一个动作"，而"动作"必须匹配这一步在做什么 ——
>    学生在算电流，你让他去列受力，**他一眼就知道你没看懂题**。
>    这条事故在题库时代踩过一次，导入题目时代同样会踩。

L3 的 7 种动作模板全部与学科无关（`kindActionFallback`，`guard.js:546-558`），
因此对导入题目同样安全。例如 `precondition` 类：

> "我示范一个动作：把你打算用的这条关系成立所需要的条件，逐条写成清单（只写条件，不写公式），
> 再拿题干的每个条件对上去，看哪一条没对上。"

### 4.9 指纹匹配：不允许存在"静默失效的指纹"

```js
// src/core/guard.js:124-139
export function fingerprintMatches(fp, text) {
  const t = String(text ?? '');
  const re = () => safeRegex(fp, 'i');
  try { if (re().test(t)) return true; } catch { return false; }
  const unfolded = unfoldScripts(t);
  if (unfolded === t) return false;
  try { return re().test(unfolded); } catch { return false; }
}
```

**背景（`guard.js:113-123`）**：归一化层为了让学生打的 `v^2` 能命中教师写的 cue `v²`，
把 `^2` 折成了 `²`。代价是**写成 `^2` 的指纹会变成死指纹** ——
而指纹是防泄题的主力，**一条悄悄失效的指纹比一条没有的指纹更危险**（因为没人知道它没在工作）。
### 4.10 步骤标题安全：学生可见文本的最后一道判据

```js
// src/core/guard.js:391-417
export function isTitleSafeForStudent(title, problem) {
  const text = String(title ?? '').trim();
  if (!text) return false;
  if (/^[\d\s.、]+$/.test(text)) return false;
  if (checkAnswerLeak(text, problem).length) return false;
  if (checkFormulaLeak(text, problem, 0).length) return false;
  if (checkSolutionInsight(text, problem, 0).length) return false;
  return true;
}

const STEP_KIND_LABEL = {
  setup:'建立模型', identify:'选择规律', precondition:'检查前提', apply:'列关系式',
  derive:'做运算',   interpret:'解释含义', conclude:'收尾结论',
};

export function safeStepRef(problem, step) {
  if (!step) return null;
  const riskyKind = step.kind === 'derive' || step.kind === 'conclude';
  if (!riskyKind && isTitleSafeForStudent(step.title, problem)) return `「${step.title}」`;
  return `第 ${step.index} 步（${STEP_KIND_LABEL[step.kind] ?? '这一步'}）`;
}
```

**这是一条由评测抓到、人没看出来的漏洞**（`guard.js:369-390` 的完整注释）：

> 复述段里有一句"你大概停在「<步骤标题>」这一步"，而**步骤标题可能就是答案**。
> 实测（sc-16 反证法）：那一步的标题是
> **「因此 a、b 有公因数 2，与"互质"矛盾」**
> 引擎把它原样复述给学生 —— **等于把整个证明的结论递过去了**。
>
> 这个洞一直存在，只是离线桩的定位很少落到那一步，所以一直没被看见。
> 它说明一件事：**步骤标题是"教研语言"，不是"学生语言"**，
> 能不能给学生看要逐条判断，不能默认放行。

## 5. 中文短语匹配：三条路径 + 否定判定

**文件**：`src/core/text.js:300-373` · `matchSignatures()`

这是**全引擎最容易出错的地方**（文件头自述）。必须同时解决两个方向的失效，只做一边都会崩。

### 5.1 两个方向的失效（都有实测数据）

| 方向 | 现象 | 实测后果 |
|---|---|---|
| **漏判** | 中文修饰语插进关键词中间：学生说"安培力**应该**向右"，签名"安培力向右"作为连续子串永远匹配不到 | 评测跑出 **0% 错因命中率**，而单测全绿 |
| **误判** | 为召回而"拆词共现"后，短词碎片到处命中：签名"只有R"拆成 `["只有","R"]` 会在"R的功率"里命中 | 假阳性 |

**为什么单测全绿却评测 0%**：单测用例是从签名原文抄的，**天然匹配**。
这是"测试数据太干净导致的假通过"——本阶段最重要的一条方法论教训。

### 5.2 解法：分路径策略，而不是一套规则打天下

```js

    if (isWordBoundaryMatch(flat, idx, key.length)) {
```

### 5.3 词边界校验：拦"子表达式误伤正确表达式"

```js
// src/core/text.js:248-253
function isWordBoundaryMatch(text, index, length) {
  const before = index > 0 ? text[index - 1] : '';
  const after = index + length < text.length ? text[index + length] : '';
  const tight = /[A-Za-z0-9+\-*/^=（）()]/;
  return !tight.test(before) && !tight.test(after);
}
```

目的：拦掉 `I=E/R` 在 `I=E/(R+r)` 里误命中。
中文相邻不算违规（中文没有分词空格，"电阻只有R"里 R 前面就是中文）。

### 5.4 否定判定：反向设计 + 一个必须跳过的例外

**检查窗口必须包含命中的词本身**（`text.js:277-288`）：


> 本检查只用于"极性为肯定"的签名。

> 输入框的自动替换只帮到"从界面上打字"的学生。而学生的话还有别的来源 ——

> **这条 cue 对这个学生就等于不存在**，他会被判成"没有说到点子上"，**而他其实说得完全正确**。

### 5.6 去重口径必须是"归一化之后"（评测抓到的静默 bug）

```js
// src/core/text.js:114-125
```

## 6. 答案判定：按待求量覆盖，而不是数数值个数

**文件**：`src/core/verify.js:68-232` · `expectedAnswers()` / `verifyAnswer()`

### 6.1 问题：为什么不能"把参考答案里所有数值都当答案"

**实测踩到的假阳性**（`verify.js:42-51` 的注释）。自由落体题的参考答案是：

> "由 `h=½gt²` 得总时间 `t = 2 s`，故 `v = gt = 20 m/s`；落地前 1 s 内下落高度 `Δh = 15 m`。"

朴素抽取会把 `2 s`（总时间）也当答案 ——
于是学生只要提到"总时间 2 秒"就会被判定成"答对了"，**弹出庆祝界面**。

> **假庆祝比不庆祝更伤**：学生立刻知道这个系统在瞎说。

### 6.2 解法：先把参考答案切成分句，再把每个分句挂到它提到的待求量上

```
"故 v = gt = 20 m/s"          → 提到 v → 属于待求量「落地速度 v」  ⇒ 20 m/s 是答案
"由 h=½gt² 得总时间 t = 2 s"  → 没提到任何待求量                  ⇒ 2 s 是中间量，丢弃
```

```js
// src/core/verify.js:81 —— 分句要连中文逗号一起切
const clauses = reference.split(/[；;。\n，,]/).map((s) => s.trim()).filter(Boolean);
```

> 实测踩到：参考答案常写成"由 `h=½gt²` 得总时间 `t = 2 s`，故 `v = gt = 20 m/s`"。
> **只按 `；` 切的话**，`t = 2 s`（中间量）和 `v = 20 m/s`（真答案）落在同一个分句里，
> 而这个分句的等号左边是 `h`，谁都匹配不上 ——
> **结果真答案 20 m/s 被整句丢掉，学生答对了也等不到确认。**

### 6.3 只在等号左边找符号

```js
// src/core/verify.js:144-166
function clauseMentions(clause, matcher) {
  const eq = clause.search(/[=＝]/);
  const lhs = eq > 0 ? clause.slice(0, eq) : clause;
  if (matcher.sym) {
    const re = new RegExp(`(?<![A-Za-z])${escapeRe(matcher.sym)}(?![A-Za-z0-9])`);
    if (re.test(lhs)) return true;
  }
  return matcher.grams.some((g) => lhs.includes(g));
}
```

> 实测：参考答案里 `I = E/(R+r) = 1 A` 这个分句，若在**整个分句**里找符号 `E`，
> 会因为右边的 `E/(R+r)` 命中，于是把 `1 A` 也算成"感应电动势 E 的答案" —— **一个值挂到了两问上**。
> 取等号左边之后，这个分句只属于 `I`。

### 6.4 宽松方向刻意的"双向不对称"

这是本附件里**最反直觉的一处设计**，值得单独讲：

| 模块 | 判定 | 宽松方向 | 理由 |
|---|---|---|---|
| `guard.checkAnswerLeak` | 该数值是否"题干已给"（是则不算泄漏） | **宁可宽松**：只比数值 | 引用题干不该被拦 |
| `verify.expectedAnswers` | 该数值是否"题干已给"（是则不算答案） | **宁可严格**：必须同值**同单位** | 错误地宣布"做对了"比漏判更伤 |


> 实测踩到：`phy-emi-01` 的已知量里有 `B = 0.4 T`，
> 而它的两个答案是 `E = 0.4 V` 与 `P = 0.4 W` —— **数值都是 0.4**。
> 如果按数值排除，这两个真正的答案会被当成"题干已给"而被丢掉，

### 6.5 完成判定：按待求量覆盖


### 6.6 三条设计红线

**红线 ①：只确认对的，绝不指出错的。**

```js
// src/core/verify.js:21-25
// 说对了 ⇒ 确认；说错了 ⇒ 什么也不说，走原来的引导路径。
// 这个不对称是刻意的：这个产品不做判卷，只做"陪你想"。
```

**红线 ②：确认文本里不许出现学生没说过的数值。**

```js
// src/core/verify.js:276-291
export function findUnstatedAnswers(text, problem, verdict) {
  const t = canonicalize(text);
  const hits = [];
  for (const r of verdict?.remaining ?? []) {
    const withUnit = new RegExp(`${escapeRe(r.value)}\\s*(?:${unitAlternatives(r.unit)})`, 'i');
    if (withUnit.test(t)) { hits.push(`${r.raw}（带了单位）`); continue; }
    const n = Number(r.value);
    if ((Math.abs(n) >= 10 || r.value.includes('.')) && new RegExp(`(?<![\\d.])${escapeRe(r.value)}(?![\\d])`).test(t)) {
      hits.push(`${r.value}（裸数值）`);
    }
  }
  return hits;
}
```

> **这是比守卫更强的约束。** 守卫拦的是"AI 主动给答案"（任何人都不许说）；
> 而确认场景下学生会疑惑"它是不是把答案告诉我了"——
> 所以判据是"引擎能不能引入一个学生原话里没有的数"，答案必须是**不能**。

关于"裸数字"的取舍：小于 10 的整数不单独查 ——
否则"**还剩 2 个待求量**"这种句子会被误判成泄漏。

**红线 ③：不假装算得准。**

> 漏判的后果是"继续引导"（可接受），误判的后果是"错误地宣布做对了"（不可接受）。
> **所以宁可漏判。**

### 6.7 一个被评测指标挡回去的重构

第一版实现把确认路径放在**最前面直接 `return`**，跳过了 observe 与定位。
后果被评测指标当场抓到：**定位命中率与错因命中率同时下降** ——
因为"学生报出答案"的那一轮不再产生任何诊断信息。

而那恰好是最不该丢信息的一轮（`engine.js:213-228`）：

> 学生说"E = 0.4 V"时，
> · `E` 这个结果**确实是对的**（`E = BLv` 与内阻无关）⇒ 该确认
> · 但他可能**同时漏了内阻**（下一步算电流才会踩到）⇒ 该记下来
> **两件事并不冲突。所以：确认只替代"提示"，不替代"观察"。**

代价是确认轮也会多调一次 `observe`（一次 LLM 调用），换来教师视图里"学生答对那一轮他在第几步、有没有错因"仍然看得到。

```js
function ensureCues(cues, title, concepts) {
  const clean = cues.map((c) => normalize(c).replace(/[，,。.\s]/g, '')).filter((c) => c.length >= 2 && c.length <= 10);
  if (clean.length >= 2) return [...new Set(clean)].slice(0, 6);

  // 从标题与概念里派生：按标点切成短语，取 2~8 字的片段
  const derived = [];
  for (const chunk of `${title} ${concepts.join(' ')}`.split(/[\s、,，/（）()：:；;]+/)) {
    const t = normalize(chunk).replace(/[，,。.\s]/g, '');
    if (t.length >= 2 && t.length <= 8) derived.push(t);
  }
  return [...new Set([...clean, ...derived])].slice(0, 6);
}
```

> `cues` 是关键词定位通道**唯一**的输入。一条路径如果没有 cues，定位就 100% 依赖模型通道，
> 而双通道交叉校验会**退化成单通道** —— 模型一旦误判就没有第二意见，
> 这正是"**错误的提示比不给提示伤害更大**"的场景。

## 8. 编排层：`handleTurn` 的 5 段链路与重试闭环

### 8.1 生成 → 守卫的重试闭环（一个"几乎从不执行"的静默 bug）

```js
// src/core/engine.js:387-408
const keepModelVoice = recheck?.passed && ['strip-equation', 'truncate'].includes(g.repairStrategy);
if (keepModelVoice) {
  finalText = rewritten;
  finalGuard = recheck;
  trace.push({ stage: 'guard', message: `采用守卫重写结果（策略 ${g.repairStrategy}，保留了模型的原始说法）` });
  break;
}
// 最后一次机会仍只拿到模板句 ⇒ 用它（仍比无信息的兜底模板更贴近本题）
if (recheck?.passed && attempt === 1) { ... break; }
// 否则带着违规信息重试下一代
finalGuard = g;
```

**为什么要分两类处理**（`engine.js:372-386` 的注释，这是本阶段最典型的一个"不报错但静默变差"的 bug）：

> `strip-equation` / `truncate`：守卫只删掉了越界的那一小段，模型自己的说法还在，
> 直接采用（比再调一次模型更快、也更贴学生）。
>
> `safe-template`：守卫把整句换成了通用模板。**这时候立刻采用是错的** ——
> 学生会收到一句"万金油"，而且他**无从知道你其实读懂了这道题**。
> 正确动作是把拦截原因带回给模型，让它换个说法再试一次。
>
> 早期实现图省事，在第一次被拦时就直接采用了模板，
> 于是"**重试**"这条路径**几乎从不发生**，提示质量被静默拉低。

违规信息如何回流到下一轮（`engine.js:670-678`）：

```js
function accumulateForbidden(base, guardHistory) {
  const out = [...base];
  for (const g of guardHistory) {
    for (const v of g.violations ?? []) {
      out.push(`上一轮被拦截【${v.kind}】：${v.detail}${v.match ? `（命中片段：${v.match}）` : ''}`);
    }
  }
  return out;
}
```

### 8.2 出口断言：让"守卫失效"变成响亮崩溃

```js
// src/core/engine.js:438-445

```

确认路径同理（`engine.js:508-515`）：

```js
const leaked = findUnstatedAnswers(text, problem, verdict);
```

> **安全机制的失败模式必须是响的，不能是哑的。**

### 8.3 拒绝路径：确定性话术递进，不调用模型

```js
// src/core/engine.js:99-103
const REFUSAL_LADDER = [
  '答案我先不给。不过我可以保证：只要你自己走通一步，后面的会越来越快。我们先从最小的那一步开始——你说说这道题给了哪些条件？',
  '我还是不给答案。但如果你愿意把现在想到的写给我（哪怕只写对一个公式名），我能告诉你"卡在哪、该检查什么"。这比我报个数字对你考试有用得多。',
  '我理解你想要结果，但直接给你答案，下次换一道题你还是会卡。这样吧，我把这一步拆成两个更小的问题，你只要回答其中一个就行……',
];
```

两个设计要点：

**① 拒绝不是终点，是转向**（`engine.js:94-98`）：拒绝之后必须给一个"低成本的下一步"，否则学生会认为"这个 AI 没用"而离开。

**② 索要答案 + 同时带着思路 ⇒ 不算纯索取**（`engine.js:111-128`）：

```js
// 残余内容判定：把"索要答案"的关键词全删掉后，还剩多少实质内容？
// 这条规则的来由：学生常说"我用欧姆定律算出了电流，但力不知道怎么求，答案是什么"，
// 这明显带着自己的思路，把他当"纯索取者"拒绝掉是误伤 —— 会让学生觉得 AI 不听人说话。
let residual = t;
for (const k of ASK_FOR_ANSWER) residual = residual.split(k).join('');
```

**③ 拒绝路径也必须过 guard**（`engine.js:175-176`）：


## 10. 三个"必须现场说清楚"的诚实边界

汇报时如果被追问到实现深度，以下三件事必须主动讲，否则一旦被对方自己挖出来，前面所有数据的可信度一起归零。

**① 离线规则桩不能读懂任意题。**
`heuristicSkeleton()` 只是"把流程撑起来"的通用六步骨架，`cues` 是通用词，定位精度远低于真模型。
它存在的价值是**验证护栏与流程**，不是验证理解能力（`docs/01` §七）。

**② 19 个场景上的 100% 不是能力证明。**
它证明的是"框架成立、不给答案守得住、跨学科可复用"；
**没有**证明"提示的教学质量高"与"能应对真实学生的多样化表达"。
教学质量必须教研盲评，自动化测不出"这句话有没有启发"。

**③ 读题链路把"每题教研手写图谱"变成了"每题教研抽查图谱"。**
工程成本下降了，**验收责任没有消失，只是换了位置**。
