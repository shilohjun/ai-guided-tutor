## 第一部分 · 技术进展（可验证的部分）

### 1.1 一句话

把学习产品的入口从「学生提问 → AI 回答」反过来，做成「**学生先交思路 → AI 看懂他卡在哪 → 只给提示不给答案**」。
方向一变，立刻产生一个真正的技术难题：**怎么保证 AI 在"帮"的同时绝不把答案说出去**。
本阶段的全部工程投入都压在解决这一个问题上。

### 1.2 核心主张：模型负责"懂"，代码负责"分寸"

这是整个系统唯一值得汇报的架构决策，其余都是它的推论。

| 判断 | 由谁做 | 为什么不能交给模型 |
|---|---|---|
| 学生说了什么、落在哪一步 | 模型（观察员） | —— 这是模型真正擅长的事 |
| 该给几级提示 | 规则引擎（决策者） | 交给模型 ⇒ 学生一喊难就拿到最强提示，等于变相给答案 |
| 什么算"说了答案" | 出口守卫（把关者） | 交给模型 ⇒ 换个说法、给近似值、给公式就能绕过 |
| 学生卡在哪一步 | 双通道交叉校验（模型只提供一路） | 只信模型 ⇒ 误判被采信，实测定位命中率掉到 72.7% |

**由此得到一条可验证的推论，也是本阶段最重要的实验结论：**

> 安全指标与模型能力无关。
> 离线规则桩、智谱 glm-4-plus、DeepSeek deepseek-chat 三种后端跑同一套评测，
> **安全指标完全一致（全部为 0）**；变化的只有话术质量（可行动率 100% → 94.9% → 100%）。
> 更进一步：把模型换成一个"每轮都故意泄题"的假模型，
> 交付给学生的文本**泄题率仍为 0%**。

这条推论的价值在于：**换模型的风险被限制在"理解准确率"，而不是"会不会泄题"。**
对企业而言，这意味着可以放心地换用自家模型，不必为安全指标重新背书。

### 1.3 三个技术支点（每一条都有代码位置与测试）

| # | 支点 | 具体做法 | 可验证证据 |
|---|---|---|---|
| **A** | **卡点分类体系** | 把"学生卡住了"拆成 **7 种互不相同的处境**（还没想 / 不知道用哪个规律 / 漏了前提 / 方向丢失 / 算错 / 走进死路 / 已收口），每种对应不同的应对方式，而不是笼统"给个提示" | `types.ts` 的 `StuckKind`；`route.js` 按卡点分派；`test/route.test.js` |
| **B** | **分层提示机制** | L0 结构化澄清 → L1 条件追问 → L2 方向提示 → L3 降级示范。两条硬护栏：**禁止跳级**（可达层级 = 从 L1 起的最长连续前缀 + 1）、**禁止原地打转**（同卡点同层给过 2 次即升级；已在 L3 则不再给提示，改为要求学生复述下一步） | `route.js` 护栏 A/B；`test/route.test.js`、`test/engine.test.js` |
| **C** | **防泄题守卫** | 提示文本在**出口**必须通过 **7 类确定性检查**：答案数值 / 解法公式 / 层级越界 / 整段解法倾倒 / 收口句式 / 跑题 / 把结论说破。违规 ⇒ 按严重度**降级重写**；最危险的四类直接换安全兜底模板；引擎返回前断言 `guard.passed === true`，否则**抛错** | `guard.js` 恰好 7 个检查；`test/guard.test.js` 32 例 |

**关于 C 的一个设计取舍值得单独说**：
"守卫失效"被刻意设计成**立刻可见的崩溃**，而不是静默地把答案发给学生。
安全机制的失败模式必须是响的，不能是哑的。

### 1.4 防泄题的真实对手：7 种绕过方式

这一页不是设计稿，是**被真实模型打出来的**。模型至少有 7 条路可以绕过 prompt 约束：

| # | 绕过方式 | 对应检查 | 发现方式 |
|---|---|---|---|
| 1 | 直接给数值 | `answer_in_text` | 设计时预判 |
| 2 | 给近似值（"大约是 0.4"），含中文数字说法 | `answer_in_text` | 设计时预判 |
| 3 | 给公式让学生自己算 | `formula_leak` | 设计时预判 |
| 4 | 列完整步骤让学生抄 | `solution_dump` | 设计时预判 |
| 5 | 用收口句式下结论 | `final_conclusion` | 设计时预判 |
| 6 | 聊与本题无关的内容 | `concept_out_of_domain` | 设计时预判 |
| 7 | **不写公式、不给数值、格式完全合规，但把学生漏掉的知识点直接说破** | `solution_insight` | **只有跑真模型才会暴露** |

第 7 条的实际案例（模型原本想说的话，被拦下）：

> "导体棒产生的电动势相当于电源，而电阻 R 和导体棒自身的电阻 **r** 组成了外电路和**内阻**。"

学生漏掉的就是"r 是内阻"这件事。这句话没有公式、没有数值 —— 原 6 类检查全部放行。

**这条的技术含义**：泄漏的判据不能停在"答案的格式"，必须延伸到"解题思路本身"。
我们因此把守卫从"字符串匹配"升级为"**指纹 + 语义结论**"双判据，
指纹由读题链路在导入题目时自动生成（数值指纹 / 公式指纹 / 结论指纹三组）。

**另一条同样致命的静默漏洞（由评测抓到，不是人发现的）：**
一道数学证明题的**步骤标题本身就是证明结论**（"…与互质矛盾"），
而引擎把标题原样复述给了学生 ⇒ 泄题率 2.6%。
修法：标题必须通过与答案同一套指纹检查；`derive` / `conclude` 两类标题一律不引用，
不安全的退到「第 N 步（动作类型）」。

> **认识论上的一句话：步骤标题是教研语言，不是学生语言。能不能给学生看要逐条判断，不能默认放行。**

### 1.5 已验证 / 未验证（这一页请务必保留）

技术型企业最容易被"全绿"的数据激怒，所以边界先写出来。

**已验证：**

| 指标 | 结果 |
|---|---|
| 泄题率 / 跳级率 / 确认答案 / 解法倾倒 / 崩溃 | 真模型两轮均为 **0** |
| 定位命中率 / 错因命中率 / 静默正确率 | **100%**（19 个教研标注场景、39 轮） |
| 跨学科复用 | 数学证明题（反证法证 √2 无理）**引擎代码零改动**即可处理 |
| 任意题目读题 | 粘贴任意题干 → 知识点 / 已知量 / 待求量 / 多解路径图谱 / 错因库 / 三组防泄题指纹 |
| 视图隔离 | 学生接口**根本不返回**路径、参考答案、错因标签、完整 trace（不是前端隐藏） |

**未验证（必须说）：**

| 未验证项 | 准确说法 |
|---|---|
| 提示的**教学质量** | 现有指标测的全是"安全"（有没有泄题、有没有越级），**没有一个指标测"有用"**。需要教研盲评 |
| 真实学生适应性 | 19 个场景是**人写的**，只能证明框架成立，不能证明能应对真实学生的多样化表达 |
| 长会话 | 场景集最长 3 轮，10 轮以上会不会重复 / 失忆 / 层级混乱，未知 |

| 生产可用性 | 无持久化（会话存内存）、无鉴权、无限流；实测一次评测耗时在 88 秒 ~ 1925 秒之间波动，受 API 限流影响严重 |

> **准确表述**：框架已建成并在真模型上验证通过；教学质量与真实语料适应性待验证。
> **不要表述为**"这个能力已经做成了"。

### 1.6 本阶段的方法论收获（三条，都是踩出来的）

1. **测试数据太干净会造成假通过。** 最初的单元测试用例是从规则表原文抄的，天然匹配 ⇒ 44/44 全绿，
   而真实评测的错因命中率是 **0%**。从那以后所有测试用例必须来自真实语料。
2. **人发现的漏洞和机器发现的漏洞不可互相替代。** 本阶段 3 个界面/交互问题都是人试用时发现的；
   而两个最严重的漏洞（步骤标题泄漏、证据重复计分）**都是评测机器抓到的**，人看十遍也看不出来。
3. **"不报错"是最危险的一类 bug。** 9 条修复里有 6 条属于"不报错，只是悄悄变差"
   （步骤标题泄漏、指纹静默失效、证据重复计分、读题静默降级、滚动提示永不出现、隐藏时量不出高度）。
   共同点是没有任何异常 ⇒ 现在它们**全部有断言**。

## 第二部分 · 需要企业支持的能力与资源

> 排序按**阻塞程度**，不按重要性。**P0 = 不给就无法在真实场景中验证**。
> 标 ⭐ 的四项是本次汇报最希望当场确认的。

### P0（阻塞级）：没有这些，系统只能是"能演示"，不能是"可信" ⭐

#### 需求 1 ⭐ **学生真实作答过程语料**（含卡点标注）

| 项 | 内容 |
|---|---|
| **要什么** | 真实学生解重难题的过程记录，按**过程**标注而非只标对错 |
| **具体字段** | ① 学生的原始表述（文字 / 语音转写）② 每一步在想什么、卡在哪 ③ 他实际写下的步骤序列 ④ 教研标注的"正确下一步该是什么" ⑤ 最终得分 |
| **形态** | 半结构化即可，**原始文本比整理过的报告更有价值** —— 整理会抹掉学生"绕"的痕迹，而我们要学的正是"怎么绕的" |
| **规模** | 先 **50–200 条**（当前只有 19 个场景，且是人工编写的） |
| **分层** | 建议按 学科 × 年级 × 题型 × 卡点类型 分层，至少要能覆盖我们 7 类卡点里的 5 类 |
| **用途** | ① 把评测场景从 19 扩到 50+ ② 微调定位模型 ③ 让教研盲评有真实素材 |
| **为什么阻塞** | 现在的 100% 建立在人写的 19 个场景上。**没有真实语料，"有效"这句话就无法说出口** |
| **风险坦白** | 真实语料进来后，现有指标**大概率会下降**。这是我们主动要的 —— 但希望企业理解这是"暴露问题"而不是"系统退步"，否则没人敢要真数据 |

#### 需求 2 **题库与知识图谱的结构化对接**

| 项 | 内容 |
|---|---|
| **要什么** | 企业题库的**结构化访问方式**（API / 导出文件 / 只读库），以及知识点标签体系的文档 |
| **至少要拿到** | ① 题干（含公式、图形的原始表达）② 参考答案 ③ **解题步骤序列** ④ 每题的知识点 / 考点标签 ⑤ 难度与题型分类 ⑥ 常见错解（有则最优） |
| **其中最关键的一项** | **解题步骤序列** —— 这是我们"路径图谱"的骨架。我们现在的图谱是模型现场读题生成的，质量取决于模型；企业题库如果已经带步骤拆解，图谱质量会**直接跨一级** |
| **接口约定** | 题目 ID 稳定、支持增量同步、题面变更可感知 |
| **对齐成本** | 我们的 `Problem.topics` 字段是给图谱映射留的接口。企业只需给出标签体系文档，我们对齐即可 |
| **对等回报** | 我们产出的题图谱（知识点 / 已知量 / 待求量 / 路径 / 错因库 / **三组防泄题指纹**）会回流成企业题库的一层增强标注，且**可审计、可版本控制** |

#### 需求 3 ⭐ **视觉模型：题目识别 + 手写识别（两条独立链路）**

这一项在 proposal 里被写成一件事，实际是两件，技术难度和验收标准完全不同，请分开评估。

**3a. 题目识别（拍题 → 题干）· 成本低，可 0.5 天接通**

| 项 | 内容 |
|---|---|
| **要什么** | 支持图文混合的 VL 模型接口（题干含公式、几何图、电路图、受力图） |
| **具体能力** | ① 印刷体 OCR ② **公式识别为 LaTeX 或等价结构化表达**（关键：不能只给"v 平方等于 2aL"这样的自然语言） ③ 简单图形的结构化描述或图注 |
| **为什么现在能接** | 我们的**读题链路已经打通**，只差"图像 → 题干文本"这一跳。VL 一接，链路就是端到端 |
| **验收** | 一次成功率 / 公式识别正确率 / 图形信息丢失率，在企业的真实拍题样本上测 |
| **当前状态** | 界面上「拍照上传」入口**已显式标出未接**，我们**没有伪造解析结果** |

**3b. 手写笔迹识别（草稿 → 步骤序列）· 这是真正难的一条**

| 项 | 内容 |
|---|---|
| **要什么** | 学生手写过程的**步骤级**识别能力，而不是整页 OCR |
| **两者差别（请企业重点评估）** | 「整页 OCR」= 一张静态图 → 一段文字；<br>「步骤级」= 时间序列 → **有序的步骤流**（第几步写了什么、在哪一步涂改、在哪一步停顿） |
| **我们真正需要的是后者** | 因为引擎要比对的是"**步骤序列 vs 路径图谱**"。整页 OCR 丢掉顺序和涂改痕迹，而**涂改和停顿恰恰是卡点最强的信号** |
| **企业已有能力** | proposal §三.2 记录：企业寻访时展示过"用摄像头识别学生动作、还原具体步骤"的能力。**这一条请现场确认可对接的程度** |
| **点的形态** | 需要的是**结构化步骤流**（含时间戳、增删改事件），不只是识别文本 |

#### 需求 4 ⭐ **实时识别采数硬件：点阵笔 / 摄像头，两者需要实测对比**

| 项 | 内容 |
|---|---|
| **要什么** | 借调少量设备做**真实学生试用**（不必采购，先验证） |
| **为什么这是 P0** | 实时观测（proposal 环节③）**完全没做**，卡在硬件。而它是整个"看过程不看答案"主张的**物理前提** |
| **两个方案我们已列出，但没有实测数据** | **摄像头**：非侵入、不改学生习惯；风险是肢体遮挡导致部分笔迹漏采，以及草稿图像识别准确性未验证<br>**点阵笔**：笔迹还原度高、采集稳；风险是**书写手感与正常用笔差异大，可能改变学生的做题状态** —— 而"不干扰学生"是这个产品的底线 |
| **需要的不是结论，是实测** | 请企业提供各 **5–10 套**，我们在真实学生身上测三件事：① 步骤还原完整度 ② 遮挡/断点比例 ③ **学生是否抱怨手感**（第 3 条最容易被忽略，却最可能让方案作废） |
| **验收指标** | 步骤还原完整度 ≥ 90%、误采断点可容忍、学生主观接受度可接受 |

### P1（重要但可并行）：让我们能"安全地换模型、可量化地调优"

#### 需求 5 **模型接入与配额（工程约束，比模型能力更影响进度）**

接入本身很轻：`.env` 填三个变量即可（`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`）；
OpenAI 兼容协议**无需改代码**；私有协议只需实现 `LLMAdapter` 的两个方法
（`observeStudent` / `draftHint`），其余全部复用。以下才是真正需要企业明确的部分：

| # | 要什么 | 为什么 |
|---|---|---|
| 1 | **JSON 输出稳定性**保证（`response_format` / 结构化输出） | 我们靠结构化输出解耦"观察"与"决策"。JSON 不稳 ⇒ 走容错兜底 ⇒ 判断质量下降 |
| 2 | **长输出截断的显式错误码**，而不是静默截断 | 我们踩过：一道六问的长题因 `max_tokens` 用尽被截断，**整题退回通用骨架** —— 知识点、错因、参考答案、**全部防泄题指纹一起丢**。也就是说：**题目越长，守卫失效概率越高**。这是安全问题，不是体验问题 |
| 3 | **字符级流式输出**确认 | 无流式 ⇒ 学生等整段生成，交互延迟不可接受 |
| 4 | **并发配额与限流策略**（QPS 上限、是否内网专线） | 实测一次评测耗时在 **88 秒 ~ 1925 秒**之间波动，就是被公网限流打的 |
| 5 | **单次调用成本口径** | 目前单次引导约 输入 2000–3000 token / 输出约 500 token，成本在分毫级。需要企业侧确认内网口径 |
| 6 | **内网可部署性**的证据 | 学生数据不出内网是我们的强烈偏好；企业模型是否支持内网部署，直接影响合规方案 |

#### 需求 6 ⭐ **接入后做一次基线对标（这一项最能保护双方）**

| 项 | 内容 |
|---|---|
| **要什么** | 企业模型接入后，用**同一套评测集**跑一次基线 |
| **跑什么** | 安全五项（泄题 / 跳级 / 确认答案 / 解法倾倒 / 崩溃）+ 能力四项（定位 / 错因 / 可行动 / 静默）+ 长题图谱完整率 |
| **对标对象** | 已在平台上跑通的 glm-4-plus 与 DeepSeek deepseek-chat 数据（`share/评测报告_真模型.txt`） |
| **为什么重要** | 有了这条基线，之后任何指标变化都能区分"**是提示系统变了**"还是"**是模型换成你们家的了**"。没有它，双方会在归因上反复扯皮 |
| **交付物** | 一份《企业模型接入基线报告》，含逐场景明细与失败样例 |

#### 需求 7 **错因库 / 常见错误标注**

我们已有 **7 类卡点分类体系**（`not_started` / `knowledge_gap` / `precondition_gap` /
`direction_lost` / `execution_error` / `dead_end_path` / `finished`）。
企业题库若已带错因标签，需要的是：**标签体系文档 + 与我们的 7 类做一次映射评审**。

映射表建好后立刻能产生价值：错因命中率是现有指标中权重很高的一项，
而它目前依赖模型现场判断；有企业标注做交叉校验，这一项才算真正可信。

### P2（长期）：采数、评测与合规

#### 需求 8 **长会话与真实交互语料**

| 项 | 内容 |
|---|---|
| **要什么** | ① 真实学生**语音**录入（口语表达思路的原始录音 + 转写）② **多轮**对话记录（≥10 轮）③ 学生真实提问的分布（他到底会问什么） |
| **为什么** | 语音是最自然的入口，但也是最脏的输入（口语、省略、指代"那个""这个"）。我们已用 Web Speech API 补上了输入通道，但**没有真实语音语料可调** |
| **规模** | 语音 20–50 小时，多轮记录 100 段以上 |
| **用途** | 口语鲁棒性调优 + 长会话疲劳测试（10 轮以上会不会重复、失忆、层级混乱）—— 这一项目前**完全没测过** |

#### 需求 9 **教研协作机制（不是要人，是要一个固定节奏）**

| 项 | 内容 |
|---|---|
| **要什么** | ① 教研**盲评 20 轮真实对话**，约半天投入 ② 教研**抽查 20 份导入题目生成的图谱** |
| **为什么** | 这是我们唯一无法用自动化替代的验证。现在所有指标测的都是"安全"，**"有用"必须人判断** |
| **盲评只问三个问题** | ① 这个提示是否**准确指向**了学生的卡点？② 学生看完之后**是否还需要自己动脑**才能往前走？③ 换成人类老师，会说得更多还是更少？ |
| **第 2 个问题是关键** | 它是"只给提示"和"变相给答案"的分界线 |
| **关于图谱抽查** | 读题链路把"每题必须教研手写图谱"变成了"每题必须教研抽查图谱"。**工程成本下降了，验收责任没有消失，只是换了位置** |

#### 需求 10 **合规与数据授权链路（决定第 1、8 条能不能真正落地）**

| 项 | 内容 |
|---|---|
| **要什么** | ① 学生作答数据与笔迹图像现有的**脱敏流程**说明 ② 语料的**权利链与授权范围**（是否已获监护人同意用于模型训练）③ 可使用边界：能否用于微调 / 能否用于评测集 / 能否留存 |
| **为什么必须前置** | 面向未成年人，且同时涉及 **≥2 家模型供应商**（企业模型 + 我们验证用的第三方模型）。**三方之间的数据流向必须在接入前划清**，否则语料进来了也不敢用 |
| **我们的姿态** | 强烈偏好**数据不出内网**：训练与评测尽可能在企业内网环境完成，我们只带走**指标与脱敏样例** |
| **一个务实的提醒** | 语料授权需要区分"**可训练**"与"**可评测**"两种用途。评测集的数据一旦用于训练就不再是评测集 —— 我们需要一部分**永久冻结**的评测数据 |

#### 需求 11 **实时识别的标注数据**

| 项 | 内容 |
|---|---|
| **要什么** | 学生真实作答**图像 / 笔迹序列**及对应标注，按 学期 × 题型 × 书写工具 分层 |
| **用途** | 衡量"实时观测"的真实准确率，而不是只看 demo 效果 |
| **依赖** | 与需求 4 的设备实测同步进行 —— 边采数边定标注规范，比先定规范再采数更快 |

## 第四部分 · 需要企业当场回答的问题

### 4.1 请务必当场确认的四项（对应 ⭐）

1. **真实学生语料**：能不能提供 50–200 条带过程标注的解题记录？走什么流程（脱敏 / 授权 / 交付形式）？**大概什么时候能给？**
   —— 这一项决定"有效"这句话能不能说出口。
2. **视觉模型**：题目识别（含公式 → LaTeX）与**手写步骤级识别**，企业分别提供到哪一层？
   特别想确认：**"把草稿转成有序步骤流（含涂改、停顿）"这个能力是否存在**，还是只有整页 OCR？
3. **采数硬件**：点阵笔、摄像头各能借调多少套用于真实学生实测？有没有已经跑过的实测数据可以直接给我们看？
4. **模型接入 + 基线对标**：内网模型的接口形态、JSON 稳定性、并发配额；以及**是否同意接入后做一次正式基线对标**。

### 4.2 另外三个希望明确的问题

5. **合规边界**：学生数据能否用于微调？能否用于评测集？是否需要一部分数据**永久冻结**作为评测集？
6. **教研节奏**：教研同学能否给出固定投入（例如每周半天盲评）？还是只能一次性支持？
7. **部署形态**：产品要内嵌进企业现有「AI 全学科学习空间」，那里用什么模型、什么前端框架？
   —— 这决定我们是"提供独立服务"还是"改造成组件"，**越早明确越省工**。

### 4.3 我们必须主动声明的一件事

> 真实语料接入后，现有指标（定位 100% / 错因 100%）**大概率会下降**。
> 这是我们主动要的结果 —— 19 个人写场景上的 100% 本来就不该被当作能力证明。
> 但需要企业理解：**这是暴露问题，不是系统退步**。
> 如果双方对"指标会掉"没有事先共识，后面就没人敢要真数据了。
