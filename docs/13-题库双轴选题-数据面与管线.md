# 题库强化设计：152 道真题接入「步步解」，按知识点 × 思路双轴选题

- 状态：待批准
- 日期：2026-11-02
- 来源：用户需求（m00001 / m00144）+ 题库文档 `高中物理高考真题题库 (2).html`

---

## 1. 一句话

把文档里 152 道真实高考物理题（含公式图/图形）离线加工成引擎能教的题目资产，让学生**按知识点**或**按解题思路**挑一道题开始学，并在「举一反三」里沿同样两个方向找到同类题。

## 2. 为什么现在做

现在项目里的"选题"只有两类：教研手写的 5 道电磁感应题，和当场粘贴/拍照的导入题。

- 手写题库太小，覆盖不到教学场景；导入题每题都要现场生成图谱，质量不可控。
- 文档里躺着 152 道真题，带官方参考答案与解析、带两套人工分类（知识点 KG、思路 TH），**是现成的、分类质量远高于模型推测的语料**。
- 引擎（`src/core/locate.js`、`engine.js`）定位学生思路时强依赖 `problem.solutionGraphs`（`locate.js` 多处、`engine.js:734`），没有图谱的题教不动。所以价值不在"多一个题库页面"，而在**这 152 道题都能被引擎教**。

## 3. 目标 / 非目标

**目标**

1. 152 道题全部入库，每道都有：可展示题干（含原图）、可检索文本、解题图谱、答案指纹、官方答案与解析（仅服务端）。
2. 学生能从**知识点**方向选题：模块 → 章 → 知识点 → 题。
3. 学生能从**思路**方向选题：思路大类 → 细分 → 题。
4. 做完一道题后，「举一反三」按知识点/思路方向给出同类题。
5. 选中的题能直接进现有 5 步流程被教（进入对话 → 引擎按图谱定位 → 只给提示不给答案）。

**非目标（本期不做）**

- 组卷、错题本、教师布置作业、题库后台编辑、多学科（只物理）。
- 学生端展示官方解析（见 §11-C5）。
- 用 KaTeX 渲染数学公式（见 §11-C2）。
- 改造旧版前端 `public/app.js`（`index.html` 已不引用）。

## 5. 已定决策（用户，m00144）

- D1 选题 + 举一反三**都要**，两处都按知识点/思路双轴筛。
- D2 解题资产**离线全量预生成**（不在运行时按需生成）。
- D3 公式图**视觉批量转 LaTeX**。
- D4 152 题**一次性全量**入库（不先做力学试点）。
- D5 范围**只到"选题 + 教得动"**，不加组卷错题本。

## 6. 方案选择

只有一条路，其余两条都不成立：

- **甲（采用）：离线管线产出数据资产 + 应用层只做"读数据、筛、教"。** 数据加工是一次性成本，产物是仓库里的 JSON，可 review、可回滚、可重跑；运行时零额外延迟、零新依赖。
- **乙：运行时按需生成图谱。** 已被 D2 否掉。额外代价：首选题要等 30–60 秒模型输出，且质量不可复现（同一道题两次生成不一样），教研无法审核。
- **丙：只做题库浏览页，不接引擎。** 等于把 152 道题做成一个静态列表，学生看完题还得自己粘贴回来。违背"教得动"这一条，也浪费了已有的图谱依赖。

## 7. 数据结构

### 7.1 题库题目对象（在现有 Problem 契约上增量）

```jsonc
{
  "id": "qb-2026-001",                  // 按文档顺序 q1..q152，稳定
  "source": "qbank",
  "subject": "physics",
  "questionType": "单选",                // 单选/多选/实验/计算
  "difficulty": 3,                       // 1–5（易 2 / 中 3 / 难 5）
  "difficultyLabel": "中",
  "exam": { "province": "云南", "year": 2026, "paper": "云南卷" },

  // —— 三份题干，各有唯一消费者 ——
  "stem": "…纯文本，公式写 Unicode（v₀、√(2gh)），禁 $ 与 \\ …",   // 引擎/搜索/指纹比对
  "stemHtml": "<p>…<img src=\"data:image/webp;base64,…\"></p>",     // 仅学生端「原题」视图
  "stemLatex": "…LaTeX 真源，仅服务端…",                             // 转录产物 / 未来渲染

  "options": [{ "label": "A", "text": "…", "html": "…" }],
  "kg": [{ "path": ["力学","动量","动量定理"], "leaf": "动量定理" }],   // 知识点叶子，可多个
  "think": [{ "id": "t2d", "name": "动量守恒", "top": "t2", "topName": "守恒思想" }],
  "topics": ["动量定理", "动量守恒"],      // = kg 叶子名，喂给现有 UI/analysis

  // —— 教得动所需（全部服务端，永不下发前端）——
  "solutionGraphs": [{ "id":"g1","name":"…","preconditions":[],"steps":[
      { "index":1,"title":"…","kind":"setup|identify|precondition|apply|derive|interpret|conclude",
        "intent":"…","concepts":["…"],"cues":["…中文+普通字符，禁 LaTeX…"] }]}],
  "misconceptions": [{ "hintSeeds": ["…"] }],
  "answerFingerprints": ["…从官方答案反推…"],
  "formulaFingerprints": ["…"],
  "solutionInsights": ["…"],
  "referenceAnswer": "B",                // 98 题=选项字母；54 题=文字/公式原文
  "correctOptions": ["B"],               // 仅服务端：选择题正确标号（指纹从正确选项文本派生，见 §11-C6）
  "officialAnalysis": "…官方解析原文（含原图 HTML）…",

  "assets": { "figures": [{ "k": 12, "dataUrl": "data:image/webp;base64,…", "caption": "…图形文字说明…" }] },
  "generation": { "model":"deepseek-flash", "at":"2026-11-02T…", "transcribedBy":"…", "warnings": [] }

```

**为什么是三份题干**：`stemHtml` 要原图（视觉保真）→ 给前端；`stem` 要干净文本（`guard.js` 的指纹比对、搜索、`dropFingerprintsMatchingStem` 都按文本跑）；`stemLatex` 是转录真源，重跑管线时不必再读图。三者由同一份 `stemLatex` 派生，管线里用确定性规则生成，不靠模型各写一遍。

### 7.2 两棵树（taxonomy）

`taxonomy.json` 直接落文档的 KG / TH 结构（不重排、不改名），只补每节点的 `count`（题数，含子节点累计）。原因是这两套分类是教研人工标的，模型重排只会更差。

```
kg:    [ { id:"m-力学", name:"力学", count:61,
           children:[ { id:"c-力学-动量", name:"动量", count:17,
                        children:[ { id:"k…", name:"动量定理", count:9 } ] } ] } ]
think: [ { id:"t2", name:"守恒思想", count:47,
           children:[ { id:"t2d", name:"动量守恒", count:18 } ] } ]
```

## 8. 离线管线（4 阶段，可重跑）

脚本在 `scripts/qbank/`，产物在 `.qbank-out/`（中间态）与 `src/core/qbank/`（终态）。**全程不改产品代码**，可先跑、可回滚。

| 阶段 | 脚本 | 输入 | 输出 |
|---|---|---|---|
| ① 抽取 | `extract.mjs` | 题库 HTML | `raw/<id>.json`：题干/选项/答案/解析的原文 HTML、图片 data URL 映射、kg/think 原始标签 |
| ② 转录 | `transcribe.mjs` | `raw/*.json` | `text/<id>.json`：`stemLatex`、选项 LaTeX、解析 LaTeX、`figures[].caption`（图形文字说明） |
| ③ 生成 | `generate.mjs` | `text/*.json` + 官方答案与解析 | `graph/<id>.json`：`solutionGraphs` / `misconceptions` / `solutionInsights` |
| ④ 装配校验 | `build.mjs` | ①②③ | `src/core/qbank/*.json` + `report.md`（通过率、告警、抽检清单） |

**阶段 ② 的请求形态（已用小样验证）**：一道题的所有公式图打成一批（≤30 张/批，38 道大题需拆）。**每张图前必须先给一行文字锚点 `图 k=2365`**——实测：不标锚点时模型会按"第 1、2、3 张"回下标，与 `data-k` 对不上；标了锚点就能按 `k` 对齐。要求返回 `{"formulas":[{"k":…,"latex":"…"}],"figures":[{"k":…,"caption":"…"}]}`。图形不转 LaTeX（电路图、轨迹图转不了），只要一段**文字说明**，供生成阶段和教师视图使用。

探针实测（`deepseek-chat` → 实际 `deepseek-flash`）：

- 公式图 8 张 + 题干一段：1826 prompt tokens（≈175 tok/图）、267 ms、回出的 LaTeX 正确（`L=1\mathrm{m}`、`B=2\mathrm{T}`、`v_0`、`E_{\mathrm{k}}`）。
- 图形 5 张（761×317 至 748×575，12–22 KB）：1399 prompt tokens、3.0 s、描述可直接用于生成（"纵轴 v_M、横轴 t、虚线标出 v 与 2v、折线在 t_0–3t_0 保持 v"）。

**阶段 ③ 的输入刻意含官方答案与官方解析**：不让模型从头自己解一遍，而是"按官方解析切分步骤、只做结构化"。这样做出来的图谱与教研给的解析同源，不会出现"图谱对但答案错"的双轨问题。

**阶段 ③ 走多模态，且不改产品代码**：`understandProblem(rawText, { adapter })` 的 adapter 是可注入的（`intake.js:70`），所以 `generate.mjs` 传一个闭包 adapter 进去，由它在内部把「题干 + 选项 + 官方答案 + 官方解析 + 该题的图形图片」拼成多模态请求，再把 JSON 交回 `normalizeIntake` 归一化。**官方答案与解析只能走闭包，绝不能拼进 `rawText`**——`intake.js:190` 的 `dropFingerprintsMatchingStem(deriveAnswerFingerprints(referenceAnswer, …), rawText)` 会把"能在输入文本里找到"的答案指纹当成已知量丢弃；若答案出现在 `rawText` 里，整题的答案指纹会被清空，守卫对这道题直接失效。这是本设计里最容易踩、后果最隐蔽的一个坑（表现为"AI 答非所问"，不是"AI 泄题"）。

生成后按官方口径覆盖：`stem`/`stemHtml`/`stemLatex`/`referenceAnswer`/`officialAnalysis` 用题库原文，`solutionGraphs`/`misconceptions`/`solutionInsights` 用模型产物，`answerFingerprints` 用官方答案重建（§11-C6）。

**风格对齐靠 few-shot**：生成提示词里塞 `problems.data.js` 中的 1 道手写题（`phy-emi-01`）作为格式与语感示例——`cues` 是关键词不是句子、`preconditions` 写成"条件 ⇒ 推论"、`intent` 一句话说清这步在做什么。否则 152 道题会出来 152 种风格。

**幂等与恢复**：每阶段按 `id + 阶段名 + 输入内容哈希`缓存，跳过已完成；`--only=qb-2026-041`、`--module=mechanics`、`--force`、`--concurrency=4`。中断后重跑只补缺的。失败写 `warnings` 不中断整批（生成阶段失败的题单独列进 `report.md` 的"待修"区）。

**成本量级**（deepseek-flash 档，按探针实测 token 推算，以实际账单为准）：

| 阶段 | 调用次数 | 输入 token | 输出 token |
|---|---|---|---|
| ② 公式转录 | ~110 批（2433 图 / 每批 20–30 张） | ~43 万 | ~10 万 |
| ② 图形说明 | ~127 次（192 图） | ~5 万 | ~6 万 |
| ③ 图谱生成 | 152 次（+ 约 15% 重试） | ~80 万 | ~80 万 |

合计 **几十元以内**；串行 4–5 小时，`--concurrency=4` 约 1 小时。

## 11. 我替你做的技术决定（可逐条否决）

- **C1 图片内联 data URL，不落地图片文件。** 理由：2433 张小图落地会让仓库和部署多出 2433 个资源文件，还要新增静态路由；内联后一道题自洽，单题响应 ~55 KB（最大 98 张的题 ~260 KB），比原 HTML 一张卷还小。代价：浏览器不复用跨题图片（跨题复用率仅 1.34×，可接受）。若日后变慢，再切成文件，只需改 `assets.figures` 的取值方式。
- **C2 不引 KaTeX。** 学生端看到的是**原图**，保真且零依赖；引擎与提示文本统一用 Unicode 记号（`v₀`、`√(2gh)`），生成阶段用 lint 强制"教学文本禁 `$` 与 `\`"。代价：未来若想让学生端文字公式可变字号，需要再引渲染器。
- **C3 题型/省份/难度作为附加标签**，不动 `Problem` 主契约，避免 `engine/locate/guard` 三处跟着改。
- **C4 图谱按官方解析结构化**，不让模型独立解题（§8 阶段③）。
- **C5 官方解析不下发学生。** 理由：这是产品红线——解析一给，整个"只给提示"就失效了。学生端只有题干 + 提示；解析留在服务端给教师视图与质量审计。
- **C6 `answerFingerprints` 按题型分两路构造，模型给的只做并集补充。** 理由：官方答案才是判分基准；而且 98 题答案是字母，从字母反推不出任何数值指纹（`deriveAnswerFingerprints` 对 `"B"` 输出空数组）。两路是：
  - **非选择题（54 题）**：官方答案文本 → `deriveAnswerFingerprints`（`intake.js:400`）。
  - **选择题（98 题）**：取**正确选项的文本**（含数值、单位、公式）抽指纹；再附加一条"报选项"的内容指纹（如 `(选|答案是|应选)(A|B|C|D)`）。正确选项标号另存 `correctOptions`（仅服务端），不进学生投影。
  - 选择题的教学路径仍按**计算/排除的双轨**切分图谱，不能走成"读出答案"。
- **C7 筛选在服务端做。** 轻索引可以公开，但筛选逻辑一旦放前端，题目全集（含答案字段的相邻数据）会整包下发，泄题面变大。
- **C8 难度映射 易=2 / 中=3 / 难=5**（1–5 与现有 5 道手写题对齐），原始档位另存 `difficultyLabel`。
- **C9 分类树原样落地**，不重排、不改名，只补计数。

## 12. 验收标准

### 12.1 自动化（可跑，进 `test/qbank.test.js` + `scripts/qbank/validate.mjs`）

1. **结构完整**：152/152 通过 schema 校验；每题 `solutionGraphs[0].steps.length ≥ 2`，每步有 `title`/`kind`/`cues`；`kg`、`think` 非空。
2. **标签对账**：对每个 KG 叶子节点、每个 TH 节点，`qbank/search` 返回的题集合与该节点 `count` 完全一致（152 × 2 轴全对账，0 差异）。
3. **防泄题**：遍历 `toStudentProblem()` 的 152 条输出，序列化后 grep 不到：`officialAnalysis`、`referenceAnswer` 的正文、任一 `steps[].cues`、任一 `solutionInsights`、`stemLatex`。（历史漏洞：`conceptTags` 曾泄题，这条就是防它复发。）
4. **指纹有效**：每题 `answerFingerprints` 非空，且不含能匹配题干的已知量（复用 `dropFingerprintsMatchingStem` 的反向断言）。
5. **教学文本合规**：所有 `cues`/`solutionInsights`/`misconceptions[].hintSeeds` 不含 `$`、`\`、`_{`、`^{`。
6. **回归不新增失败**：`node test/run.js` 当前基线是 305/312，已有 7 条失败全部在 `test/ui.test.js`（断言的是旧版 `app.js` 的 DOM：`dropzone`、`page-teacher`、首页模式卡等，与新 `shell.js` 无关）。本次验收线是**仍为 305/312 或更好**，且新加的 qbank 用例全绿；这 7 条作为已知欠账单独记录，不在本次修。`node scripts/eval.js` 离线评测不与基线退化。

### 12.2 人工抽检（随机 20 题，我出清单你过目）

每题看三件事：步骤顺序与官方解析一致；`cues` 是**定位用的关键词/短语**（对齐 `problems.data.js` 手写风格，如 `切割`、`BLv`、`内阻`），不是整句解释、不含答案数值与结论；题干原图在页面上显示正常。

### 12.3 「教得动」端到端（抽 10 题 × 2 个错误思路）

脚本：从题库选题 → 模拟学生说出一个**中途卡住**的思路（如"我用动能定理列到一半不会了"）→ 断言引擎返回：命中的步号 ≠ 1、提示等级 ≤ 2、回复中不含答案数值。10 题里 ≥ 8 题命中正确步才算通过。

## 13. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 公式图转录错（LaTeX 用了错的上下标） | 生成阶段理解偏；学生端看不到（显示原图） | 抽检 10%；`stemLatex` 与 `stem` 双份存，错在服务端可发现可修 |
| 图谱质量不如手写 5 题 | 定位精度低，提示不准 | 抽检 20 题；`generation.warnings` 显式记录；不合格的题标 `needsReview` 并在选题面板隐藏 |
| 152 题一次性全量返工 | 时间成本 | 管线可重跑、按 hash 增量；产物在 git 里，可回滚到上一版 |
| 单题响应 260 KB（98 图） | 移动端慢 | 只发 `stemHtml` 一次；图片与题干同响应；若实测慢，拆出 `/api/qbank/asset/:id/:k` |
| 与现有 5 道手写题并存导致选题列表混乱 | 体验割裂 | `/api/problems` 只返回题库；手写题保留在 registry 里供评测/演示，不在选题面板出现 |
| 模型端点模型名漂移（`deepseek-chat` 实际路由到 `deepseek-flash`） | 管线脚本行为不可预期 | 管线启动时打印 `model` 字段实回值；`report.md` 记录每次运行的真实 model |
