## 二、两条工作线的关系（重要）

本周的工作实际上由两部分组成，**它们是一条完整链路的前后两段**：

```
┌─────────────────────────────────────────────────────────────┐
│  线 A：Student Thought Analyzer Agent                       │
│  （思路诊断 Agent）                                          │
│                                                             │
│  Question + Solution Path + Student Thought                 │
│                      ↓                                      │
│              Student State JSON                             │
│  {current_step, error_type, confidence, ...}                │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  线 B：Hint Engine（提示引擎）                               │
│                                                             │
│  Student State → 层级决策 → 受限生成 → 守卫 → 学生可见提示    │
│                                                             │
│  核心：7 类防泄题检查 + 层级硬护栏                            │
└─────────────────────────────────────────────────────────────┘
```

**线 A 是"医生诊断"，线 B 是"老师教学"。**
本周这两段都已经跑通，并且可以端到端串起来：
一道题进来 → 学生说自己思路 → 系统诊断 → 分层给提示 → 出学习报告。

**关键设计决策（本周最重要的一个判断）**：
把"该给几级提示"和"什么算给了答案"这两个判断**从模型手里拿走**，
交给确定性代码。原因：

- 如果让模型自己决定层级，学生一喊难就会直接拿到最强提示 —— 等于变相给答案；
- 如果只靠 Prompt 里写"请不要给答案"，模型有至少 7 种方式绕过（本周实测抓到 3 种）。

**一句话**：模型的职责是"懂"，代码的职责是"分寸"。

## 三、本周关键产出

### 3.1 卡点分类体系

把"学生卡住"这件事拆成 7 种互不相同的处境，每种对应不同的应对方式：

| 卡点类型 | 学生处境 | 应对 |
|---|---|---|
| `not_started` | 还没形成思路 | 只做结构化澄清，不给任何方向 |
| `precondition_gap` | 知道规律但漏了前提 | **条件追问**（最高价值场景） |
| `knowledge_gap` | 不知道用哪个规律 | 问过程性质，不点名公式 |
| `direction_lost` | 知道规律但走不下去 | 指方向，不给式子 |
| `dead_end_path` | 当前路子走不通 | 引导换工具 |
| `execution_error` | 思路对但算错 | 邀请自查 |
| `finished` | 已接近完成 | **AI 应沉默** |

### 3.2 分层提示机制

| 层级 | 名称 | 允许 | 禁止 |
|---|---|---|---|
| L0 | 结构化澄清 | 分清已知/目标/困惑 | 任何物理方向 |
| L1 | 条件追问 | 追问规律的前提 | 出现公式；点名该用哪个公式 |
| L2 | 方向提示 | 指出该关注哪两个量的关系 | 给出关系式；给出数值 |
| L3 | 降级示范 | 示范**一个动作** | 给出数值；给出完整表达式 |

**两条硬护栏**：
- 禁止跳级：能达到的层级 = 从 L1 开始的最长连续段 + 1
- 禁止原地打转：同一卡点同一层级给过 2 次即升级；已到 L3 则要求学生复述

### 3.3 防泄题守卫（本周最核心的工程资产）

提示文本在出口必须通过 **7 类确定性检查**：

| # | 检查 | 拦截内容 |
|---|---|---|
| 1 | `answer_in_text` | 数值答案（含中文说法"一库仑"） |
| 2 | `formula_leak` | 解法性公式的完整表达式 |
| 3 | `level_overflow` | 超出声明层级（L1/L2 出现公式） |
| 4 | `solution_dump` | 编号步骤 >2 个或推导箭头 >2 个 |
| 5 | `final_conclusion` | "所以答案是/最终结果"类收口句式 |
| 6 | `concept_out_of_domain` | 跑题：引用了本题不存在的概念 |
| 7 | `solution_insight` | **说出解题核心结论**（如"r 是内阻"） |

拦截后自动降级重写；模型最多重试一次；两次都不过就用安全兜底模板。
**永不泄题优先于文采。**

## 四、验证结果

### 4.1 自动化测试

```
单元测试        97 / 97 通过
评测场景        19 个（教研标注：15 物理 + 4 数学）
```

### 4.2 真实模型实测（智谱 glm-4-plus，19 场景 / 39 轮）

```
【安全指标 —— 必须为 0】
泄题率                          0%
跳级率                          0%
确认答案次数                     0
解法倾倒次数                     0
崩溃次数                         0

【能力指标】
定位命中率                      92.9%
错因命中率                      100%
可行动率                        100%
静默正确率                      100%

【护栏工作强度】
守卫拦截次数                     6 ~ 10（跨运行）
```

**唯一的定位偏差出现在数学证明题上**（预期第 5 步、实际第 2 步，但错因判定正确）。
这不是 bug 而是规律：物理题的步骤能用公式符号精确定位，
数学证明题要靠"证明动作"判断，同一动作可能出现在多个步骤里。

**结论：抽象不绑学科，但每科的质量需要各自的语料来调。**

### 4.3 三项压力测试

| 测试 | 结果 |
|---|---|
| 恶意适配器（每轮都故意泄题） | 交付文本泄题率 **0%**，全部被守卫拦下重写 |
| 无 API Key（离线规则桩） | 全流程可跑，安全指标同样为 0 |
| 跨学科（加入 1 道数学证明题 + 4 个场景） | 引擎代码**未改一行**即可处理；定位质量低于物理（92.9% vs 100%），说明每科需各自的语料调优 |

## 五、本周发现并修复的问题

**这一节是本周最有价值的部分。** 所有问题都是评测跑出来的，不是设计时预见到的。

### 阶段一：离线开发时发现（5 个）

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | 单元测试全绿但评测全红 | 错因命中率 **0%** | 中文修饰语会拆散关键词（"安培力**应该**向右"匹配不到"安培力向右"），重写为分路径匹配策略 |
| 2 | 否定识别误伤 | 最该命中的场景全被判掉 | "不变""不知道"里的"不"被当成否定词；改为反向枚举 + 否定型签名跳过检查 |
| 3 | 定位打分权重失衡 | 定位到错误的步骤 | 打分公式里"步骤序号"权重过大，压过了"命中数" |
| 4 | 评测指标定义有缺陷 | 差点去修一个不存在的问题 | 只看最后一轮诊断，而最后一轮常是"然后呢"，本就不该带错因 |
| 5 | 跳级护栏有真实漏洞 | 学生可越级拿到最高提示 | 原逻辑只查"前一级是否存在"，历史缺 L1 时能直达 L3；改为按连续前缀判断 |

### 阶段二：接入真模型后发现（3 个，离线桩永远看不到）

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 6 | 冲突消解规则太保守 | 定位命中率仅 **72.7%** | 学生原话比模型推断更可靠；冲突时优先原话通道 → **72.7% → 100%** |
| 7 | 模型用"合规方式"说出答案 | **未拦截的泄题** | L1 层回复"r 组成了内阻"—— 无公式无数值，原 6 类检查全放行；新增第 7 类检查 `solution_insight` |
| 8 | 留了一条捷径 | 学生可声称"我算错了"拿最强提示 | 移除了"执行错误可直接给 L3"的特例，统一从 L1 开始 |

**两条方法论结论：**

1. **测试数据必须来自真实语料。** 最初的单元测试用例是从规则表原文抄的，天然匹配，
   所以 44/44 全绿而评测 0% —— 这是"测试数据太干净"导致的假通过。

2. **评测必须跑真模型。** 问题 6、7、8 只有真模型才会暴露：
   离线桩的输出来自不含答案的模板，永远不会"说漏嘴"，也不会误判定位。
