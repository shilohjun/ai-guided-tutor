## 一、总体概述

### 1.1 一句话说明这个项目在做什么

现在所有学习产品的入口都是「学生提问 → AI 回答」，AI 主要通过最后的答案判断学生的问题。
我们把这个方向反过来：**让学生先交出自己的思路，AI 看懂他卡在哪一步，然后只给提示、不给答案。**

方向一变，立刻产生一个全新的技术难题：

> **怎么保证 AI 在"帮"学生的同时，绝不把答案说出去？**

本周的全部工作都围绕解决这个问题展开。

### 1.2 技术栈

| 层次 | 选型 | 为什么这么选 |
|---|---|---|
| **运行时** | Node.js ≥ 20（原生 ESM） | 零依赖即可运行，方便交到教研/企业手里直接跑 |
| **第三方依赖** | **0 个**（不用 Express、不用任何框架） | 企业内网环境 `clone` 下来就能开，不需要联网装包 |
| **大模型** | OpenAI 兼容协议（实测用智谱 glm-4-plus、DeepSeek deepseek-chat） | 换供应商只改 `.env` 三个变量，不动代码 |
| **模型可替换性** | 适配器模式（`LLMAdapter` 接口） | 真模型与离线规则桩同一接口 —— 没 Key 也能跑全套测试 |
| **前端** | 原生 HTML + CSS + ES Module | 无构建步骤，避免现场演示因构建失败翻车 |
| **数据层** | 结构化题目图谱（JSON 数据文件）+ 运行时读题生成（`intake.js`） | 题库图谱需教研投入，做成可评审、可版本控制的文件；任意新题目由模型现场读题生成 |
| **测试** | 自研极简测试运行器（289 个用例） | 不引测试框架，保持零依赖 |
| **评测** | 19 个教研标注场景 + 6 项量化指标 | 让"不给答案"从主观判断变成可复现的数字 |
| **部署** | 本地 Node 服务 / Vercel serverless / GitHub Pages | 三种形态共用同一份业务逻辑 |

**架构上的核心主张：模型负责"懂"，代码负责"分寸"。**

```
LLM（观察员）          规则代码（决策者）        守卫（把关者）
──────────────        ──────────────────       ──────────────
学生说了什么           该给几级提示              有没有泄题
落在哪一步             用什么策略                有没有跑题
像哪类错因             允许引用哪些概念          有没有越界
```

> 本期新增的**读题链路**沿用同一个切法：模型只负责"读懂题目"（产出结构化图谱），
> 而"什么算说出了答案"（三组指纹）必须经过清洗与兜底，缺失时要显式告警。
> 详见第七节。

**为什么这么切**：如果把"该给几级提示"和"什么算给了答案"交给模型，会出现两个方向的失效 ——
学生一喊难就直接拿到最强提示（等于变相给答案）；或者模型换个说法、给近似值、给公式绕过约束。
这两件事都是确定性问题，必须由代码保证。

**关于用 GitHub 来展示 —— 我认为这是目前最合适的方式，理由有三：**

1. **可信度来自可复现，而不是来自描述。**
   别人不用相信我的总结，`clone` 下来跑一条命令就能看到 289 个测试通过、泄题率 0%。

2. **演示页可以做得很轻。**
   `showcase/index.html` 是一个**零依赖的单文件网页** ——
   没有构建步骤、不加载任何外部资源，发一个链接对方打开就能看。
   发给企业方或老师时，比传一份 PPT 或 PDF 都方便。

3. **诚实的边界可以被看见。**
   演示页里专门留了一页讲"**还没证明什么**"（教学质量未验证、语料只有 19 个场景、
   跨学科只做了初步验证）。把边界说清楚，反而更容易让对方信任前面的数据。

> 如果你希望改成"只给链接、不暴露源码"，也可以只发布演示页、
> 源码留在私有仓库 —— 这套结构支持两种做法，切换只需改一个设置。

## 四、不足与需要改进的地方

### 4.1 验证深度不足（最需要补的一项）

| 问题 | 现状 | 影响 |
|---|---|---|
| **教学质量未经人工验证** | 目前所有指标测的都是"安全"（有没有泄题、有没有越级），**没有一个指标测"有用"** | 无法回答"这个提示到底有没有帮到学生" |
| **评测场景只有 19 个，且是人工编写的** | 15 物理 + 4 数学 | 只能证明"框架对了"，**不能证明能应对真实学生** |
| **长会话未验证** | 场景集最长 3 轮 | 不知道 10 轮以上会不会重复、失忆、层级混乱 |
| **模型横评仍不充分** | 已测智谱 glm-4-plus 与 DeepSeek deepseek-chat | 两者安全指标一致，但样本只有两家；内网模型的 JSON 稳定性尚未验证 |

**改进计划**：
- 抽样 20 轮真实对话请教研盲评，只问三个问题：① 提示是否准确指向卡点？
  ② 学生看完还得自己动脑吗？③ 换成人类老师会说得更多还是更少？
- 用真实学生解题记录把场景集扩到 50+。**这是目前最需要企业支持的一件事。**

|---|---|---|
| 拍照识题（proposal ①） | 需要视觉模型（qwen-vl / glm-4v）；**已给出补法，但未伪造结果** | 约 0.5 天 |

### 4.3 工程与部署层面的已知限制

| 限制 | 说明 |
|---|---|
| 公网 Demo 的会话会丢 | serverless 冷启动会清空内存中的会话，间隔久了学习报告页会提示失效（已做友好降级） |
| 会话无持久化 | 当前存进程内存，重启即清空。生产化需接入带学生 id 的存储 |
| 无鉴权、无限流 | 本地开发用的小服务，不适合直接承载真实流量 |
| API 限流敏感 | 实测一次评测耗时在 88 秒到 1925 秒之间波动，生产环境需要请求排队与退避重试 |
| 离线桩能力有限 | 它的价值是"验证护栏与流程"，无法处理真实学生的多样化表达 |

### 4.4 方法论层面的两条教训

1. **测试数据必须来自真实语料。**
   最初的单元测试用例是从规则表原文抄的，天然匹配 ——
   所以 44/44 全绿，而真实评测的错因命中率是 **0%**。这是"测试数据太干净"导致的假通过。

2. **评测必须跑真模型。**
   本周 8 个问题里有 3 个**只有真模型才会暴露**：
   定位被模型误判拉偏（命中率仅 72.7%）、
   模型用"合规的方式"说出答案（无公式无数值，原 6 类检查全部放行）、
   以及我们自己留下的一条"学生声称算错就能拿最强提示"的捷径。

**第一句**：我做了一个 AI 老师，你把解题思路说给它听，它能看出你卡在哪一步 —— 但它绝不告诉你答案，只会问你"这个公式成立需要什么条件？"这类问题，逼你自己想出来。

## 九、本轮修复（三条试用反馈 + 一个评测抓出的漏洞）

### 9.1 布局遮挡

反馈："向下浏览时，右侧那一栏固定住了，压住下面的内容。"

根因：侧栏同时用了 `position: sticky` + `max-height: calc(100vh-…)` + 内部 `overflow`。
去掉 sticky，整页按普通文档流滚动 —— 遮挡在结构上就不可能发生。
全站只有顶栏保留 sticky，并加了两条断言防回退。

### 9.2 交互逻辑（本轮最实质的改动）

反馈："我直接回答出正确答案时，它还在引导我。真实的学习过程往往不是线性的。"

改成**不对称的答案判定**：

| 学生这一轮 | 引擎 | 界面 |
|---|---|---|
| 说对了（部分） | 确认这一问，不宣布完成 | 绿色确认气泡 + "还剩 N 个待求量" |
| 说对了（全部） | 宣布完成 | **庆祝界面** → 确认后跳学习报告 |
| 说错了 | 什么都不说，走引导 | 与原来一致 |

非线性也补齐了：状态条常驻「我已完成 →」随时可看报告；学习报告支持
`?session=<id>` 分享链接。

**两个设计决策值得记：**

① **判定按"待求量覆盖"，不是"数了几个数值"**，否则中间量（如"总时间 2 秒"）
   会触发假庆祝 —— 而假庆祝比不庆祝更伤。

② **确认只替代"提示"，不替代"观察"。** 第一版把确认路径放在最前面直接 return，
   跳过了观察与定位，离线评测立刻反映：定位命中率与错因命中率同时下降。
   而"学生答对了第一问、同时漏了内阻"是完全可能的，两件事不该互相排斥。

### 9.3 语言风格

`DRAFT_SYSTEM_PROMPT` 的身份改成"一位有二十年教龄的中学理科教师"，
并加了语域约束（规范术语、不用语气词/颜文字/夸张词、句子完整）；
代码侧的 voice 关同步扩了黑名单，且**语气词只删字、空话才删句**。
顺带把组装消息里的 `👉` 换成 `【下一步】`（评测的检测式同步改了）。

### 9.4 评测抓出的一个真漏洞（本轮唯一由机器发现的）

真模型评测报出 **泄题率 2.6%**（39 轮里 1 次）。定位到那一句：

> 你大概停在「因此 a、b 有公因数 2，与"互质"矛盾」这一步。

那是**步骤标题**，而这道数学题的步骤标题本身就是证明的结论。

这个洞**一直存在**，只是离线桩的定位很少落到那一步。修法：
标题要过与答案同一套指纹检查，`derive`/`conclude` 两类标题一律不引，
不安全的退到「第 N 步（动作类型）」。同一判据也用在学习报告的卡点名上。

修完泄题率回到 **0%**，定位命中率 100%。

> 三条反馈是人发现的，这一条是机器发现的 —— 两者缺一不可。
> 自动评测守得住"逻辑正确"，守不住"看起来对不对"；
> 而亲眼看着别扭的地方，也不一定测得出泄漏。

### 9.5 本轮规模

测试 **152 → 182 个用例**（新增答案判定 20 + 步骤标题安全 4 + 布局 2 + 语域 6）。
真模型评测（deepseek-chat）安全指标全 0，能力指标：定位 100% / 错因 100% / 可行动 92.3%。

### 10.2 最实质的一条：答案判定

原来的引擎刻意"不判对错"（怕变成对学生的评价），副作用是
**学生自己走通一步时系统继续追问**。现在是一个**不对称判定**：

| 学生这一轮 | 引擎 | 界面 |
|---|---|---|
| 说对了（部分） | 确认这一问，**不**宣布完成 | 确认气泡 + "还剩 N 个待求量" |
| 说对了（全部） | 宣布完成 | **庆祝界面** → 确认后跳学习报告 |
| 说错了 | **什么都不说**，走引导 | 与原来一致 |

"说错了不指出"是刻意的：这个产品不做判卷，只做"陪你想"。

**判定按"待求量覆盖"，不是"数了几个数值"。** 踩到的假阳性：
自由落体题的参考答案含"总时间 t = 2 s"，朴素抽取会把它当答案 ——
学生一提"总时间 2 秒"就弹庆祝。**假庆祝比不庆祝更伤**（学生立刻知道系统在瞎说）。
修法是把参考答案按分句挂到待求量上（只在等号左边找符号）。

**第二个设计决策：确认只替代"提示"，不替代"观察"。**
第一版把确认路径放在最前面直接 `return`，跳过了观察与定位 ——
离线评测立刻反映：定位命中率与错因命中率同时下降。
而"学生答对了第一问、同时漏了内阻"完全可能（E = BLv 与内阻无关，下一步算电流才踩到），
两件事不该互相排斥。改完指标完全恢复。

### 10.3 两条静默 bug（都由真模型评测抓到）

| # | 现象 | 根因 | 为什么危险 |
|---|---|---|---|
| 1 | 泄题率 2.6%，复述段说出「因此 a、b 有公因数 2，与"互质"矛盾」 | **步骤标题本身就是结论**，而引擎把标题原样复述给学生 | 这个洞**一直存在**，只是离线桩很少定位到那一步，所以从没被看见 |
| 2 | 离线定位命中率 92.9% → 85.7% | 归一化折平后，同一式子的两种拼法（`a²=2b²` / `a^2=2b^2`）**同时命中，证据数被算成 2** | 定位按证据数排序 ⇒ 系统性偏向写得啰嗦的那一步，学生被卡在原地 |

第 1 条的修法同时改变了我们对"步骤标题"的认识：

> **步骤标题是教研语言，不是学生语言。** 能不能给学生看要逐条判断，不能默认放行。

现在标题要过与答案同一套指纹检查，`derive`/`conclude` 两类一律不引，
不安全的退到「第 N 步（动作类型）」。同一判据也用在学习报告的卡点名上
（教师视图仍拿原始标题：同一份数据、两个投影）。

### 10.4 长题目的两半问题

用户提的是"显示"，做的时候发现还有另一半 —— **读题**。

| 半边 | 现象 | 修法 |
|---|---|---|
| 显示 | 460+ 字的题把整页拉长 | 题干加 `min(46vh,420px)` 阅读区 + 滚动 + 底部渐隐提示 |
| 读题 | 六问的题**读题直接失败**，报"无法解析 JSON" | 其实是 `max_tokens` 用尽被截断 ⇒ 错误分类 + 提示词里压输出规模 |

> 截断降级的后果不是"图谱糙一点"，而是**整题退回通用骨架**：
> 知识点、错因、参考答案、**全部防泄题指纹**一起丢。
> 换句话说，**题目越长，守卫对这道题失效的概率越高** —— 这条必须堵上。

修完实测那道六问的题：9 步合并路径 + 6 个正确知识点 + 3 条错因 + 11 条指纹，
`graphReady: true`。

### 10.5 符号输入

学生反馈："一些物理的表达式很难写上去。"`²` `₀` `μ` `Ω` `√` 在普通键盘上打不出来，
而写不出公式的学生只能用文字绕，**思路的表达精度直接下降**。

两层机制（规则放在纯函数模块 `public/mathinput.js`，浏览器与 Node 共用）：

| 机制 | 覆盖谁 | 例子 |
|---|---|---|
| 符号面板 | 所有人 | 上标 / 下标 / 希腊 / 运算 / 其它，点一下插到**光标处** |
| 自动替换 | 习惯 ASCII 的人 | `v^2`→`v²`、`v_0`→`v₀`、`mu`→`μ`、`>=`→`≥` |

**只认显式约定，不猜**：`^` `_` `>=` 是声明式的，见到就换；
而 `v0` → `v₀` 这种"猜意图"的一律不做 —— 它会顺手把 `sin53` 变成 `sin₅₃`，
**而这题里真的有 `sin53°`**。

希腊字母延迟到边界才替换（逐字触发时分不清 `pi` 与 `pilot`）。
这个坑只有**逐字测试**能发现：整串测试里 `pilot` 的 `pi` 后面跟着 `l`，规则一开始就不成立。

后端同步做了归一化对齐（`^2`→`²`、`_0`→`₀`）：
教师写的 cue 是 `v²=2aL`，学生打的是 `v^2=2aL`，不对齐的话这条 cue 对他等于不存在 ——
他会被判成"没说到点子上"，而他其实说得完全正确。

### 10.6 本轮的方法论收获

1. **评测的价值不在于分数，而在于它抓到了人没看到的东西。**
   本轮两个最严重的漏洞（步骤标题泄漏、证据重复计分）**都是机器发现的**，
   而三条界面/交互问题都是人发现的。两者不可互相替代：
   自动评测守得住"逻辑正确"，守不住"看起来对不对"；
   亲眼看着别扭的地方，也不一定测得出泄漏。

2. **"不报错"是最危险的一类 bug。**
   本轮 9 条修复里，有 6 条属于"不报错、只是悄悄变差"：
   步骤标题泄漏、指纹静默失效、证据重复计分、读题静默降级、
   滚动提示永不出现、隐藏时量不出高度。
   共同点是**没有任何异常**，只能靠断言或截图发现 —— 所以它们现在都有断言。

3. **一个改动的副作用可能出现在离它很远的地方。**
   为了让学生打的 `v^2` 能命中 cue，我在归一化里折平了上标；
   结果它同时改坏了定位排序（证据重复计分）和指纹匹配（死指纹）。
   这两处都不在改动范围内 —— **改公共基础函数，必须重跑全套评测**。

### 10.7 下一步（P0 未变，新增两条）

| 优先级 | 事项 | 需要什么 |
|---|---|---|
| **P0** | 教研盲评 20 轮真实对话 | 教研同学约半天 |
| **P0** | 真实学生语料把场景扩到 50+ | **企业提供真实学生解题记录** |
| **P0（新）** | 教研抽查 20 份**导入题目的生成图谱** | 读题链路是最大新变量，图谱质量决定提示质量 |
| **P1（新）** | 长题目（8 问以上）的图谱规模是否够用 | 需要更多长题样本压测 |
| P1 | 长会话疲劳测试（10+ 轮） | 无 |
| P1 | 拍照识题链路 | 视觉模型 + 教研复核图谱 |

### 10.8 三句话收尾

**第一句**：本轮把产品从"能引导"推到了"**能确认你答对了**" ——
学生说对了就确认（全对就庆祝），说错了什么都不说，继续陪他想。

**第二句**：最值得记的不是新功能，而是**评测抓出的两个静默漏洞** ——
复述段把步骤标题原样说给学生（而那道数学题的标题就是证明结论）、
以及归一化折平后同一式子被重复计分把定位吸住。
两个都不报错，两个都只能靠评测和断言发现。

**第三句**：现在 289 个测试、真模型泄题率 0%、定位与错因命中率 100%；
但这些数字证明的仍然是"**守得住**"，不是"**有用**" ——
那件事还是得请教研老师看真实对话才能判断。

### 12.4 真实链路

| 链路 | 实现 | 验证 |
|---|---|---|

| 拍照识题 | `/api/ocr` | 已用真实题图验证，返回 `rawText` / `latencyMs` |

2. 卡点与深层问题（左）；
3. 下一步（举一反三 + 行动建议，右）；
4. 学习时长放页脚；窄屏自动单列。

- 前端按钮与“给我公式”打字请求走同一条服务端校验，不把公式提前塞进 `/api/problem`。

已用真实会话验证：L3 后取到电磁感应卡，报告 `formulaCards = 1`。

### 12.6 演示模式

| 项 | 行为 |
|---|---|
