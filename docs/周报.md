## 一、项目概述

### 1.1 一句话说明它在做什么

现在所有学习产品的入口都是「学生提问 → AI 回答」，AI 主要通过最后的答案判断学生的问题。
我们把这个方向反过来：**让学生先交出自己的思路，AI 看懂他卡在哪一步，然后只给提示、不给答案。**

方向一变，立刻产生一个全新的技术难题：**怎么保证 AI 在"帮"学生的同时，绝不把答案说出去？**
本周的全部工作都围绕解决这个问题展开。

### 1.2 技术栈

| 层次 | 选型 | 为什么这么选 |
|---|---|---|
| **运行时** | Node.js ≥ 20（原生 ESM） | 零依赖即可运行，方便交到教研/企业手里直接跑 |
| **第三方依赖** | **0 个**（不用任何框架） | 企业内网环境 `clone` 下来就能开，不需要联网装包 |
| **大模型** | OpenAI 兼容协议（实测智谱 glm-4-plus、DeepSeek deepseek-chat） | 换供应商只改 `.env` 三个变量，不动代码 |
| **模型可替换性** | 适配器模式（`LLMAdapter` 接口） | 真模型与离线规则桩同一接口 —— 没 Key 也能跑全套测试 |
| **前端** | 原生 HTML + CSS + ES Module | 无构建步骤，避免现场演示因构建失败翻车 |
| **数据层** | 结构化题目图谱 + 运行时读题生成（`intake.js`） | 题库图谱做成可评审、可版本控制的文件；任意新题由模型现场读题生成 |
| **测试** | 自研极简测试运行器（当前 273 个用例） | 不引测试框架，保持零依赖 |
| **评测** | 19 个教研标注场景 + 6 项量化指标 | 让"不给答案"从主观判断变成可复现的数字 |
| **部署** | 本地 Node 服务 / Vercel serverless / GitHub Pages | 三种形态共用同一份业务逻辑 |

### 1.3 核心主张：模型负责"懂"，代码负责"分寸"

```
LLM（观察员）          规则代码（决策者）        守卫（把关者）
──────────────        ──────────────────       ──────────────
学生说了什么           该给几级提示              有没有泄题
落在哪一步             用什么策略                有没有跑题
像哪类错因             允许引用哪些概念          有没有越界
```

**为什么这么切**：如果把"该给几级提示"和"什么算给了答案"交给模型，会出现两个方向的失效 ——
学生一喊难就直接拿到最强提示（等于变相给答案）；或者模型换个说法、给近似值、给公式绕过约束。
这两件事都是确定性问题，必须由代码保证。读题链路沿用同一条切法：模型只负责"读懂题目"，
而"什么算说出了答案"（三组指纹）必须经过清洗与兜底，缺失时显式告警。

## 二、成果全景

### 2.1 三根柱子（产品地基，也是后面所有改动所服务的东西）

**A · 卡点分类体系**

把"学生卡住了"拆成 **7 种互不相同的处境**，每种对应不同的应对方式 —— 而不是笼统地"给个提示"：

| `StuckKind` | 学生处境 | 应对 |
|---|---|---|
| `not_started` | 还没形成思路 | 结构化澄清，先问不给提示 |
| `knowledge_gap` | 不知道用哪个规律 | 条件追问 / 定向追问 |
| `precondition_gap` | 知道规律但漏了前提 | 条件追问（最强项） |
| `direction_lost` | 知道规律但走不下去 | 方向提示 |
| `execution_error` | 思路对了算错了 | 局部示范（只示范动作，不示范答案） |
| `dead_end_path` | 自己已发现这条路走不通 | 换工具，而不是继续算 |
| `finished` | 已经收口 | 确认 / 收敛 |

证据：`types.ts` 的 `StuckKind`；`route.js` 按卡点分派策略；`test/route.test.js`。

**B · 分层提示机制**

`L0` 结构化澄清 → `L1` 条件追问 → `L2` 方向提示 → `L3` 降级示范。**两条硬护栏**：

- ① **禁止跳级** —— 能达到的层级 = 从 L1 开始的最长连续段 + 1（按"连续前缀"判断，
  而不是只看前一级）。
- ② **禁止原地打转** —— 同一卡点同一层级给过 2 次即升级；已在 L3 则不再给提示，
  改为**要求学生复述自己的下一步**。

证据：`route.js` 护栏 A（按 `reachable + 1`）/ 护栏 B（按 `sameLevelSameStepCount`）；
`test/route.test.js`、`test/engine.test.js`。

**C · 防泄题机制**

提示文本在出口必须通过 **7 类确定性检查**：

| # | 检查函数 | 违规 `kind` | 拦截内容 |
|---|---|---|---|
| 1 | `checkAnswerLeak` | `answer_in_text` | 答案数值 |
| 2 | `checkFormulaLeak` | `formula_leak` | 解法公式 |
| 3 | `checkLevelOverflow` | `level_overflow` | 层级越界 |
| 4 | `checkSolutionDump` | `solution_dump` | 整段解法倾倒 |
| 5 | `checkConclusion` | `final_conclusion` | 收口句式 |
| 6 | `checkConceptDomain` | `concept_out_of_domain` | 跑题 |
| 7 | `checkSolutionInsight` | `solution_insight` | 把结论说破 |

违规 → 按严重度选最保守的**降级重写**策略；最危险的四类直接换成安全兜底模板。
证据：`guard.js` 的 `guard()` 恰好 7 个检查；`repairHint()` 策略分流；`test/guard.test.js`。

### 2.2 各轮累积的新能力

| # | 成果 | 一句话 |

| 1 | **读题链路** | 粘贴任意题干 → 知识点 / 已知量 / 待求量 / 路径图谱 / 错因库 / 三组防泄题指纹 |

## 六、方法论收获（比功能更值得记）

### 6.1 评测的价值不在于分数，而在于它抓到了人没看到的东西

两个最严重的漏洞**都是机器发现的**（步骤标题泄漏、证据重复计分），
而界面/交互问题都是人发现的。两者不可互相替代：自动评测守得住"逻辑正确"，
守不住"看起来对不对"；亲眼看着别扭的地方，也不一定测得出泄漏。

**典型的机器发现**：真模型评测报出泄题率 2.6%（39 轮里 1 次），定位到那一句
"你大概停在「因此 a、b 有公因数 2，与"互质"矛盾」这一步" —— 那是**步骤标题**，
而这道数学题的步骤标题本身就是证明的结论。修法：标题要过与答案同一套指纹检查，
`derive`/`conclude` 两类标题一律不引，不安全的退到「第 N 步（动作类型）」。
修完泄题率回到 0%、定位命中率 100%。

### 6.2 "不报错"是最危险的一类 bug

本轮多条修复属于"不报错、只是悄悄变差"：步骤标题泄漏、指纹静默失效、证据重复计分、
读题静默降级、滚动提示永不出现、隐藏时量不出高度。共同点是**没有任何异常**，
只能靠断言或截图发现 —— 所以它们现在都有断言。

### 6.3 一个改动的副作用可能出现在离它很远的地方

为了让学生打的 `v^2` 能命中 cue，在归一化里折平了上标；结果它同时改坏了定位排序
（证据重复计分，定位命中率 92.9% → 85.7%）和指纹匹配（死指纹）。
**改公共基础函数，必须重跑全套评测。**

### 6.4 测试数据必须来自真实语料

最初的单元测试用例是从规则表原文抄的，天然匹配 —— 所以 44/44 全绿，
而真实评测的错因命中率是 **0%**。这是"测试数据太干净"导致的假通过。

## 七、三句话说明我的工作

**第一句**：我做了一个 AI 老师，你把解题思路说给它听，它能看出你卡在哪一步 ——
但它绝不告诉你答案，只会问你"这个公式成立需要什么条件？"这类问题，逼你自己想出来。

**第二句**：为了保证它真的不给答案（而不是我们嘴上说说），我在它开口之前加了一道"安检" ——
每条提示都要过 7 道检查，凡是出现答案数字、解题公式、或者"所以答案是…"这种话，
就拦下来重写。我用真实模型测了几十轮，它曾经多次想越界，全被拦住了。

**第三句**：现在这套东西已经放到 GitHub 上，别人打开链接就能看演示，也能自己下载跑一遍
看到 273 个用例全部通过 —— 但我最想说的其实是它的不足：**现在的数据只能证明它守得住不给答案，
还证明不了它的提示对学生真的有用**，这件事得请教研老师实际看 20 轮对话才能判断。
