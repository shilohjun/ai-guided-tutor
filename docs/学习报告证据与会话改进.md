# 学习报告：会话与证据逻辑改进

本轮只调整数据保存、核验、报告计算和现有控件的数据绑定；不改报告结构、CSS、卡片位置或辅导提示词。

## 对建议的判断

| 建议 | 判断与落实边界 |
| --- | --- |
| 报告依赖完整会话，而非题库命中 | 优先级最高。确认题目时保存服务端题目快照，包含原始文字、确认题干、可用图片、已知条件、待求量、来源、可空题库ID、评估规则。不能把客户端提交的答案当成标准答案。 |
| 字段缺失只影响相应部分 | 有用。旧会话找不到题目时仍生成过程报告；缺少知识标签、可匹配练习或可靠答案不使整份报告失败。存储读取失败与“确实没有记录”仍区分，前者返回可重试错误，不能伪造空会话。 |
| 五类学习状态 | 有用，但不能靠AI语气、答题轮数或“我懂了”判断。逐问保存独立完成、提示后完成、示范后完成、仍有错误、尚未作答/证据不足，并保留错误与后续修正。 |
| 进度与报告共用记录 | 有用。服务端按有明确对象的作答累计，不再由前端对答案数值取并集；相同数值不能代表两个不同小问。定位到某步不代表前面已完成。 |
| 为了填满页面自动推断掌握/正确率 | 不建议。一个选择答案正确不等于它涉及的全部知识点都已掌握；标签是题目属性，不是学生水平。证据不足显示为待核验。 |

## 已确认的代码问题

1. 原掌握规则仅覆盖5道内置物理例题。大部分扩充题库题没有对应知识评估规则，导致个人掌握栏缺少数据。
2. 旧逻辑首次生成报告需要注册表里仍有题目；只有已生成过的报告能绕过题目过期。
3. 独立完成度把“定位到/提问过的步骤数”计作完成，不能证明独立完成。
4. 报告第一次生成后永久冻结，继续聊天得到的新证据无法进入报告。
5. 对话完成状态原先由客户端累计数值，报告却独立重算，口径可能不同。

这些是代码中确认的问题；某次线上报错是否由临时注册表TTL、多实例或存储故障造成，仍需该次会话编号、题目编号及后台日志定位，不能据此直接认定。

## 处理后的数据流

确认题目 → POST /api/session/start → 保存服务端题目快照 → 每轮先保存输入处理状态 → 成功后保存学生发言、AI回答和提示记录 → 统一逐问证据计算 → 对话完成情况与报告复用同一口径。

- 题目快照优先于当前题库/注册表，题库改版不改写已保存会话的题意。
- 模型调用失败的原始输入仍在 inputLog，状态为 failed；它不计作已核验正确/错误证据。
- 新轮次使旧报告进入 reportHistory，再按新增证据计算新报告；同一版本重复读取不重算。
- 无快照的旧会话最多恢复过程报告，不能凭空恢复原题、标准答案或真实正确率。
- 完成率=有核验证据完成的待求量/已识别待求量；分母未知时为null。它与首次独立作答正确率、知识掌握分别计算。
- 选项题仅在标准答案是明确、独立的选项字符串且学生明确选择时核验；问句、猜测、引用和含糊说法不作完成证据。
- 数值题需要明确待求量、值及可识别单位。未知格式、公式图片、缺少可靠参考答案保持待核验；不声称实现通用物理解题判卷。
- 模型自动生成的导入题参考答案默认未经可靠核验，不能直接计正确率。只有服务端/教研明确标记 referenceVerified=true 后才能使用；客户端无法通过确认接口写入这个标记。
- 现有UI继续使用“掌握/待巩固/薄弱”区域；待核验内容带文字说明，绝不当作“薄弱”。作答独立完成也不直接改成知识掌握。

## 存储是必须补上的部署条件

快照只能保存在实际配置的存储里，改算法不能让进程内存跨重启或跨服务器共享。

- 单机本地测试可配置 STORE=file，STORE_DIR指向持久目录，重启后仍能恢复。
- 多实例/云函数必须接共享数据库（项目已有cloudbase驱动），并验证实际 store.kind 是cloudbase，不能只看环境变量：驱动打开失败时可能降级到memory。
- 默认memory适合演示，不能承诺隔天、重启或换实例后记录还在。
- /api/session/start返回saved与durable，供排查保存是否成功；没有修改密钥或生产部署配置。

## 本地学生场景复测（2026-11-14）

复现8轮学生求助模式，确认旧逻辑只保留首次笼统困惑，漏掉规律选择、方向判断和适用条件。现按实际求助原话分组，记录轮次和次数，提供分别对应的行动；求助证据不当作作答错误或掌握证据。

额外修复：裸选项、‘应该选C’及‘选C，因为……’等明确作答漏识别；待核验标签重复；已缓存v2报告无法显示新版分析。旧报告升级一次，原报告完整留档。答案改正后不抹去首次错误，答对选项不自动消除未核验的推理求助。UI结构与样式不变。

验证结果：原760项测试、报告相关59项测试全部通过；835题报告接口回归及样式审计通过。实际网页发送三类求助，报告分别呈现3条具体卡点。使用离线规则桩与临时文件存储，未调用付费模型；没有验证云端部署或真实模型的物理理解质量，没有更改用户原始会话记录或上传GitHub。
