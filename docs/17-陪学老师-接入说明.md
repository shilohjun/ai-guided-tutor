## 怎么自己验

```bash
node scripts/build-persona-docs.mjs --check   # 文稿与生成物是否同步
npm test                                      # 340 个用例 + UI 规范审计
npm start                                     # 然后开 http://127.0.0.1:5173/?p=2
```

`?p=2` / `?p=3` 是逐页深链。它以前只定义没调用（点了也不落页），这次顺手修好了。

真模型那条路已经实测过四位老师同一句输入的口径差异：派蒙「唔，没思路的时候，派蒙陪你先把题目拆开看……呀？」、
诸葛「小友莫急。此题所给，无非导轨间距、……你先说说，这回路里哪一部分是电源」——
风格是按 `01`–`04` 来的，不是套壳改名。

## 头像取景：最后是重裁素材解决的

建华的头像一开始偏左。中间试过两轮 CSS 位移，都只能"看起来差不多"，最后发现 CSS 这条路本身走不通：

- **平移**（`--fx:34%`）能把鼻梁推到圆心，但素材content 本来就画在左边，
  往右一推，**右边就没有像素补上**了 —— 圆形右弧空出一条底色，比原来更难看。
- **放大**能补上缺口，但要让平移后的画面重新铺满圆，缩放得 ≥3.1×
  （脸在 256 画面里只占从 x=0.16 起），头顶会被切掉。绕不开。

所以正解在素材层：`characters/body/jianhua.png` 是 480×720 的原始立绘，分辨率比 256 的头像高得多，
从那里按脸居中重裁一张方图（裁窗 x 219–359、y 18–158，正好把左侧那块蓝色板书裁掉），
再缩到 256。现在 `profile/jianhua.png` 本身就是居中的，CSS 里不再有任何 per-persona 位移。

判据也换了三轮，记下来免得再走弯：**不透明包围盒**（被画框外的手臂钉在 x=0）→ 23%；
**肤色重心**（把脖子和手算进去）→ 30%；**鼻梁落到圆心**（画中心十字线逐档比对）→ 34%。
三个数都指向"要往右推"，但真正的结论是"这张图不该这么裁"。

其余三位目前的构图可以直接用（赫敏偏右约 11%、诸葛偏左约 9%，24px 下都在 2px 以内）。
要一起整齐，跑同一个裁窗逻辑重裁即可。

## 已知待调（这次没做）

1. **赫敏与建华教授的口吻偏弱**。两人的文稿最长（11k / 9.5k 字），L0 澄清轮容易退化成
   "先把题目拆成三块"这类通用句式。已经在提示词末尾加了「口吻锚点」（`quote` + `voiceSample`），
   但还不足以压住长文稿的稀释。要调的话优先改 `02`/`04` 文稿的开头，或在锚点里多放两句。
2. **离线桩的正文没按新规范重写**。`createOfflineAdapter` 的 L0–L3 文案里仍带"把题干条件列一遍"
   这类指派动作；现在只在可见投影层套了老师的口气（`stylePersonaReply`），没有重写正文。
   本地 `.env` 有真 Key，所以走不到这条路；要在无 Key 演示时也合规，得把
   yangchen 的 `src/core/skill-dialog.js` 一并移植过来 —— 那是另一件事。
3. **开屏页、立绘大卡、`public/entrance-page.jpg` 都没接**（按需求排除）。

## 与 yangchen 分支的差异

同一个提交 `1e2aee2` 里还捆着读题定位口径（`OBSERVE_SYSTEM_PROMPT` 的
`candidateStepIndex`）、`buildDraftUserPrompt` 的路径顺序刻画、以及离线对话 skill 的重写。
这些没有一起接：main 已经在那几个文件上走了 50+ 个提交，整块搬会回退题库与 LaTeX 的修复。
需要的话应该单独做一个分支，逐条比对再移植。
