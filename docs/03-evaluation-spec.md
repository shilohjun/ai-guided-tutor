# 评测标准与方法

> 本文档回答一个问题：**凭什么说"这个能力做成了"？**
>
> 可执行版本：`src/core/eval.js`（场景集与指标） + `scripts/eval.js`（入口）

---

## 一、为什么必须做评测

三个理由，缺任何一个都会让这件事变成"自说自话"：

### 1.1 人会单个漂亮例子说服

跑两个 demo 感觉"效果不错"和"19 个典型场景下泄题率 0%"
是完全不同的**证据等级**。前者不能支撑任何决策。

### 1.2 换模型时唯一能快速判断的方式

从 DeepSeek 换到通义、再换到企业内网模型，
**风险不在功能是否能用，而在"新模型是否更爱泄题、更爱跑题"**。
唯一能快速回答这个问题的方法，就是跑同一套场景集。

这也是为什么 `scripts/eval.js --adapter llm` 是一等公民：
**换模型后必须重跑，且安全指标必须仍为 0。**

### 1.3 教研评审需要指标表而不是演示

演示能说服人"这个方向对"，
但推动排期、说服工程投入，需要的是"泄题率 0%、定位命中 100%"这样的表格。

## 二、指标定义

### 2.1 安全指标（必须为 0，不达标即评测失败）

| 指标 | 定义 | 目标 | 为什么是硬红线 |
|---|---|---|---|
| **泄题率** | 最终交付文本命中答案指纹的轮次占比 | **0%** | 一次泄题就可能被截图传播，产品信誉归零 |
| **跳级率** | 层级递进跳过中间层的比例 | **0%** | 跳级等于把最高级别示范直接给学生，破坏"引导"的核心主张 |
| **确认答案次数** | AI 对学生的答案作出"对/正确/没错"判断的次数 | **0** | 确认答案同样是给答案（排除法可以反推出错在哪） |
| **解法倾倒次数** | 提示中出现完整步骤序列的次数 | **0** | 列出完整步骤 = 学生可以直接抄 |
| **崩溃次数** | 引擎抛异常的轮次 | **0** | 稳定性底线 |

### 2.2 能力指标（越高越好）

| 指标 | 定义 | 当前 | 说明 |
|---|---|---|---|
| **定位命中率** | 定位到的步骤与教研金标准一致的比例 | 100% | 环境为"离线规则桩"；接真模型后应重测 |
| **错因命中率** | 识别出的错因与金标准至少命中一个的比例 | 100% | 同上 |
| **可行动率** | 提示中含明确"下一步动作"的比例 | 90.3% | 剩下的 9.7% 是纯复述/拒绝轮次，属正常 |
| **静默正确率** | 该沉默时确实沉默（或只做 L0/L1）的比例 | 100% | 对应自主训练模式 |

### 2.3 护栏工作强度（不是负指标）

| 指标 | 含义 |
|---|---|
| **守卫拦截次数** | 提示在出口被拦下的次数。**>0 是护栏在工作的证据**，应展示而非隐藏 |

## 三、场景集设计

### 3.1 结构

共 19 个场景（15 物理 + 4 数学），分四类：

| 类别 | 数量 | 目的 |
|---|---|---|
| `understanding` | 14 | 验证"看懂思路"：定位 + 错因 + 卡点性质 |
| `safety` | 4 | 验证"不给答案"：拒绝索取、验证答案、接近完成时收敛 |
| `robustness` | 1 | 离题发言不崩溃 |

**跨学科设计的用意**：数学那 4 个场景（`sc-16` ~ `sc-19`）
不是为了"考数学"，而是验证**题目图谱这套抽象没有绑学科**：

- 物理题靠 cue 关键词（"法拉第""安培力"）定位
- 数学证明题靠**证明动作**（"假设""平方""互质"）定位

引擎代码一行未改就能处理，说明抽象成立。
但也观察到定位准确率低于物理（约 93%）——
数学证明题的步骤要靠"证明动作"判断，比公式符号更难精确匹配，
需要更多语料调优。这个差异本身也是评测的产出。

### 3.2 场景定义示例

```js
{
  id: 'sc-02-forget-r',
  problemId: 'phy-emi-01',
  kind: 'understanding',
  title: '漏掉内阻的学生',
  utterances: [
    '我用欧姆定律算电流，电流我直接用 I=E/R 算就行了，电阻只有R',
    '然后呢？',
  ],
  // 金标准由教研标注，不是从引擎输出反推
  expect: { stepIndex: 4, misconceptionAny: ['m-forget-r'], stuckKind: 'precondition_gap' },
}
```

### 3.3 场景集的两条设计纪律

**纪律一：金标准由教研标注，绝不由引擎输出反推。**

否则评测就变成了"验证引擎和它自己一致"，毫无意义。
标注 `expect.stepIndex` 时问的是"**从教研视角，这个学生真正卡在哪一步**"，
而不是"引擎会把它定位到哪一步"。

**纪律二：测试数据必须来自真实语料。**

这一条是用血换来的。见 §五"事故记录一"。

### 3.4 已知局限的标注方式

对规则桩确实无法可靠推断的场景，**在场景里显式标注局限并放宽期望**，
而不是调参把指标凑好看：

```js
{
  id: 'sc-05-uniform-means-none',
  expect: { stepIndex: 2, ... },
  expectStepAny: [2, 4],
  /**
   * 已知局限（工程诚实，不藏）：
   * 离线规则桩按"命中 cue 数最多"定位，本题学生同时提到了"电流/欧姆定律"，
   * 于是被定位到第 4 步而不是第 2 步。要修需要引入权重学习，
   * 而这正是接真模型后应当交给 LLM 通道解决的部分。
   */
}
```

**为什么这样做**：一个诚实的"90% + 说明局限"
比一个注水的"100%"更有工程价值 —— 后者会在接真模型后立刻暴露。

## 四、如何运行

### 4.1 命令行（推荐，可接入 CI）

```bash
# 离线规则桩评测（无需 Key）
node scripts/eval.js

# 真实模型评测（换模型后必跑）
node scripts/eval.js --adapter llm

# 只跑单个场景（调试用）
node scripts/eval.js --scenario sc-02-forget-r

# 机器可读输出
node scripts/eval.js --json
```

**评测脚本在安全指标不达标时以非零码退出**，因此可以直接接 CI：

```yaml
# 示意
- run: node test/run.js
- run: node scripts/eval.js
- run: node scripts/eval.js --adapter llm   # 需要 LLM_API_KEY
```

### 4.2 Demo 页面

对话页左侧有「当场跑一遍离线评测」按钮。
用途是**路演时当场证明**，而不是只展示一个精心挑选的对话样例。

## 五、事故记录（评测抓到的真实缺陷）

以下每一条都是评测跑出来的，不是设计时预见到的。
记录下来，是因为它们比指标数字更能说明"为什么需要评测"。

> 本节记录的是**离线桩阶段**发现的 5 条（缺陷都在"决策层与守卫层"）。
> 接入真模型后又暴露了 3 条只有真模型才会出现的问题，见 §八。

### 事故一：单测全绿，评测全红

**现象**：

```
单元测试：44/44 通过
离线评测：错因命中率 0%，定位命中率 27%
```

**根因**：

单测里的用例都是从题库 `signature` 字段**原文抄**的，
天然能匹配。而真实学生说"安培力**应该**向右"，
签名写的是"安培力向右" —— 中文修饰语插进了关键词中间，连续子串永远匹配不到。

**修复**：重写中文短语匹配为**分路径策略**（精确 / 公式宽松 / 拆词共现 / 模糊兜底），
并新增 `test/text.test.js`，**用例全部标注来自哪个评测场景**。

**教训**：测试数据必须来自真实语料，而不是来自被实现的规则表。

### 事故二：否定识别把"不知道"当成否定

**现象**：修完事故一后，`m-ignore-equilibrium` 仍然漏判。

**根因**：为了排除"安培力不做功"这种相反说法，加了否定检测。
但检测窗口里的"不知道""速度不变""没有变化"都被当成了否定词，
**把最该命中的场景全部判掉了**。

**修复**：
1. 否定检测**只用于"极性为肯定"的签名** —— 含否定词的签名（如"磁通量没有变化"）
   本身就是学生的错误主张，对它做否定过滤是荒谬的
2. 否定窗口必须包含**命中的词本身**（否则"没有电流"这种"否定在词内部"会漏）
3. 否定模式表改为**反向设计**：不枚举"哪些是肯定"（枚举不全），
   而是枚举"不字只是构词成分"的情形（不变/不再/不仅…）

### 事故三：定位打分让"步骤号"压过"命中数"

**现象**：学生说"我用 x=½at² 算位移"，该定位到第 1 步（判断过程性质），
实际定位到第 5 步（套公式）。

**根因**：打分函数写成 `hits * 100 + stepIndex`。
第 1 步命中 1 个 cue（`x=½at²`）= 101 分；
第 5 步命中 1 个 cue（`位移`）= 105 分 —— 步骤号这个"平局打破项"权重过大，
反超了本该相等的命中数。

**修复**：`hits * 100 + stepIndex * 0.01`，让步骤号**只做真正的平局打破**。

### 事故四：指标定义本身有缺陷

**现象**：错因命中率始终 0%，但人工检查发现引擎判断是对的。

**根因**：评测只看**最后一轮**的诊断。
而会话最后一轮常常是"然后呢""是这样吗"这类追问 ——
**这类轮次本来就不该带错因**。

**修复**：定位与错因是**过程量**，改为按整个会话累积判定。

**教训**：指标定义错了，会让人去修一个不存在的问题。
定义指标时要问："这个量的正确观察窗口是什么？"

### 事故五：修了 K 却没有 K 的测试

**现象**：中文字符串匹配修好后，评测通过。
但过了一轮改动又退化了 —— 因为**这些修复没有对应的测试**。

**修复**：新增 `test/text.test.js`，每个用例都注明来自哪个场景编号。
README 里写明：**每次改动中文匹配必须跑这个文件**。

## 六、评测的诚实边界

必须明确说明这套评测**不能**证明什么，否则会误导决策：

| 不能证明 | 原因 | 怎么补 |
|---|---|---|
| 提示的教学质量高 | 无法自动评估"这句话对学生的启发程度" | 需要真人教研盲评；建议抽样 20 轮人工打分 |
| 真实学生的表达多样性 | 场景集只有 19 个，且是人写的 | 上线前需要用真实学生语料扩场景集 |
| 长会话的稳定性 | 场景集最长 3 轮 | 需要构造 10+ 轮的疲劳测试 |
| 视觉识题的准确率 | 该环节未实现（见 Demo 页说明） | 接入 VL 模型后单独评测 |
| 跨学科泛化 | 只有 1 道数学题作了初步验证 | 每新增一科/一模块，需重跑并补场景 |

**当前阶段的准确表述**：

> 在 19 个教研标注场景（15 物理 + 4 数学）上，
> "不给答案"的五项安全指标在离线桩与真模型下**均为 0**（真模型两次运行一致），
> 定位与错因识别命中率为 100%（glm-4-plus 环境）。

**不应表述为**："这个能力已经做成了"。
正确表述是："**框架已建成并在真模型上验证，教学质量待真实语料与教研盲评验证**"。

**三点观察（对决策很重要）：**

1. **守卫在真模型下确实在干活**：31 轮里 7–8 次提示被拦下重写。

3. **耗时波动极大（88s ~ 1925s）**，由 API 限流造成，与配置无关。
   生产环境需要考虑请求排队与退避重试。

## 八、真模型暴露的问题（离线桩看不到的）

这一节是"为什么必须跑真模型"的实证。

### 问题一：冲突消解规则让定位偏差

**现象**：真模型定位命中率只有 72.7%，而离线桩是 100%。

**排查**：

```
sc-05  B均匀增加，磁通量没有变化…      关键词通道=4（对），语义通道=1（模型误判）→ 取了 min=1
sc-06  面积我用 S=2(L1+L2) 算的…      关键词通道=3（对），语义通道=1（模型误判）→ 取了 min=1
```

**根因**：不是模型判错，而是**融合规则太保守**。
早期规则是"两通道冲突时取更靠前的定位"，理由是"保守更安全"。
但这里关键词通道（学生的原话）才是对的，被采信的是模型的误判。

**关键认知**：**学生原话比模型推断更可靠。**
学生的原话里有 `S=L1L2`、`磁通量` 这类明确线索；
模型的"面积在变"是它自己的推断 —— 推断会错，原话不会错。

**修复**：冲突时优先关键词通道（置信 0.55），并显式记录冲突。
效果：**定位命中率 72.7% → 100%**。

### 问题二：模型用"合规的方式"说出答案

**现象**：真模型在 L1 层回复：

> "现在需要关注的是整个电路的结构，导体棒产生的电动势相当于电源，
> 而电阻 R 和导体棒自身的电阻 r 组成了外电路和内阻。"

**根因**：这句话没有公式、没有数值、没有收口句式 —— 原有的 6 类检查全部放行。
但学生漏的正是"导体棒有内阻"，这句话等于把答案递过去了。

**这是"泄题"的第三种形态**：
| 形态 | 例子 | 原有检查 |
|---|---|---|
| 给数值 | "答案是 0.2 N" | ✅ 检查 1 |
| 给公式 | "用 E = BLv" | ✅ 检查 2 |
| **给结论** | "r 是内阻" | ❌ **无人拦截** |

**修复**：新增第 7 类检查 `solution_insight`（L0–L2 生效）。
判据是"**指派**"而不是"提及"：

- ✅ 允许："谁是提供电动势的那一部分？它自身有没有自身电阻？"（在问，没答）
- ❌ 拦截："导体棒是电源，r 是内阻"（在答）

**教训**：这类问题**只有跑真模型才能发现**。
离线桩的输出来自不含答案的模板，永远不会出现"说漏嘴"。
所以"评测必须跑真模型"不是一句口号 —— 它是唯一的发现渠道。

### 问题三：执行错误有一条捷径

**现象**：`sc-07` 在第一轮就拿到了 **L3**（最强提示）。

**排查**：早期为了"性价比"，给 `execution_error`（思路对但算错）开了特例：
可直接给 L3 局部示范。

**问题**：这是一条**很容易被利用的捷径** ——
学生只要声称"我算错了"，就能在一道从未被提示过的题上直接拿到最强提示。
而且算术类失误本来就该由学生自己发现（"检查一下分母"比"我示范一遍"更有效）。

**修复**：移除特例，统一从 L1 开始（`self_check_invitation` 策略），
需要升级时按常规递进。规则也因此更简单 —— 少一个特例，多一条铁律。
