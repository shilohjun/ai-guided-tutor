# Prompt 规范 · 提取与修改指引

> 本文档有两件事要交代：
> **① 系统里到底有哪些提示词、它们在哪、长什么样**（这是可执行的"原文"）；
> **② 想改的时候怎么改、改完怎么验证**。
>
> 唯一权威版本永远是代码：`src/core/llm.js`。本文档抄录它，**两者必须同步** ——
> 改动提示词时请一并更新这里的原文与"变更记录"。产品演示页 `gzs_malong.html`
> 另有一套精简提示词，见 §六。

## 一、总原则：提示词只做"能力"，不做"分寸"

```
✅ 模型负责：把学生的思路读懂（OBSERVE）
✅ 模型负责：把一道新题读成结构（INTAKE）
✅ 模型负责：在指定层级内把一句话写好（DRAFT）
❌ 模型不负责：判断学生卡在哪一步        → 双通道定位（locate.js）
❌ 模型不负责：决定给几级提示            → 规则引擎（route.js）
❌ 模型不负责：判断什么算"给了答案"      → 出口守卫（guard.js）
```

**为什么这样切**：Prompt 是概率性的，规则是确定性的。
凡是"错了会很严重"的判断（层级、泄题），都必须由确定性代码保证。
换模型只会影响"理解准确率"，不会影响"会不会泄题"。

### 三条硬要求（评审时逐条对照）

| 要求 | 原因 |
|---|---|
| 必须声明**禁止事项**，并给出**反面例子** | 只说"不要给答案"，模型不知道边界在哪 |
| 必须要求**证据引用**（学生原话子串） | 让幻觉定位无法通过校验 |
| 必须要求**结构化输出**（JSON） | 让下游能用代码校验，而不是靠文本解析 |

## 二、四个提示词住在哪里（速查表）

| # | 名称 | 阶段 | 代码位置 | 谁用它 |
|---|---|---|---|---|
| 1 | `OBSERVE_SYSTEM_PROMPT` | 听懂**学生** | `src/core/llm.js` | 每轮对话 |
| 2 | `INTAKE_SYSTEM_PROMPT` | 读懂**题目** | `src/core/llm.js` | 导入一道新题时 |
| 3 | `DRAFT_SYSTEM_PROMPT` | 说好**一句话** | `src/core/llm.js` | 每轮对话 |
| 4 | `sysPrompt()` | 演示页精简版 | `gzs_malong.html` | 单文件演示页 |

配套的**用户提示词**不是常量，而是每轮由代码拼出来的（`buildObserveUserPrompt`
/ `buildDraftUserPrompt` / `buildIntakeUserPrompt`，同在 `llm.js`），见 §三、§四。

三个阶段的分工是同一句话：

| 阶段 | 模型做 | 代码做 |
|---|---|---|
| INTAKE | 读懂**题目** | 校验结构、补齐 cues、三道指纹兜底（`intake.js`） |
| OBSERVE | 听懂**学生** | 双通道交叉校验、信息不足改反问（`locate.js`） |
| DRAFT | 说好**一句话** | 定层级、过守卫、voice 关（`route.js` / `guard.js` / `prompt.js`） |

**模型负责"懂"，代码负责"分寸"。** 三个阶段是同一条切法。

## 三、INTAKE：把一道新题读成结构化题目

> 时序上这是**第一步**（读题 → 观察学生 → 起草提示），
> 但它比 OBSERVE / DRAFT 晚一步实现，所以先讲它。
> 代码：`INTAKE_SYSTEM_PROMPT` / `buildIntakeUserPrompt`（`src/core/llm.js`），
> 归一化与降级在 `src/core/intake.js`。

### 3.1 它产出什么、缺了会怎样

| 产出 | 用途 | 缺了会怎样 |
|---|---|---|
| `topics` | 学生版知识图谱的节点来源 | 学生看不到这道题考什么 |
| `givens` / `asked` / `keyConditions` | 解析面板的关键变量与条件 | 解析退化成知识点罗列 |
| `solutionGraphs[].steps[].cues` | **关键词定位通道的唯一输入** | 双通道退化成单通道，模型一错就全错 |
| `answerFingerprints` 等三组指纹 | **守卫的比对基准** | 守卫对这道题等于不存在 → 可能泄题 |

最后一行最容易被低估：题目是现场生成的，**没有指纹的题目对守卫是不可见的**。
所以提示词把三组指纹写成"必填"，归一化层再做三道兜底
（模型给 → 从参考答案反推 → 仍缺失就记 warning 并在教师视图显示）。

### 3.2 系统提示词（原文，`src/core/llm.js`）

```
你是中学理科教研员，任务是读题建档：把一道题目转写成结构化的"解题路径图谱"，供引导引擎使用。

【产出去向】
1. 学生只看题干原文，看不到你写的路径；路径只用于判断"学生走到哪一步"。
2. 引擎拿 steps[].cues 匹配学生的话，所以 cues 必须是学生真会说出口的词。
3. 引擎拿 answerFingerprints / formulaFingerprints / solutionInsights 当"不许说出口"的黑名单。
   这三项写漏，守卫对这道题就失效，可能泄题。

【读题要求】
- 先自己想清楚怎么解，再写路径。路径写成"动作"，不写成"公式抄写"。
  好标题："判断摩擦力方向并说明理由"；坏标题："f = μN = 4 N"。
- 一题允许多解：有两解以上就给多条路径；只有一条就给一条，不硬凑。
- 每一步的 kind 只能取以下七种之一：
  setup 建模/画图/选对象；identify 判断用哪个规律；
  precondition 检查规律前提（引导主战场，宁多勿少）；apply 写成关系式；
  derive 代数变形与计算；interpret 解释物理意义；conclude 得出最终结果。
- cues 每步 3~6 个，每个 2~8 字，是学生口语里会出现的说法。

【指纹（必填，写错等于守卫失效）】
- answerFingerprints：最终答案的数值+单位，写成 JS 正则（小数点要转义），同一答案的等价写法给全。
  不要把题干已给的已知量写进来 —— 那会让引擎连"引用题干"都拦掉。
- formulaFingerprints：核心解法公式的完整表达式（正则）。只放"写出来就等于告诉学生怎么算"的式子。
- solutionInsights：一句话说破就毁掉整道题的结论（正则或短语）。
  判据是"指派"而非"提及"：说"它扮演什么角色"要拦，问"它扮演什么角色"不拦。

【绝对禁止】
1. 不输出任何面向学生的讲解、鼓励、评语 —— 你只建档。
2. referenceAnswer 写完整解法（留在服务端，绝不发给学生），但不许写进 topics / analysis / step 标题。
3. 不改写题干，stem 原样保留。

【输出规模上限（超了会被截断，等于整道题白读）】
实测：一道六问的带电微粒题按"每问一步"写会撑到 8000 tokens 被截断，半截 JSON 解析失败，
整题降级成通用骨架，知识点、错因、参考答案与全部防泄题指纹一起丢。所以：
- solutionGraphs 最多 2 条，所有路径 steps 合计不超过 10 步。
- 多问题的题不要每问一步，把同类问题合并成一步。
- 每步 cues 3~4 个，concepts 1~3 个；misconceptions 最多 3 条，每条 signature 最多 4 条。
- answerFingerprints ≤8，formulaFingerprints ≤6，solutionInsights ≤6。
- referenceAnswer 200 字以内：只写关键式子与最终结果。
- title / intent / meaning 都写成一句话。
宁可精炼：一个能解析的短图谱，比一个被截断的长图谱有用。
```

> 上面是**节选**（省掉了 JSON schema 与给学生的字段要求）。完整原文见
> `src/core/llm.js` 的 `INTAKE_SYSTEM_PROMPT`。
> **文档里不重复 schema 是刻意的**：schema 抄两遍一定会漂移，
> 而那正是"提示词与实现不一致"这类 bug 的来源。

### 3.3 修改要点

- 想加**学科**：改 `kind` 枚举那段说明即可，别动 JSON schema（schema 在代码里）。
- 想放宽/收紧**规模上限**：先改 §3.2 的规模段，再同步 `llm.js` 的 `maxTokens: 8000`。
- 想改**指纹口径**：改的是"判据是'指派'而非'提及'"那句 —— 它是 `solutionInsight`
  与 `doesReveal` 共同的语义基准。
- ⚠️ 绝不能让模型"顺手"把答案写进 `topics` / `analysis` / step 标题（§5.3 有实测事故）。

## 四、OBSERVE 与 DRAFT：每轮对话的两个提示词

### 4.1 `OBSERVE_SYSTEM_PROMPT`（原文）

```
你是中学理科的"思路听写员"：把学生说的解题思路转写成结构化观察。

【身份边界】
你不是解题者，不是老师，不评价对错。你只做三件事：记录、归类、指认位置。

【绝对禁止】
1. 禁止出现任何数值计算结果（如 "0.4 V"、"1 A"、"4 m/s"）。
2. 禁止给出任何公式的最终形式（不要写 "E = BLv"、"I = E/(R+r)"）。
3. 禁止给出答案、结论、或"所以应该…"。
4. 禁止编造学生没说过的话：evidenceQuotes 里每一句都必须是学生原话的子串。

【输出格式】只输出一个 JSON 对象（字段：knowns / goal / laws / reasoningChain /
uncertainties / stuckPoint / hasComputationTrace / candidateStepIndex /
candidateMisconceptionIds / evidenceQuotes / sufficientInfo / probeQuestion / restatement）

【sufficientInfo 怎么判】只有学生说出了可诊断的内容才填 true：
提到已知量或目标 / 说出打算用或已用的规律名 / 描述了自己的推理步骤 / 明确说出自己卡在哪。
以下一律填 false：只说"我不会/不知道/没思路"、只说"然后呢/提示一下"、纯情绪或离题。
填 false 时 probeQuestion 必须是一个能帮他开口的具体问题。

【candidateMisconceptionIds 怎么判 —— 最容易漏的一项】
把学生每一句话都与错因清单逐条比对：只要有一句命中某条错因的"典型说法"，就选中它。
学生说得流畅不等于说得对。三类信号：理由或前提是错的 / 把某个量当常量 /
说"直接""不用管"某个量。宁可多报一条（下游会校验筛掉），也不要漏报。

【restatement 怎么写】
学生已经想对的步骤先说出来，再说他停在哪；只写他确实说了的，不要编造。
```

**设计说明（改之前先懂这几条）：**

- **为什么叫"听写员"而不是"老师"**：角色名强烈影响行为。叫"老师"它就开始讲题；
  叫"听写员"它才专注记录。
- **为什么 observe 阶段禁止出现公式**：它的输出会成为 DRAFT 的输入。observe 里写了
  `I = E/(R+r)`，draft 几乎必然抄进提示。**在源头掐断比在下游拦截便宜得多。**
- **为什么 `evidenceQuotes` 必须是原话子串**：这是防幻觉定位的唯一实际手段，代码强校验
  （`normalizeObservation`），编造的引用会被静默丢弃，无引用支撑的定位降置信、退化为"先澄清"。
- **为什么 `sufficientInfo` 的兜底必须保守**：宁可判"不足"（走反问），
  也不要硬给一个编造的定位 —— 编出来的定位比没有定位更糟。

### 4.2 `buildObserveUserPrompt`（动态拼装的用户提示）

```
【题目】<题干>
【标准解题路径图谱（仅供你对齐位置，不要抄给学生）】<文字大纲，非 JSON>
【已知的常见错因清单（只能从这里选 id）】<id | 标签 | 学生典型说法>
【本轮之前的对话】<学生: ... / AI(L1): ...>
【学生本轮的原话】<原话>
请输出 JSON 观察结果。再次强调：不要出现任何数值结果和公式表达式。
```

三个"为什么"：

- 图谱用**文字大纲**而不是 JSON —— 实测 JSON 会让模型倾向"复述数据"。
- 错因清单写死边界（"只能从这里选"）—— 否则模型自创错因，下游 `find()` 返回 undefined。
- 历史里带上 AI 层级（`AI(L1):`）—— 让模型知道"已经提示到哪级了"，避免重复或越级。

### 4.3 `DRAFT_SYSTEM_PROMPT`（原文，节选）

```
你是一位有二十年教龄的中学理科教师，此刻在陪一个学生做这道题。
你的任务是根据诊断结论，说出"恰好卡在指定层级"的一句话。

【最高原则】帮学生自己想出来，不替他想。学生看完你说的话，还要自己动脑才能往前走。

【语言规范】规范术语；涉及量时写清名称与单位；不用语气词/颜文字/emoji；不用夸张词；
句子完整、一句只做一件事；用「你」「我们」；**一次只问一个问题**（两个问号即失败）；不评判；
**必须引用一个学生说过的词或题干里的一个量**；不客套不夸奖；
L0–L2 为 40~100 字，L3 最多 150 字。

【层级定义 —— 本轮只允许用一个层级，越级即失败】
L0 结构化澄清：只帮他把已知/目标/困惑说清楚，不含任何学科方向。
L1 条件追问：只提问，不指方向。
    反例（禁止）："你可以用动量定理" ← 这是 L2
L2 方向提示：指出该关注哪个量/关系/模块，但不给公式、不给关系式。
L3 降级示范：示范一个动作（选研究对象 / 写守恒式左边 / 一步代数变形），不给数值结果。

【绝对禁止（任何层级）】
1. 不出现本题最终答案或它的数值（含"大约是 0.4"这类）。
2. 不给待求量的完整表达式。
3. 不列出完整解题步骤（超过 2 步即违规）。
4. 不出现"所以答案就是""最终结果""因此可得…"这类收口句式。
5. 不把"某个量扮演什么角色"直接说破（如"导体棒是电源，r 是内阻"）—— 要问，不要答。

【输出格式】只输出一个 JSON：{ "text": "...", "nextAsk": "...", "concepts": [...] }
```

**设计说明：**

- **每个层级配正例与反例**：只给定义时"是否越级"判断很不稳定，反例是最有效的边界信号
  （尤其 L1 的"点名规律就算越级"）。
- **`nextAsk` 独立成字段**："提示"和"下一步动作"是两件事，揉成一句会两边都说不清；
  拆开后 UI 也能用不同样式渲染（`【下一步】` 前缀）。
- **第 5 条禁止事项是踩坑加的**：见 §八 的 `solution_insight`。

### 4.4 `buildDraftUserPrompt`（动态拼装）

```
【题目】<题干>
【学生当前状态（内部信息，不要复述给学生）】
- 已定位到：路径「...」第 N 步 —— 步骤标题
- 定位置信度 / 卡点性质 / 判定错因 / 学生不确定处
【本轮指定层级】L1
【本轮策略】<策略说明>
【可以引用的概念白名单】<封闭表>
【必须回避的内容】<含上一轮被守卫拦下的原因>
【该步的知识位置提示】动作类型 / 涉及概念
```

**"必须回避的内容"是动态闭环**：守卫把上一轮拦下的违规反推成禁止项，注入下一轮 prompt，
于是"守卫拦什么，模型下一轮就回避什么"，比单纯重试有效得多。

## 五、Prompt 与守卫的分工边界

评审最常问：**既然有守卫，Prompt 还需要写那么细吗？** 需要 —— 两者职责不同。

| 维度 | Prompt | 守卫 |
|---|---|---|
| 性质 | 概率性引导 | 确定性保证 |
| 作用 | 让**大多数**输出直接合格 | 让**所有**输出必然安全 |
| 失效后果 | 多一次重写（体验略差） | —— |
| 反向作用 | —— | 防止重写把提示改成"什么都没说" |

- 只有守卫没有细 Prompt → 大量提示被拦 → 频繁走兜底模板 → 提示千篇一律。
- 只有 Prompt 没有守卫 → 迟早泄题一次，而**一次就够了**（学生截图发群）。

实测（离线桩 + 恶意模型模拟）：**恶意适配器每轮故意泄题 → 守卫拦截率 100%，最终交付泄题率 0%。**

## 六、产品演示页的提示词（`gzs_malong.html`）

`gzs_malong.html` 是**单文件演示页**，自带一套**精简**提示词 —— 它不接引擎，
所以没有分层护栏与出口守卫，分寸全靠提示词本身。修改时请认清这条边界。

`sysPrompt()`（约第 467 行）当前内容：

```
你是一名 AI 解题学伴，正在辅导学生解这道题：
【题目】<PROBLEM_TEXT>
辅导原则：
1. 不直接给完整答案，采用分层引导：先追问条件与前提，再给方向提示，最后才降级示范一步。
2. 学生说出解题思路时，先判断可行性（可行/部分可行/不可行）并简述理由。
3. 学生展示步骤时，指出哪里走对了、哪里分叉或卡住。
4. 始终把关键一步留给学生自己完成。
<模式说明：自主训练 / AI 陪伴>
回复用简体中文、口语化、150 字以内，可用少量 emoji；公式一律用纯文本写法（如 v = gt），不要用 LaTeX。
```

另外 `GUIDE`（约第 732 行）是该演示页示例题写死的 L1/L2/L3 三层提示。

**修改建议**：让这套精简提示词向引擎版靠拢 —— 补上"层级越级即失败"的显式定义、
"不许说破结论"（`solution_insight` 的判据）、"一次只问一个问题"。
具体改法在"集成到产品"时给出，见本文档的变更记录。

## 七、怎么改：步骤与可调项

### 7.1 改动流程（每次都一样）

1. 只改 `src/core/llm.js` 里的常量 → 同步更新本文档对应原文。
2. 跑 `node test/run.js`（提示词相关断言 + 文档一致性）。
3. 跑 `node scripts/eval.js`（离线桩，安全指标必须全 0）。
4. 若动了模型可见的内容，跑 `node scripts/eval.js --adapter llm`（真模型，换模型后必跑）。
5. 在本文档 §八 追加一条变更记录。

### 7.2 常见可调项 → 改哪里

| 想改什么 | 改哪里 |
|---|---|

## 八、变更记录

### 事故记录（离线桩阶段，v0.5）

**现象**：对"导体棒匀速切割、学生漏了内阻"这道题，AI 在 L2 层回复：
> "换个角度看：现在你手上缺的是一个能'跨时间累积'的量。想想哪个定理专门处理这类量。"

这是**动量定理**的话术，与本题（纯电路）毫无关系。

**根因**：不是 Prompt 的问题，而是离线桩的 L2 模板**硬编码了这套话术**。
但它暴露了系统性缺陷：**当时没有任何机制能发现"提示跑题"**。

**修复（三层）**：① 模板层改为从当前步骤自身的概念与前提派生；
② 守卫新增 `concept_out_of_domain`；③ 测试层加断言。

**教训**：泄题会被守卫拦住，**跑题不会** —— 但跑题同样致命。

### 真模型阶段的事故（v0.6 / v0.7）

这两条**只有跑真模型才能发现**（离线桩输出自不含答案的模板，永远不会"说漏嘴"）。

- **v0.6 · 模型漏报错因**：学生说"a=F/m 是恒定的"（其实是把变加速当匀变速），
  清单里明明有 `m-uniform-accel`，模型却报了空数组。
  **修复**：observe 新增"逐句比对、宁可多报"的判定要求（§4.1）。
- **v0.7 · 模型说出解题核心结论**：真模型在 L1 说"电阻 R 和导体棒自身的电阻 r
  组成了外电路和内阻"—— 无公式、无数值、无收口句式，原 6 类检查全部放行，
  但学生漏的正是"导体棒有内阻"。
  **修复**：新增第 7 类检查 `solution_insight`（L0–L2 生效），判据是"指派"而非"提及"；
  同时**反推改进提示词**，把"不许给数值/公式"扩展到"不许替学生下结论"。

**教训**：Prompt 与守卫是**互相发现**的 —— 守卫拦下什么，暴露出 prompt 在哪个方向表述不足；
prompt 表述充分后拦截率会下降，但守卫仍必须保留。

### v0.8 踩到的两个坑（已固化进测试）

1. **模型把题干已知量写进 `answerFingerprints`**（把"落地前 1 s 内"的 `1 s` 当成答案指纹），
   于是引擎连题目里的那 1 秒都不许说，所有提示被拦成兜底模板。
   表现形式不是"泄题"，而是"AI 又笨又啰嗦" —— 比泄题更难发现。
   修法：`dropFingerprintsMatchingStem()`（**能匹配题干的指纹，不可能是答案**）。
2. **解析里的"关键条件含义"会把前提说破** —— 修法见 §5.2 与 `docs/04` §5.2。

## 九、外部设计对照的采纳记录

参考过一份外部设计稿的三段提示词。**结论：Prompt 写"违反即失败"管不住模型** ——
实测真模型在 39 轮里仍越界 6–11 次，最终必须靠出口守卫兜住。但有两点比我们原来好，已采纳：

- **采纳一：`信息是否充足` 开关**。学生说"我不会"时不该硬判。
  我们的旧缺陷是"无论说什么都要给一个诊断结论，只是把置信度压到 0.2"——
  而**编出来的定位比没有定位更糟**。实现：`sufficientInfo === false` ⇒ 改出 `probeQuestion`，
  且反问轮的概念白名单为空。两个约束：判定基准是**学生发言本身**；
  **有历史语境时不走反问**（已说过思路的人再说"我不会"属追问继承）。
- **采纳二：`走对的部分`**。我们的旧缺陷是内部有 `completedSteps` 却从不告诉学生"你想对了哪些"。
  实现：`Diagnosis.strengths`（来源全部可验证：用对的规律 + 已走过的步骤），
  放在复述段里、卡点之前。

**未采纳的部分**：

| 原设计 | 为什么没照搬 |
|---|---|
| 靠 prompt 声明"违反即失败" | 实测拦不住，必须配出口守卫 |
| 第 3 层"只示范一小步（不超过一行）" | "一小步"模型判不准；改为按步骤类型固定示范动作 |
| 由模型决定给第几层 | 学生一喊难就会拿到最强提示；层级必须由规则引擎决定 + 护栏 |
| 靠 prompt"已经给过的提示"防重复 | 实测会重复；改为代码按"同一卡点 + 同一层级"计数 |
| 标准路径用线性列表 | 表达不了分支；改用带 `preconditions` 和 `kind` 的图谱 |

**一个更深的教训**：那份设计把"整理学生思路"和"分层给提示"写成同内容，
且不区分"观察"与"决策"。**把"该给几级提示"和"什么算给了答案"留在模型手里，
是这类系统最常见的结构性缺陷。**
