# 题库解析编译成关键点链（落地记录）

日期：2026-11-11　分支：`feat/pilot-platform`

## 1. 修的是什么

题库 835 道真题，每道都有官方答案与解析，但产品里这两样东西只用了一次：
`src/core/report-review.js:77` 把解析渲染成报告页的复盘卡。
真正辅导学生的路径（`src/core/qbank.js` → `heuristicSkeleton`）用的是**通用六步骨架**——
「读清条件与目标 / 判断该用哪个规律 / 核对规律成立的前提 / 写出关系式 / 代入数据 / 得出结论」。
代码自己也不装，硬编码了 `graphQuality:'source-tags-with-generic-tutoring-skeleton'`。

后果是：一道题真正难在哪、有几个坎、先判断什么后判断什么，全被抹平了。
学生被"定位"到第 3 步「核对规律成立的前提」时，这句话对任何一道题都成立，也就等于没说。

## 2. 做法

解析当**结构源**，不当**内容源**：不把解析原文喂给学生，只用它决定
「这道题有几关、每关要作出什么判断、依据是什么」。

- `src/core/keysteps-prompt.js`：三套提示词（计算 / 选择 / 实验）。
  计算题问推导链上的判断，选择题问主链 + 干扰项归因，实验题问操作规范 / 数据处理 / 误差来源。
  第一版一套通吃时，实验题被抽成"判断选项 A/B/C"——那是答题动作，不是思维关卡。
- `scripts/build-qbank-keysteps.mjs`：离线批量编译，JSONL 断点续跑，失败把错误写回提示重试一次。
- `scripts/build-keysteps-data.mjs`：校验 + 生成 `src/core/qbank-keysteps.data.js`（server-only，不进前端）。
- `src/core/keysteps.js`：`normalizeKeysteps` 做 schema 校验，`keystepsToGraphs` 转成引擎认识的
  `{index,title,kind,intent,concepts,cues,forks}` 步骤；末步非收尾时自动补一步 `conclude`
  （route 与 report 依赖"最后一步是收尾"这个不变量）。

## 4. 接到哪儿

- `src/core/qbank.js`：有编译结果就 `solutionGraphs = keystepsToGraphs(...)`、
  `graphQuality:'source-analysis-keypoints'`；没有才退回骨架。`summary` 也换成章节·叶节点 + 题干首句。
- `src/core/llm.js:163` `buildDraftUserPrompt`：起草提示里多两行
  「这一步要作出的判断」「判断依据」，并明确写"依据只用来决定该点出哪一个理由，
  不要把依据里的完整算式或结论抄给学生"。
- `src/core/similarity.js` + `src/core/report-practice.js`：
  报告页的"巩固这一知识点"改成先按**关键点重合度**排序，理由里点明共用的是哪个判断：
  「题库知识标签：卫星与变轨。这道题同样要作出「椭圆轨道半长轴」这个判断。」
  方法桶只排序、不改理由——那里要学生练的是"这一招"，塞一个不相干的判断进去反而糊。

## 5. 证据

同题对照（`YN-2026-13`，5 个关键点，真模型三轮）：

- 骨架版：第 3 步「核对规律成立的前提」→ "圆周运动这个方向是对的，半径是不是 R 得由 S、P 和速度方向一起定"
- 关键点版：定位到「由几何关系求轨迹半径」→ "轨迹圆过 S 和 P，圆心在弦 SP 的中垂线上；
  S 到 O 是 0.8R，P 在圆面最高点，半径就能用勾股关系表示"

回归口径：`npm test` 801/801、`.test.mjs` 54 条全绿、UI 规范审计通过；
`npm run eval` 19 场景逐条通过，**泄题率 0%**（安全指标一票否决）。

## 6. 坑（都写进了代码注释）

- `stemText` / `analysisText` 里的公式是 `〔式〕` 占位，真公式只在 base64 图里。
  关键点因此只依赖文字结构、不依赖数值——这是可接受的取舍，但"判断依据"里模型会自己补公式，要能容忍。
- 模型会自造 key 名（`关键点链` 而非 `keysteps`），解析器认一组别名并递归找数组。
- cue 去标点把小数点一起删了："0.02 秒"变"002 秒"，定位永远匹配不上。
  `src/core/intake.js` 的 `stripCuePunct` 改成只删非数字之间的点。
- "下列操作正确的是"里每个选项讲一个不同实验时，模型会为每个选项单列一关（`BJ-2026-15` 五关里三关是选项）。
  提示词补了一条：这是**一道坎**，压成"逐条检查每项说法是否满足它自己的前提"，把最容易错的那条写进依据。

## 7. 没做的

- 检索层（RAG）本身：设计稿在 `docs/superpowers/specs/2026-11-11-qbank-rag-design.md`，
  被这件事前置了——现在相似度用的是结构化关键点，不是向量。
- 分小问的题（约 30% 含「(1)(2)」）仍是一条链，没有拆成多张图。
  引擎允许最多 3 张图，真要拆是下一步的事。
- 「结论整理」这类收尾型关键点算不算一道坎，还没定论。
