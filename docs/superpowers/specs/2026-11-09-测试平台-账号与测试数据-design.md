## 0. 一句话

给这个项目建一个**能长期开着、给真实高中生用、测完能拿出数字**的试用站：一人一个测试账号，会话不随实例消失，四页路上的进/退/停/弃被记下来，每一道题都能导出成一份给人看的报告和一行给机器看的数据，按批次并排比。

---

## 1. 意图：这批数据要回答什么

**只回答一个问题：学生会不会用。**

不回答"提示有没有让他自己走完一步"——那是教研盲评的活，需要人读对话，不是埋点能算出来的。硬把两个问题塞进一套指标，会得到一套谁都不信的表。

所以本版的量化对象是：**他停在哪一页、在哪一页退回去、一道题重来了几次、有多少人走到报告页。**

前提是已经和作者确认过的事实：

- 测试是**放养**的：把链接发出去，学生自己找时间做，没有人在旁边看着；
- 是**改一版测一轮**：所以要有批次这个维度；
- 平台走**继续全 CloudBase**（见 §4）。

### 1.1 一个必须先纠正的事实：是四页，不是五页

`PRODUCT.md:26` 与 `README.md:8` 都写着"五页流程：题目 → 方式 → 解题 → 报告 → 巩固"，**代码里已经是四页**：

- `public/index.html:1944`：`var PAGES = ['题目', '方式', '解题', '报告'];`
- `public/index.html:2132`：`if (n === 5) n = 4; // 兼容旧链接；练习不再占一页。`
- `docs/report-practice.md`：取消独立第五页，旧页码 5 指向报告。

所以本设计的漏斗是 **p1→p2→p3→p4**，「再练一道」是报告页上的一个动作，不是一级台阶。若照"五页"实现，第五根柱子会永远是 0，"走完了"永远算不出来。

> 顺带一件小事：`PRODUCT.md` 与 `README.md` 这两处文案是旧的，应该在同一次提交里改掉，否则下一个人还会照着五页写。

## 2. 目标 / 非目标 / 反目标

### 目标

| # | 目标 | 怎么算达成 |
|---|---|---|
| G1 | 一人一个账号，能区分人 | 登录后所有记录都带 `userId`；换设备登录还是同一个人 |
| G2 | 会话不随实例消失 | 杀掉云函数实例/重启本地服务后，同一账号打开还能接着做、报告还在 |
| G3 | 四页漏斗可量化 | 能算出"第 3 页掉一半"这种句子，且能点进去看是谁 |
| G4 | 单条可导出 | 一道题导出成一份 Markdown（给人看）+ 一份 JSON（给机器） |
| G5 | 整批可导出 | 一个 zip：学生表、作答表、事件流、对话流、逐条报告、字段说明 |
| G6 | 批次可并排 | 同一份题单、同一批指标，两版放一起看 |
| G7 | OCR 与模型用量看得见、有硬上限 | 看板显示今日次数与上限；超限后接口直接拒，页面写明原因 |

### 非目标（这一版不做）

- **不做教学效果评估。** 不做"学生真的学会了吗"的任何推断。报告和导出的字段说明里必须写这一句。
- **不做知识点跨题画像、错因归一、教研复核工作流。** 那是 `docs/09` 的 Phase 3，它有自己的验收口径。
- **不做录屏回放。** 要引第三方库、要处理学生屏幕上的隐私，而漏斗掉点用它换不到新结论。
- **不做开放注册、找回密码、手机号/邮箱验证。** 账号是你手动发的一批；忘了口令就是重发一个。
- **不做学生端的历史页。** 学生只需要"继续刚才那道题"这一个入口，不需要时间线。

### 反目标（做成了也算失败）

- 一堆好看的图表，但没人能据此说出"这一版比上一版好在哪"。
- 为了统计加了二十个埋点，结果没有一个被真正看过。
- 把测试数据当成教学结论汇报出去。

## 3. 约束

这些是既有事实，设计必须绕开，不是可以谈的选项。

| 约束 | 出处 | 对设计的影响 |
|---|---|---|
| 会话在进程内存 `Map` 里，TTL 2h、上限 500 | `src/server/router.js:81-85` | 必须落库；内存只能当缓存 |
| 会话 id 由前端生成，且**第 3 页才创建** | `public/index.html:2602-2618` | 页 1–2 的事件没有 session 可挂，需要 `visit` 这一层（§5.2） |
| 一次 `/api/chat` **最多串三次模型调用** | `src/core/engine.js:242`（observe）+ `:348`（`for attempt < 2` 的 draft） | 超时预算必须是「一轮」的，不是「一次调用」的（§5.9） |
| 云函数硬超时 30 秒 | `cloudbaserc.json` 的 `"timeout": 30` | 而模型单次超时配 45 秒、OCR 超时配 30 秒（正好等于天花板），两个都会撞 |
| 导入题的注册表只在内存，TTL 6 小时、上限 200 | `src/core/registry.js:22-27` | 照片/粘贴来的题**重启后不可能续做**（§5.5） |
| 项目零运行时依赖，`npm test` 离线可跑 | `package.json`、README | 存储层用「端口 + 可替换驱动」，云 SDK 只能懒加载进云函数包 |
| `/api/ocr` 读体上限 2.6MB，其余 1MB | `src/server/router.js:234` | 手机原图必须先压；并且要能拒 |
| 绝不给答案 | `PRODUCT.md` 硬约束 | 埋点只能加在流程外面，不能改变判定 |
| 公网入口有口令门与凭据裁剪，但**当前部署没配口令** | `src/server/demo-gate.js`、`cloudbaserc.json`（只有 `FORCE_OFFLINE=0` + `ALLOW_OCR=1`） | 今天这条链接对任何拿到 URL 的人是满血真模型 + OCR。切换前要先收回链接（§5.11） |

## 4. 方案选择

三条路，已经在对话里选定了 ①。

|  | ① 继续全 CloudBase | ② 云托管容器 | ③ 自己的轻量服务器 |
|---|---|---|---|
| 国内可达 | 已验证，免备案 | 免备案 | 要备案，2–3 周 |
| 会话与记录 | 云函数无状态，必须落云数据库 | 进程可常驻 | 单进程内存，最省事 |
| 单次请求上限 | **硬 30 秒** | 可到几分钟 | 无 |
| 冷启动 | 1–2 秒 | 可留最小实例（几十元/月） | 无 |
| 导出 | 要写导出接口 | 要写导出接口 | 直接拿库文件 |
| 改动量 | 账号 + 落库 + 埋点 + 导出 | 还要加容器化 | 还要加运维与证书 |

**选 ①。** 理由：线上已经在这套上跑着。换形态等于同时改「平台」和「功能」，出问题分不清是谁的。

**升级到 ② 的触发条件（写死，不靠感觉）**：测试期实测 `/api/chat` 的**一轮失败率** > 2%（口径见 §5.4），或日活并发导致云函数排队。

> 注意：这个数只有在我们**自己**能测到时才有意义。云函数被网关 30 秒砍掉时，函数里的代码一行都不会跑，事件也写不进去——所以 `chat_send` 必须在调用模型**之前**落库，否则"超时率"永远是个 0（§5.3、§5.9）。

## 5. 要建的东西

### 5.1 身份与准入

一个新集合 `test_user`：

```
{ id, displayName, codeHash, salt, batches: [batchId], createdAt, disabled, firstSeenAt, lastSeenAt }
```

- `displayName` 是**代号**（S01、S02…），跟你登记的真名对照表**不进数据库**，只进你手上的那份 CSV。看板上一律显示代号。
- `code` 是登录口令，**只存 `codeHash + salt`**，服务端永远拿不回明文。
- 口令形态：6 位数字（`317482`）。可念、可抄、可以在微信里手打给学生。不用大小写字母，因为这在手机上是一次失败率很高的输入。
- `batches` 是**数组**，一个人可以同时在多个批次里。这条不是洁癖：改一版测一轮时，**让同一批人测两版**比每版换一批人强得多（配对比较，能排除"这批学生本来就更能打"）。而"一人一句口令、换一版重新发"会系统性丢掉最不积极的那几个学生，正好污染比较。

账号由脚本产生，不通过网页注册：

```
node scripts/issue-accounts.mjs --batch b2 --count 30 --out accounts-b2.csv
node scripts/issue-accounts.mjs --add-to b2 --userids S01,S02   # 老账号加进新批次
```

输出 CSV：`序号,代号,口令,登录链接`。你按名单一人一行发出去。

**登录流程**

```
POST /api/auth/login  { code }
  → 200 { token, displayName, batchId, expiresAt }
  → 401 { error: '口令不对' }
```

- token 是 32 字节随机值，服务端存哈希，**有效期绑账号（默认 60 天），不绑批次**——否则 v2 一开，老 token 全失效，等于强制换人。
- 前端存在 `localStorage`（沿用现有 `bsj-*` 前缀，用 `bsj-token`），后续每个请求带 `x-test-token`。
- 校验点放在 `src/server/demo-gate.js` 里，和现有口令门**同一个位置**：

```
buildRequestContext()
  ├─ 先解测试 token  → { userId, batchId, user } | null
  ├─ 再走现有口令门  → 决定这次能看见哪些凭据（不动）
  └─ 合成 { env, gate, user }
```

这样三个入口仍然只调一个函数，不会漂移。

**为什么是口令不是一次性链接**：链接会被转发到班级群，一个人转出去全班都能用；口令可以单独发、可以单独停用、泄露了改一个不影响别人。

**未登录能看见什么**：登录页和一句话说明。其余一律 `401`。这一版不保留「游客看个热闹」——放养测试里，一个没有身份的会话产出的数据没有分析价值。

**试点只跑 CloudBase。** `api/index.js`（Vercel）与 `api/worker.js`（Workers）保留但**不实现账号**：强制 `STORE=memory`，`/api/admin/*` 一律 401。理由有两个，都不是偷懒：token 校验要读库，而 `@cloudbase/node-sdk` 在 Workers 上根本装不上；账号只在云上跑，`src/` 就可以直接用 `node:crypto`，不用为 Workers 再写一套 WebCrypto。

### 5.2 数据布局

五个集合。选文档型（云开发数据库）是因为写入形状不固定、读法主要是"按批次取一片、按人取一串"。

```
batch         { id, label, versionSha, versionBuiltAt, questionIds[], startsAt, endsAt,
                ocrCap, dailyCap, idleMinutes, abandonHours, allowPhoto, createdAt }
batch_member  { batchId, userId, joinedAt }
test_user     { … §5.1 … }
visit         { id, userId, batchId, openedAt, lastAt, sessionIds[] }
session       { … 一次作答 … }
event         { visitId?, sessionId?, userId, batchId, at, type, payload }
```

**为什么要有 `visit`。** 会话 id 是前端在**进入第 3 页**时才造的（`index.html:2618`），而拍照、粘贴、选题全发生在第 1 页。如果事件只能挂在 session 上，那么最便宜也最有信息量的两个掉点——「打开了链接但一道题都没选」和「拍了照但识别失败」——根本记不下来，而它们恰好就是漏斗第一级的分母。

所以：

- `visit` = 一次打开（登录后的落地）。页 1–2 的事件挂在 `visit.id` 上。
- `session` = 一道题的作答。在**入场开始时**创建（选题/粘贴/拍照任一发生），此后的事件同时带 `sessionId` 与 `visitId`。
- 漏斗 p1 的分母是 `visit` 数，p2 起的分母是有 `session` 的 `visit` 数。

`session` 的形状：

```
{
  id, visitId, userId, batchId, problemId, questionIndex,
  startedAt, lastAt, finishedAt,
  endState,               // 'in_progress' | 'finished'   ← 只有两种，没有 'abandoned'
  segments: [ { start, lastEventAt, endReason } ],
  intake: { path: 'qbank'|'paste'|'photo', at, ocrAt, importAt },
  progress: {
    maxPage,              // 1–4
    reached: { p1: ts, p2: ts, p3: ts, p4: ts },
    backtracks,           // 从 n 页退到 n-1 页的次数
  },
  counters: {
    resetCount, intakeChanges, chatTurns, hintLevels: [],
    formulaOpens, reportViews, practicePicks,   // practicePicks 取代"第五页"
  },
  turns: [ { i, at, role, text, level?, stuckKind?, latencyMs?, engine? } ],
  reportSnapshot, reportBuiltAt,
  version: { sha, builtAt },
}
```

**`endState` 只有两种，`abandoned` 不落库。** 「放弃了没有」是**读的时候算出来的**：`lastAt` 距今超过 `batch.abandonHours` 且没 `finishedAt`。理由见 §5.5——一旦把它写成状态，它就会变成别的功能的门槛，而那个门槛会自己制造数据。

**`reportSnapshot` 必须落一份。** 报告现在是从 `record` 现算的（`buildReport`）；如果导出时重算，导出件会随代码变化而变，两个月后导出的和当时学生看到的不一样。快照冻结当时那一份。

**事件只追加，不更新。**

### 5.3 事件字典

只留 13 种。加一种必须删一种，或者说明为什么非它不可。

| type | 何时 | payload | 挂在哪 |
|---|---|---|---|
| `login` | 登录成功 | `{ displayName }` | — |
| `visit_open` | 落地页 1 | `{ referrer? }` | visit |
| `batch_open` | 打开题单 | `{ questionIds }` | visit |
| `page_enter` | 进入某页 | `{ page: 1..4 }` | visit / session |
| `page_exit` | 离开某页 | `{ page, via: 'next'\|'back'\|'close'\|'idle' }` | visit / session |
| `intake_choose` | 选了哪种入场 | `{ path }` | visit |
| `ocr_call` | 点拍照识别 | `{ bytes }` | visit |
| `ocr_result` | 识别回来 | `{ ok, ms, quota }` | visit |
| `import_result` | 读题回来 | `{ ok, ms, warningCount }` | session |
| `chat_send` | 学生发一句，**写库后才调模型** | `{ len, copiedStem }` | session |
| `chat_reply` | 收到回复 | `{ ms, level, stuckKind, suppressed, engine }` | session |
| `chat_error` | 我们代码返回的失败 | `{ code: 'TURN_SLOW'\|'UPSTREAM'\|'GUARD', status }` | session |
| `session_reset` | 重置 | `{}` | session |

`copiedStem` 是"有没有认真"的粗筛：前端比较首条消息与题干的重合度，超过 0.8 记 true。**只记布尔，不记内容。**

**`chat_send` 先落库、后调模型，这条是硬要求。** 云函数被 30 秒砍掉时，`chat_reply` / `chat_error` 都不会写；但只要 `chat_send` 已经落库，事后就能用「有 send 无 reply 且该 session 之后 2 分钟无事件」把这个会话认成一次被腰斩的调用。**没有这一条，§4 的升级触发条件就是空话。**

### 5.4 漏斗与指标口径

**页级漏斗**：`visit_open → p2 → p3 → p4`。四根柱子，这是唯一的主指标。

**掉点不是一个判定，是两个数。**

- **段内停顿**：同一段里超过 `batch.idleMinutes`（默认 8）没有任何事件 → 这一段记 `endReason: 'idle'`。只影响"这一段结束了"，**不影响他能不能回来**。
- **放弃**：`lastAt` 距 `batch.abandonHours`（默认 24）没更新，且没有 `finishedAt` → 读时算作放弃。
- 所以主语是：**最后停在页 N、并且之后再没回来的人数**。不是"关掉页面"——那个事件在手机上经常发不出来。

**重来** 由三个数合成：`resetCount + intakeChanges + 同一 (userId, problemId) 的 session 条数 − 1`。

**每批次都算的数**：人均题数、人均走到第几页、每页平均停留、退回次数分布、`chatTurns` 分布、AI 沉默率（`suppressed` 比例）、模型延迟分位、**一轮失败率**、OCR 调用次数与失败率。

**一轮失败率**（就是 §4 的那个触发条件）：

```
分子 = 有 chat_send 但在 abandonHours 内没有对应 chat_reply/chat_error 的轮数
     + 有 chat_error 且 code = TURN_SLOW/UPSTREAM 的轮数
分母 = chat_send 总数
```

**认真度粗筛**（不进主指标，只做分层）：`copiedStem` 为真的会话、首条消息 < 8 字的会话。看板给一个开关"包含/排除应付式作答"。

### 5.5 断点续做

一个学生隔天回来，必须能接着做——否则前半段数据白记，而且他的漏斗会被算成"掉在第 3 页"。

- 学生端在页 1 顶部有一个「继续刚才那道题」条：取该 `userId` 下**最近一条没有 `finishedAt` 的 session**，**不管它隔了多久**。隔了三天也照样给，条上写「3 天前 · 第 3 页」。
- 点进去恢复：题目、当前页、对话历史、提示层级。**提示层级不能归零**（`docs/09` §1.4 已指出旧壳恢复会话时 `hintLevel` 被置成 `null`，这正是"AI 从 L0 重来"的成因）。
- 恢复要记 `resume_click`，`idleMinutes` 就是"他是不是过了一阵又回来"的证据。

**这里有一处必须先定，否则 G2/A2 是假的**：只有**题库题**能续做。

照片/粘贴来的题活在 `src/core/registry.js` 的内存 `Map` 里，TTL 6 小时、上限 200（`registry.js:22-27`）。冷启动之后 `getProblemById` 返回 null，`/api/chat` 直接 404（`router.js:722`）。要让它也续做，就得把整个题目对象——**包括参考答案与解题图谱**——按会话存一份，这与 §7 的数据最小化正相反，而且把答案库复制成 N 份。

所以：**题单里的题一律来自那 152 道题库**；照片/粘贴作为独立入口（§5.6），不承诺续做、不计入漏斗。

### 5.6 三个界面

**① 学生端（改 `public/index.html`）**

加四样，不加第五样：

1. **登录页**：一个输入框 + 一句话（"这是内测，输入老师给你的 6 位数字"）。
2. **开场说明**（登录后第一次）：三句话——这是什么、这一轮有几道题、大概多久；一个"开始"按钮。记 p0→p1 的停留，就是"他读没读"。
3. **题单条**：`第 2 道 / 共 6 道 · 下一道`。没有它，学生不知道该做哪几道，"同题单可比"就是一句空话。
4. **「继续刚才那道题」条**。

**照片与粘贴怎么办。** OCR 是你明确要求"能用、有次数"的东西，但让它进题单流程会同时破坏两件事：每个人做的题不同（漏斗不可比）、且它不能续做。所以：

- 题单**只走题库题**；
- 页 1 保留一个**「试一试拍照识题」**的独立入口，进去能拍照、能看见识别结果、能识别后练一道**不计入题单**的题；
- 这条路径的调用**照样计数、照样上配额、照样显示在看板上**——你要的「OCR 可用 + 次数可见」在这里成立，而且不污染主漏斗。

**② 看板 `/admin.html`（新增，单文件，与现有风格同一套令牌）**

- 顶部：批次选择器、口径说明一行、数据截止时间、**今日 OCR 12 / 200 · 模型 340 次 · 中位 3.2 秒 · 一轮失败 0.4%**。
- 第一屏：漏斗（四根柱 + 转化率）+ 四个数（打开人数、答题人数、走到报告人数、一轮失败率）。
- 第二屏：批次对比表（同题单、同指标，两版并排；同一人出现在两版时标"配对"）。
- 第三屏：人的列表，代号 + 题数 + 最后停在页 + 认真度标记；点进去是单人页，逐条 session 可展开对话。
- 右上：导出按钮（单条 / 整批）。
- 页脚：一句话——**这批数据回答的是"会不会用"，不是"有没有效果"**。

权限：`ADMIN_CODE` 环境变量。**没配就 404**——和现在"公网一律锁死教师视图"同一个精神（`src/server/demo-gate.js:84`）。看板的所有数据都走 `/api/admin/*`，服务端校验，不在前端过滤。

**③ 提示词与判定的展示**：不做。看板不显示卡点分类、不给 L0–L3 的统计——那是 `docs/09` 的画像，这一版看的是"会不会用"。

### 5.7 导出

**单条**（`GET /api/admin/export?sessionId=`）：一个 `.zip`，内含

```
session.md      # 给人看：题目、每轮对话、最后报告，按时间顺序
session.json    # 原始记录：turns、counters、progress、reportSnapshot
```

`session.md` 在服务端渲染，字段顺序固定，不把 JSON 丢给人看。

**整批**（`GET /api/admin/export?batchId=`）：

```
students.csv     # 代号,批次,首次登录,最后登录,题数   （不含真名）
sessions.csv     # 一条作答一行：所有标量指标
events.jsonl     # 每行一个事件
turns.jsonl      # 每行一轮对话
reports/<sessionId>.json
README.md        # 字段字典 + 口径说明 + 这一版能/不能回答什么
```

三条硬要求：

1. **CSV 必须能直接用 Excel 打开**：UTF-8 带 BOM，否则中文列名在 Excel 里是乱码。
2. **导出件默认不含真名**，只有代号。真名在你手上的发号 CSV 里，靠代号对。
3. **README.md 里必须写明"这批数据回答的是会不会用，不是有没有效果"**——防的是三个月后有人拿它去汇报教学质量。

### 5.8 用量与闸门

阿里云那条链路查不到余量（`docs/06` 与 README 都记着），所以**我们自己的计数就是唯一口径**。

- 每次 `/api/ocr` 成功，`counters.ocrUsed[batchId] += 1`；失败不计（按成功调用计费）。
- 两道闸：`batch.ocrCap`（整批）与 `OCR_DAILY_CAP`（环境变量，日粒度）。任一触顶 → `503 { code: 'OCR_QUOTA' }`，页面把相机入口置灰并写明"今日额度已用完"。
- 看板顶部常驻那一行（见 §5.6）。
- 界面文案必须写清口径：**"本站计数，与阿里云控制台可能差几单（重试与超时都会计入供应商侧）"**。这不是免责声明，是防止对账时互相怀疑。

### 5.9 平台配置与时间预算

**超时这件事，按"一次调用"算是错的。** 一次 `/api/chat` 最多串三次模型调用：`engine.js:242` 的 `observeStudent`，加 `:348` 那个 `for (attempt < 2)` 里的 `draftHint`。若把 `LLM_TIMEOUT_MS` 写成 25000，最坏情况是 75 秒，而云函数 30 秒就砍——被砍时我们的代码一行都不跑，前端拿到的是网关的 502，学生看到的是一句没有原因的错误。

所以改成**一轮一个截止时间**：

| 项 | 现在 | 改成 | 为什么 |
|---|---|---|---|
| 一轮总预算 `TURN_DEADLINE_MS` | 无 | `22000` | 留 8 秒给冷启动、读库、守卫与响应序列化 |
| 单次模型超时 | `45000` | `min(12000, 剩余预算)` | 三次调用分着用，不能让第一次吃光 |
| 剩余预算 < 4 秒 | — | 不再重试 draft，直接收口 | 与其写出半句话，不如让前端重试 |
| 超时后的返回 | 网关 502 | **我们自己返回** `503 { code:'TURN_SLOW', retryable:true }` | 只有我们自己返回，才写得了 `chat_error`、前端才给得出「重试」 |
| OCR 超时 | `30000`（正好等于天花板） | `12000` | 实测 863ms；给 12 秒已经是 14 倍余量 |
| 前端失败态 | 只有错误文案 | 文案 + **一个「重试」按钮** | 超时可恢复，让人重新打一遍字是浪费一次数据 |

### 5.10 存储层

一个端口，三个驱动：

```
src/server/store/index.js       // openStore(): 按 STORE 环境变量选驱动
src/server/store/memory.js      // 默认；与现在行为一致（进程内 Map）
src/server/store/file.js        // 本地开发与测试：JSONL 落盘，node:fs，零依赖
src/server/store/cloudbase.js   // 生产：懒加载 @cloudbase/node-sdk，写云开发数据库
```

规则四条：

1. **`memory` 是默认**，任何环境不配就退回它，行为与今天一个字节不差。
2. **公网 Demo 一律 `memory`**（沿用 `docs/09` §6.4 的结论），不配就不得写真实学生数据。
3. 驱动同接口：`getUser / putUser / getBatch / listBatchesByUser / getVisit / putVisit / getSession / putSession / appendEvent / listSessionsByBatch / listEventsBySession`。测试只针对 file 驱动跑，云驱动靠同一套契约 + 一条冒烟用例。
4. 云函数的 `dist-cloudbase/bubujie-api/package.json` 里加 `@cloudbase/node-sdk`，`installDependency` 改 `true`；源码用**动态 `import()`** 懒加载，本地与 CI 不装这个包也照常跑。

### 5.11 切换（一次，且是一次性动作）

现在的线上链接是**满血**的：`cloudbaserc.json` 里只有 `PUBLIC_DEMO_FORCE_OFFLINE=0` 与 `ALLOW_OCR=1`，**没有配 `DEMO_ACCESS_CODE`**——也就是说任何拿到 URL 的人都能用真模型、能烧 OCR 额度。加了账号之后，这件事会变成"登录框后面才是满血"，但切换那一刻是一次**在活服务上的硬切**：

1. 切换前，先把旧链接从所有群/文档里收回，或改成指向登录页。
2. 切换后，除登录页与 `/api/auth/*` 外，`/api/*` 一律 401。
3. 旧链接上已有的匿名会话没有身份，**不迁移**（它们也不是测试数据）。
4. 切换日在批次里单独标记，前后两段不合并统计。

另外两件配置：

- **云数据库权限**只开「仅管理端可读写」，所有访问经云函数；前端永远不该直连数据库。
- **数据留存**：批次结束后 90 天清理，清理前必须先导出。
- **密钥位置**：现在在 `cloudbaserc.json` 明文（该文件已 `gitignore`，但仍在工作树里）。改成部署脚本从 `.env` 读，只注入云函数环境变量——少一份明文副本，就少一次"顺手发出去"的机会。

## 11. 还没定的（需要你）

1. **同一批人测两版，还是每版换一批人？** 我按"同一批人"设计（`test_user.batches` 是数组、token 不绑批次），因为配对比较能排除"这批学生本来就更能打"。代价是 v2 要用同一批人再等一轮。
2. **照片入场要不要进题单？** 我按"不进"设计（可比的漏斗 vs OCR 展示，我选前者，OCR 用独立入口保住）。如果你要的是"就要让学生真的拍着用"，那漏斗的横向比较就得放弃，看板要改成只报"人人各自的完成情况"。
3. **同意与告知做不做、做到什么程度？** 一行勾选（我建议的最低限度），还是监护人知情？这是 §7 里唯一可能要额外一周的事。
4. **现有 CloudBase 环境直接切，还是新开一个环境？** 直接切省事，但旧链接下线那一刻会打断现在可能正在用的人。
5. **题单几道题、多少人？** 我按 6 道、单批两周、50 人以内设计。若实际 3 道，每页样本太薄，指标会抖；若 200 人以上，§4 要改选 ②。
