# 设置面板：主题与字号档位 —— 设计

日期：2026-11-02
状态：待审

## 一句话

顶栏那颗太阳/月亮按钮换成齿轮，点开一个设置弹层，里面管两件事：主题（浅色 / 深色 / 跟随系统）和字号档位（小 / 中 / 大，三档吸附）。字号放大时，字和"包着字的固定尺寸盒子"一起放大。

## 为什么做

学生晚上刷题想换深色护眼；题目长、字小，看不下去。这两件事现在各有一个问题：

- **深色其实已经做完了**，只是没有门。`html[data-theme="dark"]` 已经翻掉了 paper/surface/line/ink/brand/mint/amber/coral 与阴影（`public/index.html:86-110`），另有 5 条深色补丁规则（`public/index.html:277`、`:906-911`、`:916-917`、`:918`）。入口是顶栏一个没有文字的图标按钮（`public/index.html:950`），点一下切换。全站搜不到"设置"两个字。
- **字号完全不可调**。好在这条便宜：全站 70 处字号没有一处写死 `font-size:NNpx`，全走 `--fs-*` token（`public/index.html:77-81`），行高是无单位倍数，会自己跟着走。

所以这个需求的实质是：**给已有的深色一个正经入口，并补一套字号档位**。不是重做深色。

## 目标

- **G1** 顶栏齿轮打开设置，主题与字号都能在这里选。
- **G2** 主题三选，默认「跟随系统」，选完刷新后仍在。
- **G3** 字号三档吸附，中档 = 现状像素**一个都不动**。
- **G4** 放大时文字与固定尺寸的盒子同步放大：不夹字、不出横向滚动、版面比例不变稀。
- **G5** 设计纪律继续成立：`npm test`（含 UI 审计）全绿，审计仍然守得住字号档位。

## 非目标

- 不做「跟随系统」以外的时间/电量自动切换。
- 不做每页独立字号，不做任意连续字号。
- 不动旧壳：`public/shell.css`、`shell.js`、`shell-overrides.css`、`youth.css`、`classic.html`（README 已标注为旧壳，只被 classic 加载）。
- 不做服务端保存，只用 localStorage。
- 不新增「高对比」「减少动效」等其它开关。

## 反目标（做成了也算失败）

- 大档出现横向滚动条，或文字被容器裁掉。
- 深色下面板自己读不清（对比度不足）。
- 面板打开后焦点丢失；Esc 或点外面关不掉。
- 三档之间差值小到看不出区别，等于白做。

## 约束（来自代码的事实）

- **单文件**：markup + 内联 `<style>` + 内联 `<script>` 全在 `public/index.html`，由 `server/server.js` 直接静态发出。没有构建步骤、零依赖。
- **首屏必须上色**：`public/index.html:9-23` 的脚本在样式表之前跑，否则闪白。档位属性必须搭同一班车，否则大档用户每次刷新先看到一帧中档。
- **审计脚本从 token 字面量推规则**：`scripts/audit-ui-style.js:27-35` 用正则从 `--fs-*:NNpx` 里收集"允许的字号"，并靠整数白名单守间距（2/4/6/8/12/16/24/32）与圆角。字号一旦分档，这个推导方式会失效，必须同步升级 —— 这是本设计的主要附带成本。
- **DOM 契约测试**：`test/ui.test.js` 会核对内联脚本里每个 `$('#id')` 在 markup 里都存在，写错一个字母就是"点了没反应"。新增 JS 引用的 id 必须先落地在 markup 里。
- **README 用例数被测试钉住**：`test/docs.test.js` 会对比 README 里"当前规模"的用例数与实际注册数。加测试就要改 README 的数字。
- `--fs-title` 已定义但**当前没有使用点**（只有 meta/body/lead/sub 在用）。

## 方案（三条路，选了第二条）

| | 做法 | 好处 | 代价 |
|---|---|---|---|
| A | 一个 `--ui-scale` 乘系数，所有尺寸 `calc(Npx * var(--ui-scale))` | 定义最少，加一档只加一行 | 会出现 14.95px、18.4px 这类值；审计的整数白名单失效；字号与控件可能出现"字变了框没变"的中间态 |
| **B（选）** | **三套显式整数数值表**，每个尺寸三档各一个人挑的整数 | 每个值可读可审；审计能继续守"只取固定档"；不会出现半像素 | token 定义变三倍；页三的覆盖要改写 |
| C | 全站改 `rem`，靠根字号缩放 | 加档只改根字号，语义最正 | 全站尺寸现在都是 px，等于重写全部 CSS，风险最大，收益不明显 |

选 B 的理由：这个仓库的纪律就是"只取固定档"（字号三档、间距八档、圆角九档），B 是这条纪律的自然延伸；而且它把"大档到底多大"变成一张能逐行核对的表，而不是一个藏在系数里的手感。

## 已定（用户拍板）

1. **入口**：顶栏太阳/月亮按钮换成齿轮，同一个位置（`.tb-right` 内）。
2. **主题三项**：浅色 / 深色 / 跟随系统。理由：现在的默认其实就是跟随系统，只给两项的话，从没选过的用户打开设置会看到"两个都没选中"。
3. **字号三档吸附**：滑块只能停在小 / 中 / 大三个落点，拖动感保留。
4. **放大范围**：只放大"包着文字的固定尺寸盒子"，间距与圆角不动。
5. **页三不再单独缩小字号**：原来页三有 6 条覆盖（顶栏高 `:219`、padding/gap `:220`、品牌标 26px `:221-222`、
   brand-name 字号 `:223`、brand padding `:224`、隐藏副标题 `:225`）。现在只保留「顶栏更矮」这一条，
   其余 5 条一律回到统一档位 —— 大档下对话页也一起放大。
6. **面板形态**：齿轮下方锚定弹层，点外部或 Esc 收起；≤760px（已有断点 `public/index.html:880`）改成贴底整宽抽屉 + 遮罩。
7. **滑块标注**：只写 小 / 中 / 大，不露百分比（百分比与实际倍率对不上，会自相矛盾）。

### 我定的（不同意就否）

- 存储：沿用 `bsj-theme`（值域扩展为 `light|dark|system`），新增 `bsj-ux`（`s|m|l`）。旧值 `light|dark` 直接可用，无迁移动作；没存过 = `system`。
- 地址参数：`?theme=` 保留并扩到 `system`，新增 `?ux=s|m|l` —— 截图脚本靠它一次覆盖九个组合。
  两个参数都只影响这一次：首屏只还原、不落盘（见「触达点」）。
- 一个档位属性同时驱动字号与盒子尺寸（`html[data-ux="s|m|l"]`），不拆成两个开关：拆开就会出现"字放大了框没跟上"的中间态。
- 深色不重做，只做验收式检查（逐页看有没有漏掉的硬颜色）。

## 具体数值

### 字号（中列 = 现状，不动）

| token | 小 | 中 | 大 |
|---|---|---|---|
| `--fs-meta` | 10 | 11 | 13 |
| `--fs-body` | 12 | 13 | 15 |
| `--fs-lead` | 12 | 13 | 15 |
| `--fs-sub` | 14 | 15 | 17 |
| `--fs-title` | 16 | 18 | 21 |

小约 −10%、大约 +15%。`--lh-*` 无单位倍数不变，自动跟随。`--fs-title` 现在没有使用点，仍按档给值，免得将来"只放字不放大标题"。

### 尺寸（只放"包着字的固定盒子"）

| token | 用在哪 | 小 | 中 | 大 |
|---|---|---|---|---|
| `--topbar` | 顶栏高（`public/index.html:83`、`:152`） | 48 | 52 | 58 |
| `--topbar-sm` | 页三顶栏（`:219`） | 44 | 46 | 50 |
| `--ctl` | `.icon-btn` / `.send-btn` 32px 控件盒（`:206`、`:373`） | 30 | 32 | 36 |
| `--input-h` | 首页输入区高度（`:356`） | 44 | 48 | 54 |
| `--ico` | 品牌标（`:167-170`） | 28 | 30 | 34 |
| `--ico-lg` | 首页大标（`:326-329`） | 36 | 40 | 44 |
| `--ico-sm` | 步骤圆圈 / 题号勾 / 进度点（`:186`、`:231`、`:449`） | 22 | 24 | 28 |
| `--av` | 聊天头像盒（`:644`，32） | 30 | 32 | 36 |
| `--av-img` | 头像图本身（`:648`，原 26 内缩在盒里） | 24 | 26 | 30 |
| `--pane-head` | 面板标题行最小高（`:547`） | 40 | 44 | 48 |

### 明确不动

间距（2/4/6/8/12/16/24/32）、圆角（0/2/4/8/10/12/16/24/999）、`--lh-*`、以及装饰微组件（4px 圆点、1px 分隔线、进度条）。

理由：撑开版面靠的是盒子高度，不是留白。留白跟着放大会让大档变得又大又稀，反而更难读；而且动间距就要动审计白名单，纪律会松。

## 面板行为

- 齿轮：`aria-expanded` 同步，`aria-controls` 指向面板。
- 打开：焦点进入面板（默认落在当前选中的主题项）；关闭：焦点回齿轮。Esc 关闭，点面板外关闭（桌面靠 document 监听，小屏靠遮罩）。
- 主题分段控件：`role="radiogroup"` + `aria-checked`，三点变化立即生效。
- 滑块：原生 `input[type=range]`（`min=0 max=2 step=1`），`input` 事件即时应用档位（拖动过程中字就在变，不是松手才变），`aria-valuetext` 报"小/中/大"；轨道用渐变换色表示已填充部分，三个刻度点上下一一对应。
- 小屏（≤760px）：面板贴底、整宽、上方加半透明遮罩；遮罩在桌面宽度下 `display:none`，同一个开关逻辑。

## 实现时踩到的坑（做完回填，给下一个人）

1. `.topbar` 上有 `backdrop-filter:blur(12px)`，它会成为 `position:fixed` 后代的**包含块**。
   面板与遮罩因此挂在 `</header>` 之后，而不是顶栏里面 —— 否则小屏"贴底整宽抽屉"会以 52px 高的顶栏为参照。
2. 小屏抽屉的覆盖规则必须排在 `.set{}` 基础规则**之后**。顺序写反时桌面那条 `width:288px` 会赢，
   手机上就是"半个面板飘在角落"。这条已由 `test/settings.test.js` 钉住（断言源码顺序）。
3. 桌面端**不加遮罩**：加了会把整页压灰，看着像禁用。遮罩只在 ≤760px 出现。
4. 首屏那次 paint 必须显式传 `persist=false`，否则用 `?theme=` 看一眼就把偏好写死了，
   连「跟随系统」都会被吞掉。只有用户点选/拖动才落盘。
5. +15% 之后，390px 宽会先挤坏两处小药丸：`.c-chip`（"物理 · 高中"换行）、`.q-meta .kind`（"难度 2/5"断两行），
   都补了 `white-space:nowrap`。盒子里的图标也要跟档，否则 32→36 之后图标显小：
   改成 `calc(var(--ctl) / 2)`、`calc(var(--ico-sm) / 2)`，中档恰好还是 16 / 12。
6. 审计脚本里"禁止字面量 `font-size:NNpx`"必须作用在**展开 var() 之前**的 CSS 上；
   展开之后全站都是 px，会一次报出七十条。
