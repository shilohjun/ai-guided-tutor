# 免口令进场与完成码（设计稿）

> 2026-11-15　状态：待产品负责人过稿　取代：`docs/superpowers/specs/2026-11-09-测试平台-账号与测试数据-design.md` 的「身份与准入」一节（该稿其余部分仍然有效）

## 0. 一句话

**进门不验人，出门发一张票**：学生打开链接就能用（不必输口令）→ 用完了主动点「结束使用」→ 服务端发一个 6 位完成码 → 老师在看板里输码，直接打开这一次使用。

## 1. 意图：为什么要换掉口令

口令本来干两件事：**认人**（把记录挂到某个 `S01` 上）和**挡成本**（带对口令才给真模型与拍照）。试点跑下来，认人这件事的收益全被"发号 40 条 + 微信里挨个发 + 学生输错 5 次被锁 15 分钟"吃掉了。

改成完成码，等于把认人从事前挪到事后：**进门零成本，出门一张票**。票是学生手里唯一的凭据，也是老师唯一需要搬运的东西。

换掉之后必须同时成立的三条：

1. 谁都能进门（不需要老师事先发任何东西）；
2. 记录仍然能对应到人（至少对应到"这一次"）；
3. 别人的使用不能被读、改、重置。

第 3 条是这次改动里最容易漏的一条，见 §5.1。

## 2. 目标 / 非目标 / 反目标

### 目标

- 学生打开链接 →（可选）填一句称呼 → 直接开始做题；**全程不需要任何口令**。
- 学生点「结束使用」→ 看到一个 6 位完成码 → 抄走/截图/发给老师。
- 老师在看板顶部输入完成码 → 直接打开那一次使用（谁、几点到几点、做了几道题、每题的完成情况、报告）。
- 设备换了、缓存清了，不影响老师找回记录（按姓名 + 日期）。
- 老数据（发号时代的批次记录）仍在看板里看得到，只是没有码。

### 非目标（这一版不做）

- 学生自己用码回看自己的记录。
- 找回/恢复码、跨设备同步。
- 批次继续存在（发号动作取消）。
- 学习画像、错题本、家长端。
- 真模型的花费上限（见 §5.8 与 §9）。

### 反目标（做成了也算失败）

- 学生输完码才发现要用另一个码，或者门口出现任何"验证"字样。
- 码需要老师解释怎么用。
- 为了免口令，把「别人的记录不能碰」这条丢了。
- 看板上出现两套并列的筛选逻辑（批次 + 码），没人说得清该用哪个。

## 3. 约束

1. **`public/index.html` 一个字节都不许改**（它是成品页）。所有新界面在 `public/pilot.html` 这层壳里，`admin.html` 单独改。
2. **零依赖、无构建**。原生 ESM + 原生 DOM。
3. **serverless**：Vercel / CloudBase 都没有常驻进程，**不能靠定时器**做"超时自动结束"。一切超时都必须是读时惰性计算（现有 `isAbandoned` 就是这么做的，`metrics.js:346-372`）。
4. **三端共用** `src/server/router.js`：Vercel / Cloudflare / CloudBase 只有一个业务入口。
5. **存储端口只有主键读写**（`store/index.js:28-51`）。要新加"按码查"，必须扩端口，不能靠全表扫描（CloudBase 上会是灾难）。
6. 现在整班共用一个出口 IP（`auth.js:451-460` 的注释就是这个意思），**任何按 IP 的限速都必须给全班留余量**。

## 4. 方案选择

已否决的两条路：

- **A. 纯匿名，不要任何身份**。听起来最省事，实际上把 `notMine` 变成恒真（`router.js:719-723` 在没有身份时放行），而会话 id 是客户端自己编的时间串（`router.js:700`）—— 谁都能读别人的报告、往别人的会话里写、甚至 `/api/reset` 把人家的记录清掉。否决。
- **B. 进门让老师发一次性链接**。那是"把口令换成另一种口令"，门槛还在老师手上。否决。

选定的路：**匿名设备票**。

> 服务端在第一次打开时自动签发一张票（用户看不见、不用输任何东西），票背后是一条没有口令的用户记录。**它的唯一作用是让"归属"重新成立**，不是登录。

这条的好处是：`userId` 归属链路（`session.userId` / `visit.userId` / `event.userId`、`notMine`、`persistSession` 拒绝覆盖别人）全部原样成立，**不用改写任何一处归属判定**。

## 5. 要建的东西

### 5.1 身份：匿名设备票

新集合 `visitor`：

```
token { tokenHash, userId: 'g-<16hex>', role: 'visitor', displayName: '王浩' | '',
        expiresAt, createdAt }
```

- **不建 visitor 表**（这一点比初稿改了）。身份直接写在令牌记录里，走"开发档"那条路：
  `resolveToken` 认 `role:'visitor'` 就地还原 `{ id, displayName }`，不去查 `test_user`。
  理由：访客既不该混进"名单"表（几百个浏览器会把 `listUsers` 拖死），也不值得为它新增
  一张表和三份驱动实现 —— 它本来就只是"这一台浏览器"。
- 令牌沿用现有机制（32 字节随机、库里只存 sha256、60 天 TTL），客户端存在现有的
  `localStorage['bsj-token']` 键上，请求头仍是 `x-test-token` —— 前端 `withToken()`
  一行都不用改。
- 新建接口 `POST /api/auth/visitor { displayName? }`：**总是新发一张**（不复用旧票，
  否则"换个人"就没有边界了）。客户端只在本地没有票时才调它。
- **票是必需的**：`PILOT_REQUIRE_LOGIN=1` 保持开启，没有票就 401，客户端回到问候屏重新领。
  票丢了（清缓存/无痕/换设备）就是一次新的使用 —— 这正是产品要的边界，不做恢复码。
- **姓名是记录上的字段，不是账号上的**：`visit.displayName` 在开场时写死一份。
  今天 `displayName` 只存在于 `test_user`，会话/访问/事件上都没有它（看板靠 `userId`
  反查账号才显示出来），账号表退场之后这条反查没有了。
- **领票不限速**（初稿写的 30 次/IP/小时已取消）：整班共用一个出口 IP，40 个学生
  第一节课就会撞上；而它写的只是一条令牌记录，刷不出账单。真要挡在网关层挡。

### 5.2 一次「使用」= 一次 `visit`

不改主键、不新建表，把现有 `visit` 扩成这次改动的主角：

```
visit { id, userId, displayName, openedAt, lastAt, endedAt | null,
        endReason: 'manual' | 'idle' | null,
        code: '482913' | null, sessionIds[] }
```

- 一次使用从"打开"开始，到"结束使用"为止。**期间做几道题都算同一次**，每道题仍是一份独立的 `session` 与独立报告。
- `batchId` 保留，但语义变了（v3）：**它是部署级的一个固定标签**（`PILOT_BATCH_ID`，默认 `pilot-1`），写在票上、会话与事件从票上抄。老看板与整批导出因此仍认得新数据；配成空串就是不归批。改名只影响之后新开的票（票 60 天有效）。
- 结束是**终态**：`endedAt` 一旦写上有值就不再变；要再练就是一次新的使用、新的码。
- 宽限：最后一次动静超过 **2 小时**视为自然收尾（`endReason:'idle'`）。不做定时器，**在读的时候惰性物化**，而且**只在学生这条路上**：他下次打开时当场补码并落库（幂等）。看板读流水时**不补码**（`admin.js` 立过"看板只读"的规矩），超时但没人收尾的那条显示"进行中（已超时）"。
- "最后一次动静"**不能读 `visit.lastAt`**：那个字段从 `createVisit` 之后再也没有写入方。改成从会话里算：`max(openedAt, 每个 session 的 lastAt)`。
- 2 小时内回到同一台设备，可以接着上一次继续做（不强制结束），因为"上次没做完"是常态；超过 2 小时才收尾。这条同时把现有的"续做"（`/api/session/resume`）保住了 —— 它今天挂 401 是因为没有 `req.__user`，有了票就自动通。

### 5.3 完成码

- **6 位十进制**，全局唯一，不区分批次，**永不过期**。
- 独立集合 `usage_code`，键就是码本身：`{ code, visitId, userId, createdAt }`。为什么不在 visit 上扫：存储端口只有主键读，CloudBase 全表扫不可接受；而且码必须是"查得到"的东西，不是"扫得出来"的东西。
- 撞码就重生成（`auth.js:186-197` 已有这个先例：生成 → 查 → 撞了再来）。
- 码**只印给学生**，服务端任何读接口都不回显码，除非是这一次使用的结束响应或看板按码查。
- 码不需要加密强度：能看到它的只有学生本人和老师，而老师那一侧外面还有一道管理员口令（`admin.js:736-749`）。

### 5.4 接口

新增（都挂在现有登录守卫之后，即需要票）：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/visitor` | 领票。`{displayName?}` → `{token, userId, displayName}`。**必须加进 `LOGIN_EXEMPT_PATHS`**，否则没有票的人连票都领不到 |
| GET | `/api/usage/current` | 当前这次使用：`{visit, lastEnded}`。`visit` 为空且 `lastEnded.code` 有值 = "上一次已自动收尾，码是 XXXXXX" |
| POST | `/api/usage/start` | 开始 / **接着用**（同一台设备 2 小时内回来是同一次）。`{visitId, resumed, displayName, lastEnded}` |
| POST | `/api/usage/end` | 结束：`{code, endedAt, reused, summary}`。**幂等**：已经结束过就回同一个码 |
| GET | `/api/admin/usage?usageCode=` | 看板按码查一条（需 `x-admin-code`）。参数叫 `usageCode` 而不是 `code`：`?code=` 在这个仓库里是公网 Demo 的口令，而看板页有一条静态契约禁止口令出现在查询串里 |
| GET | `/api/admin/day?date=` | 看板按日期的流水（需 `x-admin-code`）。日期按**北京时间**解释 |

`/api/visit` **不动**（有了票就不再 401，老测试与老调用方照旧），但新的学生壳不再调它 —— 开场走 `/api/usage/start`，因为只有那条路会"接着用"。老的 `/api/admin/overview?batchId=`、`/api/admin/users?batchId=`、`/api/admin/export?batchId=` **原样保留**，只服务历史数据，不再有新数据进来。

新事件类型（第三批，本轮**尚未加**）：`usage_start`（客户端，开场）、`usage_end` / `usage_auto_end`（服务端）。归属用 `visitId`，符合现有 owner 规则（`events.js:132-135`）。加之前要过 `EVENT_TYPES` 那个封闭字典的审核（加一条要说明为什么）。

### 5.5 界面 · 学生这一侧（`public/pilot.html`）

三段式，全部在壳里，产品页不动：

1. **问候屏**（顶替今天的登录屏）：一句话 + 一个"怎么称呼你"的输入框（可跳过，记得上次输入）+ 一个「开始」。没有任何"口令/验证/登录"字样。点开始 = 领票 + 开场。
2. **使用中**（今天的壳）：顶栏右侧的「退出」改成「**结束使用**」，点了先二次确认（"结束后这一次就结束了，会给你一个完成码"）。
3. **收尾页**：全屏，只有三样东西 —— **大字号完成码**（可点一下复制）、一行"把码发给老师"、本次概况（做了几道题 / 用了多少分钟）；底部一个「再开一次」（开新的一次使用、新码）。

宽限与断线：

- 打开时若票上还有未结束的使用且未超 2 小时 → 直接进使用中，顶上一条窄提示："上次没结束，可以接着做，也可以现在结束"。
- 超时 → 打开时显示"上一次已经自动收尾，完成码是 XXXXXX"（只提示一次，可点复制）。
- 共用电脑：上一位没点结束就走，下一位在问候屏会看到同一条"上一位没结束"的提示 —— 因为票是设备级的，这是这套方案里**唯一无法自动消掉**的串号场景，明说在提示里，让人自己点结束。

### 5.6 界面 · 老师这一侧（`public/admin.html`）

- 载入方式从"口令 + 批次"变成"**口令**"。批次框删除。
- 顶部两个动作：**「按完成码查」**（6 位输入框）与**「看某一天」**（默认今天）。
- 按码查 → 一张使用卡：姓名、开始/结束时间、结束方式（主动/自动）、几道题、每题（题目、走到第几页、是否完成、报告折叠展开）、以及"导出这一次"。
- 按日期 → 流水表：时间、姓名、状态（进行中 / 已结束 / 自动收尾）、码、题数、时长。老记录（有 `batchId` 无码）在这一屏里照常出现，来源一栏写"历史（b2）"。
- **不再有"全班一张表"**。理由：批次取消之后，"全班"这个词没有定义了；真要看人，按日期看流水 + 按码看个人，两个动作覆盖了 100% 的实际用法。
- 页面顶部加一行用量：当天对话轮数 / 当天拍照次数（今天 `overview.usage` 已经算好了这些数，只是换了展示位置）。这一行是 §5.8 里"事后看用量"唯一的落点。

### 5.7 存储端口

`store/index.js` 新增四个方法，三个驱动（memory / file / cloudbase）都要实现：

- `getUsageCode(code)` / `setUsageCode(code, rec)` —— 主键读写，三端都简单。
- `listVisitsByDate(dateKey)` —— file 驱动按 `openedAt` 的日期戳建目录或写一个索引；cloudbase 用 `where(openedAt >= from and < to)`；memory 直接 filter。
- `getOpenVisitByUser(userId)` —— 用于"上次没结束"的判断。
- `endVisit(visitId, {endedAt, endReason, code})` —— 幂等写；已结束的直接返回原值。

`clear()`（测试用）要记得带上 `usage_code` 与 `visitor`。

### 5.8 成本闸（这一版明确不设上限）

产品负责人已定：**不加真模型的花费上限**，靠"链接不公开 + 事后看用量"。

- 拍照沿用现有 `OCR_DAILY_CAP` 日额度（不变），只是批次那一维随批次一起消失。
- 真模型今天**完全没有闸**（只有每轮 22 秒的墙和单次超时）。这一版不新增闸，但留一个**保险丝**：`LLM_DAILY_TURN_CAP`，空 = 不限（默认，等于今天的行为）。写它只是为了"账单那天能在十秒内拉住"，不需要改代码。
- 额度真的用完时（如果将来配了保险丝），**必须明说**"今天的 AI 额度用完了"，不允许静默降级成离线桩 —— 静默降级的症状是"AI 变笨了"，没人会想到是额度。
- 事后看用量：`admin.html` 顶部那一行（§5.6）。

### 5.9 老数据与老账号

- `test_user` 里发号产生的账号**保留**，但**不再能登录**（登录分支删掉）。它们仍能被 `getUserById` 解析出来，所以历史记录上的 `S01` 照样显示。
- 历史 visit / session / event 一个字段都不动，也没有码；看板按日期仍看得到，来源一栏标"历史（批次 b2）"。
- `scripts/issue-accounts.mjs` 保留但从 `package.json` 的说明里拿掉，README 里标注"历史工具，试点已改用完成码"。

### 5.10 登录屏的去向

学生登录分支删除后，`/api/auth/login` 仍保留两档：**调试口令**（`PILOT_DEV_CODE`）与**看板口令**（`ADMIN_CODE`）。它们的入口不再出现在正常路径上：

- 看板：直接开 `/admin.html`（它本来就是自己填口令）。
- 调试：`/pilot.html?key=1` 才显示那一个口令输入框。

这样"门口"对学生是问候屏，对你是另一个 URL —— 不需要第三个页面。

## 7. 风险

| 风险 | 现在怎么处理 |
|---|---|
| 链接被公开转发，真模型账单无上限 | **已知风险，产品已接受**。保险丝留在 `LLM_DAILY_TURN_CAP`；看板顶部有当天轮数 |
| 共用一台电脑，上一位没结束 | 问候屏提示"上一位没结束"；结束是设备级的，无法自动分辨人 |
| 姓名乱填/重名 | 姓名只是称呼，不是身份；老师认人靠码 + 时间 + 本人对照 |
| 学生把码弄丢 | 老师按"姓名 + 日期"从流水里找回来 |
| 有人猜到别人的码 | 码只有老师能用（看板外面还有管理员口令）；学生侧没有任何按码查的入口 |
| 老数据没有码，老师问"那批人呢" | 流水里按日期 + 姓名仍能看到，来源标"历史" |
| 6 位码在 1e6 空间里撞上 | 生成时查重，撞了重来；索引表主键是码本身，天然防重 |
| serverless 没有定时器，"自动收尾"可能永远不触发 | 惰性物化：只在被读到的路径上补，没人读就没人看，也就没人需要那个码 |

## 8. 验收（能当场跑）

1. 清空 localStorage，打开 `/pilot.html` → 出现问候屏，**不需要任何口令** → 填称呼 → 开始 → 做题。
2. 点「结束使用」→ 收尾页出现 6 位码 → 再点一次结束（刷新后仍能拿到）→ 码不变。
3. 把码填进 `/admin.html` 的「按完成码查」→ 打开这一次使用：姓名、时长、题数、每题情况、报告。**用第二张码查不到第一条**。
4. 打开 `http://…/pilot.html` 换一个浏览器 → 是新的一次使用、新码；老师按"今天 + 姓名"仍能找到第一条。
5. 手工把某个 visit 的 `lastAt` 改到 3 小时前 → 下次打开显示"上一次已自动收尾，码是 XXXXXX"；同一天再读看板，码不变（幂等）。
6. 不带票直接打 `/api/report?sessionId=…`（用别人的 id）→ 401/403，不是 200。
7. 老批次数据：看板选一个历史日期 → 老记录在流水里出现，来源标"历史"，没有码。
8. `npm test` 全绿（含新增契约用例）。

## 9. 分阶段与工作量

| 阶段 | 内容 | 量级 |
|---|---|---|
| 1 | 存储端口扩四个方法 + 三驱动实现 + 单测 | 半天 |

## 10. 我替你定的（可推翻，推翻任何一条都只影响一小块）

1. **一次使用 = 一次打开（`visit`），不是一道题**。同一次打开里做三道题，仍然只有一个码，看板上是"一次使用里含 3 个会话"。理由：`本次使用` 这句话本身是"这一次坐下来"；按题发码会让一个学生一次坐下来拿到三个码，抄码的张数直接翻三倍。
2. **收尾页只放码 + 概况，不放完整报告**。完整报告在使用中（产品页第 4 页）就能看；结束是终态（你选的 Q5 c），结束之后再把产品页挂起来看报告，等于把"终点"又打开了一次。收尾页给的是「再开一次」。
3. **完成码永不过期**。老师的动作可能隔几天才做，会过期的码是没用的码。
4. **宽限期 2 小时**。比"最后一次操作"计，不是比"开场"计。
5. **「退出」按钮改名为「结束使用」**，并且带二次确认 —— 误触的代价是"这一次结束了，码作废"，比多点一次贵得多。
6. **`LLM_DAILY_TURN_CAP` 默认空（不限）**。你的决定是不设上限；这个变量只是保险丝，不改默认行为。
7. **学生登录分支直接删，不留在开关后面**。留在开关后面等于同时维护两套身份，迟早有人把开关打开。
