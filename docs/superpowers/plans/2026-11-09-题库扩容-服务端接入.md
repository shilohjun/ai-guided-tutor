# 题库扩容 · 服务端接入 实施计划（简版）

> **这份计划是里程碑级的。** 每个里程碑开工前，由执行的人展开成任务级步骤（先写失败的测试 → 再实现 → 跑通 → 报错更早暴露）。里程碑之间的依赖在表里标了。
>
> **纪律（沿用仓库既有约定）：** 未经明确指令不 `git commit`、不 `git push`；每步停在工作区可见的状态。

**Goal:** 题库从「152 道内联在 `public/` 里的 JSON」变成「服务端按 id 与标签检索、可承载 3 万道的只读资产」，学生端与教师端看到的内容不变。

**Architecture:** 题目数据三类分三处——题面与图片进对象存储+CDN，轻索引进服务端内存，教法资产（图谱/指纹/答案/解析）留私有存储只走服务端。函数只做路由、投影、取数据，不再携带题目内容。

**Tech Stack:** Node ≥20、零依赖、现有 `router.js` 与 `registry.js`；腾讯云 CloudBase 云函数（512 MB / 30 s / 无 npm 依赖）+ 对象存储。

**设计依据:** `docs/13-题库双轴选题-数据面与管线.md`（离线四阶段管线的原始设计）、`docs/题库地图-交接文档.md`（现状与已知欠账）。

## 全局约束

- **零依赖**：`package.json` 的 `dependencies` 保持 `{}`，`installDependency: false` 不动。对象存储访问用 `node:crypto` 手写签名，不引 SDK。
- **函数包不带题目内容**：`scripts/build-cloudbase.mjs:61` 会把整个 `public/` 打进函数包，任何进入 `public/` 的数据都等于进了包体。
- **答案与解析永不出服务端**：`toStudentProblem`（`src/server/router.js:285`）是唯一出口，新增字段一律加白名单，不加黑名单。
- **文件行尾必须 LF**：`test/settings.test.js` 按 `\n` 匹配 CSS，CRLF 会直接挂。
- **用例数同步**：`test/run.js` 的 `suites` 数组要加新套件；README 里「当前注册 N 个用例」必须等于真实总数（`test/docs.test.js` 会核对）。
- **改完 `public/index.html` 必跑** `node test/run.js` 与 `node scripts/audit-ui-style.js`（字号只允许 13/15/17，padding 只允许 2/4/6/8/12/16/24/32）。

**基线：** `node test/run.js` = **340/340 通过**（2026-11-09 实测）。

## 一、为什么必须现在改（数字）

| 事实 | 数值 | 出处 |
|---|---|---|
| 152 道题目前的题面资产 | `public/qbank/q/` **14.37 MB**，96 KB/道，八成以上是内联 base64 图片 | 实测 |
| 这些文件去了哪 | 被 `build-cloudbase.mjs:61` 整个打进函数包 | `scripts/build-cloudbase.mjs` |
| 3 万道按同密度 | **≈ 2.9 GB** | 推算 |
| 函数上限 | 512 MB 内存 / 30 s 超时 / 无依赖 | `cloudbaserc.json` |
| 现在一道真题怎么"被教" | 点题 → 题干文本塞进输入框（`public/index.html:3693` `landPickedQuestion`）→ `/api/problem/import`（`src/server/router.js:640`）现场调模型读题 | 实测 |

结论：**接入几万道题的本质不是"加一个接口"，是把题目数据从函数包里搬出去、把检索收进服务端、把图谱变成离线资产。**

## 二、目标与非目标

**目标（可验收）**

1. 3 万道题能在服务端被**检索**：按知识点/思路/题型/难度/省份筛选 + 游标分页，单次响应 < 4 KB。
2. 3 万道题能被**选中并进入五页流程**，不需要前端整包下载题库。
3. 每道题有 `teachStatus`，前端据此决定「开始学」能不能点。
4. 函数包体积 **< 5 MB**，与题库规模无关。
5. 学生投影里 grep 不到图谱、答案、解析、指纹。

**非目标（本期不做）**

组卷、错题本、教师端布置作业、多学科（只物理）、题库后台编辑、题面改成可渲染 LaTeX（另案）。

## 三、目标形状

```
                    ┌──────────────── 学生端（public/index.html）
                    │  只拿：轻索引分页结果 + 题面 URL
                    ▼
   /api/qbank/*  ── router.js ──► src/core/qbank/
                    │               ├ index.js        轻索引：筛选/分页/计数
                    │               ├ store.js        唯一碰存储的地方（adapter）
                    │               └ projection.js   学生投影白名单
                    ▼
        ┌───────────────┬──────────────────────┬─────────────────────────┐
        │ 轻索引         │ 题面 + 图片            │ 教法资产                 │
        │ 内存驻留        │ 对象存储 + CDN         │ 私有存储，按 id 取         │
        │ ~8–12 MB       │ 题面 JSON + 图片文件     │ 图谱/指纹/答案/解析/LaTeX  │
        └───────────────┴──────────────────────┴─────────────────────────┘
                              ▲                        ▲
                              └──── 离线管线（本机跑，不在函数里）────────┘
```

`store.js` 只暴露四个函数，实现可换（本地目录 / 对象存储 / 云数据库），上层不动：

```js
loadIndex()            // 轻索引，进程内缓存 + 版本号
search(filter)         // 标签筛选 + 游标分页
getProblemAsset(id)    // 题面（题干/选项/图片 URL）
getTeachAsset(id)      // 图谱/指纹/答案/解析
```

**M0–M4 不需要等那几万道题的源数据**——用现有 152 道当试点，把服务端建起来，M5 只是换输入。

### M0 · 冻结数据契约

**产出**
- `docs/qbank-契约.md`：一张字段表（必填/选填/来源/示例），定住 `id, 题干(三种形态), 选项, 答案, 解析, kg[], think[], 题型, 难度, 省份, 来源, 图片引用[], teachStatus`。
- `scripts/qbank/normalize.mjs`：任意源 → 上面的 JSONL。第一版先用现有 `public/qbank/q/*.json` 当输入，做**往返一致**（normalize 能吃掉自己）。
- `docs/qbank-覆盖报告.md`：答案覆盖率、解析覆盖率、公式图张数、题均图片数。

**验收**
```bash
node scripts/qbank/normalize.mjs --in public/qbank/q --out .qbank-out/norm.jsonl
# 期望：152 lines，必填字段缺失 0
```

**闸门**：如果源数据的「解析覆盖率」< 60%，M6 的策略必须改（没有官方解析就只能让模型自己解，图谱质量与可审性都下降）——这个数出来之前不要排 M6。

### M1 · 图片出包（试点 152 题）

**产出**
- `scripts/qbank/put-assets.mjs`：把 base64 图片落成文件、上传对象存储、回写 URL。
- `src/core/qbank/store.js` 的两个 adapter：`local`（读 `public/` 或本地目录，开发和测试用）与 `cos`（生产）。同一份合同，`store.js` 之外没有人知道用的是哪个。
- 题面 JSON 里 `stemHtml` 的 `<img src>` 从 `data:` 换成 URL。

**验收**
```bash
node scripts/qbank/put-assets.mjs --sample 20
# 期望：20 题的图片 URL 全部 HEAD 200，题面 JSON 总体积下降 > 80%
```

**回滚**：旧的内联文件仍在 `public/qbank/q/`，切换只改 `store.js` 的 adapter 选择。

### M2 · 数据访问层 + 索引 + 测试套件

**产出**
- `src/core/qbank/store.js`（4 个函数，两个 adapter）
- `src/core/qbank/index.js`（筛选/分页/计数；索引结构见 `docs/qbank-契约.md`）
- `src/core/qbank/projection.js`（学生投影白名单）
- `scripts/qbank/build-index.mjs` → `.qbank-out/index-v1.json`（带 `version` 与 `count`）
- `test/qbank.test.js`：至少 6 个用例——筛选命中数、游标分页不重不漏、`teachStatus` 过滤、投影不含图谱/答案、索引版本号、空结果不报错。
- 改 `test/run.js` 的 `suites` 加 `'qbank'`；同步 README 的用例数。

**验收**

**分页约定**（写进契约，M3 直接用）：`cursor` = 上一页最后一条的排序键的 base64；无 `cursor` 从头发。**不用 offset**——3 万条翻深页会扫表。

### M3 · 五个接口 + registry 查询链

**接口**（全部加在 `src/server/router.js`，紧挨现有 `/api/problems:514`）

| 接口 | 返回 | 约束 |
|---|---|---|
| `GET /api/qbank/taxonomy` | 两棵树 + 计数 | 公开 |
| `GET /api/qbank/search` | `{ total, nextCursor, items[] }` | 公开，item 只有轻索引字段 |
| `GET /api/qbank/problem/:id` | 学生投影 + 图片 URL | 公开，禁图谱/答案/解析 |
| `GET /api/qbank/related` | 同类题 + `reason` | 公开 |
| （内部）`getTeachAsset(id)` | 图谱/指纹/答案/解析 | 不出 HTTP，只给 registry |

**改** `src/core/registry.js:77` 的 `getProblemById` 查询链：**bank → 手写 → 导入**。题库不进 `imported` Map（不吃 TTL、不占 200 条上限）。

**验收**
```bash
node test/run.js
# 期望：全绿，且新加的防泄题用例通过：
#   遍历 search 与 problem/:id 全部输出，序列化后 grep 不到 officialAnalysis /
#   referenceAnswer 正文 / 任一 cues / 任一 solutionInsights / stemLatex
```

### M5 · 3 万道灌库（等源数据）

**产出**
- `scripts/qbank/ingest.mjs`：normalize → 上传图片 → 分批写索引 → 打版本号。
- 发布方式：索引文件按版本命名（`index-v{n}.json`），服务端启动读版本号；**灰度与回滚就是切版本号**，不重新部署。
- 报告：题量、字段缺失率、图片上传失败清单、索引体积、冷启动读取耗时。

**验收**
```bash
node scripts/qbank/ingest.mjs --check
# 期望：抽样 50 道，题干/图片/标签/答案 逐项对得上；失败 0
```
并且：`/api/qbank/search` 打 100 次，P95 < 200 ms。

### M6 · 图谱批量生成（离线队列）

**产出**
- `scripts/qbank/generate.mjs`：按 `id + 输入内容哈希` 幂等，支持 `--only/--module/--limit/--concurrency`，断点续跑，失败写回 `teachStatus=failed` 不中断整批。
- 分级策略（**默认**）：先给「高频知识点 + 有官方解析」的题生成到 `reviewed`；海量长尾停在 `none`，走现在这套运行时读题。
- 抽样审核清单：随机 20 题，看步骤顺序与官方解析一致、`cues` 是关键词不是整句、不含答案数值。

**验收**
- `teachStatus` 分布报告 + 抽检 20 题通过率 ≥ 80%。
- 抽 10 题做「教得动」端到端：命中的步号 ≠ 1、提示等级 ≤ 2、回复不含答案数值。

### M7 · 清理

**产出**：删 `public/qbank/q/`（14.37 MB）、`public/qbank/data.json`、`map.html` 的内联数据；`build-cloudbase.mjs` 不动，包体自然瘦下来。

**验收**
```bash

# 期望：dist-cloudbase/bubujie-api 总体积 < 5 MB（现在仅 qbank/q 就 14.37 MB）
```

## 五、需要你拍板的三件事

| # | 问题 | 不定的后果 | 我的建议 |
|---|---|---|---|
| 1 | **那几万道题现在是什么形态**（文件/库/接口），有没有参考答案与解析，公式是图片还是 LaTeX | M0 写不出来，M5/M6 无法排期 | 先给 3 道样例，我把契约按真实字段写 |
| 2 | **存储选哪条**：甲 对象存储+CDN+函数内索引（零依赖）/ 乙 CloudBase 云数据库 / 丙 自建 Postgres | `store.js` 的 adapter 写哪两个 | **甲**。只读题库 + 标签筛选，甲能到 95%，且守住零依赖 |
| 3 | **图谱覆盖策略**：全量生成 / 分级（推荐）/ 只做运行时 | M6 的成本差一个数量级 | **分级**：先让 3 万道都能选，再让值得教的几千道能教 |

## 六、风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 源数据没有解析 | 图谱只能靠模型自己解，质量不可审 | M0 的覆盖率报告是闸门；不够就走「只选题不教」降级 |
| 图片量比 152 题更大 | 对象存储与 CDN 成本、上传耗时 | 上传前统一压到长边 800、webp；报告里给总量 |
| 索引体积超过函数内存预算 | 冷启动慢 | 索引只放轻字段（题干截断 80 字）；超 20 MB 就切云数据库（乙） |
| 前端一次性切换引入回归 | 选题流程挂掉 | M4 保留 `?bank=legacy` 开关，一个变量切回 |
| 未提交、多里程碑并行 | 工作区互相污染 | 一里程碑一目录产物的 `--out` 隔离；不 commit 但每步留可运行状态 |

## 七、不做什么

- 不做组卷、错题本、教师布置作业（`PRODUCT.md` 的 anti-goals）。
- 不做题库后台编辑器——本期题目是只读资产。
- 不改题面的公式渲染（`⟨式⟩` 占位仍在，KaTeX 是另一件事）。
- 不动 `public/qbank/map.html` 的地图形态，只换它背后的数据来源。
