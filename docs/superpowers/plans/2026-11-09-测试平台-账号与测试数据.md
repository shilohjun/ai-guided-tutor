# 测试平台 · 测试账号与测试数据 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给步步解建一个国内可直达、会话不丢、按批次量化的试用站：一人一账号、四页漏斗可算、单条与整批可导出、OCR 与模型用量有硬上限。

**Architecture:** 在现有零依赖 Node 应用上加三层——①`src/server/store/`（端口 + memory/file/cloudbase 三驱动，云 SDK 懒加载，本地与 CI 不装）；②鉴权与事件（`auth.js` / `events.js`，挂在 `demo-gate.js` 已有的请求上下文上）；③只读的度量与导出（`metrics.js` / `export.js` / `admin.js`，纯函数优先）。前端只改 `public/index.html`（登录、开场说明、题单条、续做条、埋点）并新增 `public/admin.html`。

**Tech Stack:** Node ≥ 20（`node:crypto` / `node:zlib` / `node:fs` 内置）、原生 `http`、CloudBase 云函数 + 云开发数据库、自研测试运行器（`test/runner.js`）。

**Spec:** `docs/superpowers/specs/2026-11-09-测试平台-账号与测试数据-design.md`

## Global Constraints

- **零运行时依赖**：根 `package.json` 的 `dependencies` 必须保持 `{}`。云 SDK 只允许出现在 `dist-cloudbase/bubujie-api/package.json` 里，源码中一律用动态 `import()`。
- **`npm test` 离线可跑**，新套件必须注册进 `test/run.js:10` 的 `suites` 数组。
- **`test/docs.test.js` 会核对 README 里的用例数**（`totalRegistered()`）。每个新增用例的任务，最后一步都要把 `README.md` 里那个数字改成实际值，否则套件会红。
- **时间戳一律 `new Date().toISOString()` 的形状（UTC，24 字符，带毫秒与 Z），由服务端生成**。客户端时钟不可信，不得用前端时间做排序或时长计算。
- **CSV 导出必须 UTF-8 带 BOM**（`\uFEFF`），否则 Excel 打开是乱码。
- **导出与看板不得出现参考答案/解题路径**，只允许出现学生当时看到的那份报告快照。
- **试点只跑 CloudBase**；`api/index.js` 与 `api/worker.js` 保持可用，但强制 `STORE=memory` 且 `/api/admin/*` 一律 401。
- **界面文案中文**，不出现英文报错串；错误必须带可操作的一句话。
- **四页**：`PAGES = ['题目','方式','解题','报告']`，`setPage(5)` 别名到 4。任何"第 5 页"的写法都是错的。

## Review Focus

这五类输入/条件，规格里只是隐含，但最可能让真实用户踩到。每一条都在下面某个任务的测试里钉住。

1. **同一台电脑换账号** → 前一个人的 token、续做条、看板数据不能被他看到。一个人用家里共用电脑是常态，这是数据串号最快的一条路。（Task 2、4、10）
2. **弱网下的埋点** → `/api/events` 失败不得阻断对话、不得弹错、不得让页面白屏。学校的网比你测的时候差。（Task 3、10）
3. **客户端时钟不可信** → `page_exit` 经常发不出来（手机上切走、进程被杀），掉点必须能只靠 `lastEventAt` 算出来。（Task 3、5）
4. **6 位数字只有 100 万种** → 不做失败次数限制，一个脚本能把全班账号枚举出来。6 位数的可读性是用低熵换的，必须配一道闸。（Task 2）
5. **空批次 / 零题 / 单人** → 看板不能出现 `NaN`、`Infinity`，也不能把"只有一个人"算出"最大掉点是第 1 页"这种假结论。（Task 5、9）

### Task 2: 账号、口令与登录限速

**Files:**
- Create: `src/server/auth.js`、`scripts/issue-accounts.mjs`

- Test: `test/auth.test.js`、`test/run.js`

**Interfaces:**
- `hashCode(code, salt?) → { codeHash, salt }`（`scryptSync(code, salt, 32)`，`salt` 16 字节 hex）
- `verifyCode(code, user) → boolean`（定时安全比较，复用 `demo-gate.js` 的 `safeEqual` 思路）
- `issueAccounts(store, { batchId, count, prefix = 'S', start = 1 }) → Promise<[{ displayName, code }]>`，`displayName` 形如 `S01`
- `login(store, code, ip, now = Date.now()) → Promise<{ token, user, expiresAt } | null>`；`token` 32 字节 hex，库里只存 `sha256(token)`
- `resolveToken(store, token) → Promise<{ user, batchId, expiresAt } | null>`
- `checkLoginRate(ip, code, now) → 'ok' | 'code_locked' | 'ip_locked'`；`noteLoginFailure(ip, code, now)`；`noteLoginSuccess(ip, code, now)`（**只清该 (ip, code) 对**）
- 两维限速：`(ip, code)` 15 分钟内 5 次；`ip` 60 分钟内 60 次，成功不清零 IP 维；`'unknown'` 不参与 IP 维锁定（**这是 R17 裁定后的形状，取代了本计划初稿的「单维 per-IP + 成功清零」，理由见账本**）
- `TOKEN_TTL_MS = 60 * 24 * 60 * 60 * 1000`
- HTTP：`POST /api/auth/login {code}` → `200 {token, displayName, batchId, expiresAt}` / `401 {error:'口令不对'}` / `429 {error:'试太多次了，15 分钟后再试'}`
