# 读题与视图隔离（本轮新增的两条链路）

> 本文档对应 2025-11 的一次能力升级。它回答两个问题：
> **① 学生拿来一道题库里没有的题，引擎怎么"看懂"它？**
> **② 为什么教师能看到的东西，学生一定拿不到？**

---

## 一、读题链路：任意题目文字 → 结构化题目

### 1.1 它补的是哪个缺口

在题库时代，引擎的可靠性建立在"教研手写的图谱"上：

```
题库（problems.data.js）     教研手写：路径 / 前提 / 错因 / 答案指纹
        ↓
     引擎（route + guard）    拿图谱当基准，判断学生走到哪一步、该给几级提示
```

这套结构有一个致命的适用性上限：**学生拿来的题 99% 不在题库里**。
于是"能不能现场读懂一道没见过的题"就成了产品能不能用的分界线。

读题链路（`src/core/intake.js`）就是补这一环：

```
题干原文（学生粘贴）
        ↓
   LLM 读题（INTAKE_SYSTEM_PROMPT）
        ↓
   归一化 + 校验（normalizeIntake）
        ↓
   与题库题**完全同构**的 Problem 对象
        ↓
   registry 登记 → 之后走与题库题一模一样的 route + guard
```

关键设计：**读题的产物与题库题同构，因此下游一行代码都不用改。**
引擎不认识"导入题"这个概念（只在学生版判断链路里加一句"读题"），
守卫也不认识 —— 它只认 `answerFingerprints` 这些字段。

### 1.2 三条红线

**红线 ①：解题路径对学生隐藏。**
学生看到的只有题干原文 + "我已经读完了"。路径只用于引擎判断位置。
实现方式是**服务端白名单投影**（见第二节），不是前端隐藏。

**红线 ②：题目必须带指纹，否则守卫对它等于不存在。**

守卫（`guard.js`）是拿 `Problem` 当基准做比对的：

| 指纹字段 | 拦什么 | 缺失的后果 |
|---|---|---|
| `answerFingerprints` | 数值答案 | 说出"20 m/s"不会被拦 |
| `formulaFingerprints` | 解法公式 | L1 里写 `E = BLv` 不会被拦 |
| `solutionInsights` | 把结论说破（"r 是内阻"） | 用合规的方式把答案递过去 |

所以 `normalizeIntake` 对这三项做三道兜底：

1. 模型给的 → 清洗（丢掉编译不过的、丢掉过泛的）
2. 从 `referenceAnswer` 反推（数值 + 单位 → 正则）
3. 仍然缺失 → **记 warning**，并在教师视图里显示出来

第 3 条很重要：**"没指纹"必须是可见的，不能静默降级。**
否则教研会以为这套系统对所有题目都有防泄题能力。

**红线 ③：读不懂就降级，不装作读懂了。**

| 情况 | 行为 |
|---|---|
| 适配器没有读题能力（离线规则桩） | 退到"通用六步骨架" |
| 模型调用失败 | 同上，并把错误原因写进 warnings |
| JSON 解析失败 / 结构不合法 | 同上，并逐项记录被修正的地方 |
| 题干 < 8 字 | 直接拒绝（不做无意义的读题） |

降级骨架是诚实的弱能力：它只抽已知量与待求量，路径是通用六步，
定位精度明显低于真模型读题 —— 这句话**逐字写在返回给前端的 notice 里**。

### 1.3 归一化在防什么（都是真实踩到的）

| 模型常见坏输出 | 归一化动作 | 不修的后果 |
|---|---|---|
| 步骤号从 0 起 / 跳号 | 重排为 1..n | 定位与报告的分母全错 |
| 末步 kind 写成 `apply` | 强制为 `conclude` | 引擎永远不认为学生"接近完成" |
| `kind` 拼错（`thinking`） | 落回白名单 | `route` 的按步派发整条失效 |
| 步骤没有 `cues` | 从标题/概念派生补齐 | 关键词定位通道对这一步永久失效，双通道退化成单通道 |
| 改写了题干 | **丢弃**，用学生粘贴的原文 | 学生看到的题和他手里的题不是同一道 |

### 1.4 答案指纹的两个真实事故（已固化为测试）

**事故 A：题干里的数值被当成了答案。**

模型把题干"落地前 1 s 内"里的 `1 s` 写进了 `answerFingerprints`。
后果：引擎连念题目里的那 1 秒都算泄题，**所有提示被拦成兜底模板**。
表现形式不是"泄题"，而是"AI 又笨又啰嗦"—— 这类故障比泄题更难被发现。

修复：`dropFingerprintsMatchingStem()`。
判据很短但极有效：**一个能匹配题干的指纹，不可能是这道题的答案。**

**事故 B：题干的"小问编号"被当成了已知量。**

题干"求：(1) ……；(2) 最后 1 s 内的高度"里的 `2`，
被"抽取题干所有数字"的逻辑当成已知量，于是"2 s"这条指纹被误放行。
修复：`stripEnumerators()`（注意必须放过小数，不能把 `0.5` 吃掉 `0.`）。

### 1.5 读题会用到什么、成本多少

| 项 | 值 |
|---|---|
| 调用次数 | 1 次（`max_tokens: 4000`） |
| 实测耗时 | 5~15 秒（deepseek-chat，7 步图谱） |
| 落库位置 | `src/core/registry.js`（内存，TTL 6 小时，上限 200 道） |
| 题目 id | 题干内容哈希 `imp-xxxxxxxx` |

**为什么 id 用内容哈希而不是随机串：**
同一道题被粘贴两次应该命中同一张图谱；
serverless 冷启动把注册表清空后，重新导入会得到**同一个 id**，前端不需要知道发生过回收。

## 二、视图隔离：学生视图 / 教师视图

### 2.1 之前的做法是错的

升级前，`/api/chat` 把 `diagnosis.teacherView`（错因标签、证据原话、完整 trace）
和学生消息**一起**返回，靠前端一个 checkbox 决定显不显示。

那是"前端不显示"，不是"学生拿不到" —— 打开 F12 就能看到。

### 2.2 现在的做法：服务端白名单投影

```
GET /api/problem?id=xxx        → toStudentProblem()   无路径名、无指纹、无参考答案
POST /api/chat                 → buildStudentTurn()   无错因、无置信度、无 rationale、无守卫细节
GET  /api/report?sessionId=    → 学生自己的学习报告

GET  /api/teacher/problem      → toTeacherProblem()   完整图谱 + 参考答案 + 三组指纹
GET  /api/teacher/session      → 逐轮复盘 + 完整 trace + 被拦下的片段
GET  /api/teacher/overview     → 跨会话的卡点分布与帮助强度
                                   ↑ 全部需要 TEACHER_KEY
```

**为什么用白名单而不是"给教师数据打码"：**

打码依赖"记得打哪里"，每加一个字段都要重新审一遍，漏一处就是泄题；
白名单依赖"允许说什么"，漏一处只是少说一句话。
这和守卫用**封闭词表**而不是黑名单，是同一条思路。

### 2.3 教师视图的三种形态

**本地默认不用口令，点一下就能进。** 形态由**部署形态**决定，不由"有没有配口令"决定：

| 形态 | 触发条件 | 行为 |
|---|---|---|
| `open` | 本地运行，`TEACHER_KEY` 留空 | 教师视图直接进 |
| `key` | 配了 `TEACHER_KEY` | 必须带对口令；不带口令一律 401 |
| `off` | 公网部署（`api/index.js` 强制置位），且没配口令 | 教师视图整体关闭（403） |

```js
// src/server/router.js
export function teacherMode() {
  if (readTeacherKey()) return 'key';
  if (String(process.env.DSH_FORCE_TEACHER_LOCK ?? '') === '1') return 'off';
  return 'open';
}
```

**为什么要有 `off` 这一档，而不是"没配口令就一律开放"：**

教师接口返回的是**完整解题路径 + 参考答案 + 答案指纹**。
如果"没配口令 = 开放"这个默认值跟着代码上了 Vercel，
那份公开链接就等于把答案挂在网上 ——
而这恰恰是最容易发生的疏忽：本地跑得好好的，部署时没人会想起来"还得去配个口令"。

所以默认值由**部署形态**决定：

```
server/server.js（本地）       → open
api/index.js（Vercel / 公网）  → off，除非显式配了口令
```

这条规则写在代码里，不依赖部署时"记得"。
确实要在公网开教师视图，就配 `TEACHER_KEY`，`off` 不会生效。

其它细节：

| 项 | 值 |
|---|---|
| 来源 | 环境变量 `TEACHER_KEY`（`.env`，不入版本库） |
| 传递 | 请求头 `x-teacher-key`（前端只在打 `/api/teacher/*` 时注入） |
| 比较方式 | 定长逐字符异或（避免 `===` 的短路比较） |
| 前端存放 | `sessionStorage`（关标签页即失效，不落盘） |

> 三档形态各自有断言守着（`test/ui.test.js` 的「视图隔离 · 教师端点鉴权」）。
> 其中一条专门检查 `api/index.js` 里那段强制锁死逻辑还在不在 ——
> 它是"部署时忘了配"的唯一防线，删掉不会有任何报错，只会静默把答案挂上公网。

### 2.4 学生视图刻意不显示的东西

学生对话页里**没有**"防泄题护栏"面板、没有"守卫拦截 N 次"、没有"答案泄漏"统计。

理由：那是我们的工程内控，不是学生的学习内容。
学生需要的反馈是"我在看你的思路 / 你现在在哪 / 你需要回答什么"。

于是学生版判断链路（`buildStudentEnginePath`）只说这几件事：

```
读题   → 把这道题的条件与目标理清了
听懂   → 我抓到了你提到的「求导、令导数为零求驻点」
定位   → 按你说的话，你大概走到第 1 步（共 6 步）
决定   → 我在问你一个前提
成文   → 把它写成一句你能直接回答的话
复核   → 换了一种问法，让它更贴近你现在的进度   （仅在真的发生过重写时出现）
```

它**不**包含：错因标签、定位置信度数字、层级策略名、守卫违规类型、
路径名与步骤标题（那等于把解法告诉学生）。

`test/ui.test.js` 里有断言守着最后这条：学生版判断链路里不允许出现这些词。

### 2.5 这个隔离是可以被验证的

```bash
# 不带口令：401
curl -i http://127.0.0.1:5173/api/teacher/problem?id=phy-emi-01

# 带口令：完整图谱 + 参考答案
curl -H "x-teacher-key: $TEACHER_KEY" http://127.0.0.1:5173/api/teacher/problem?id=phy-emi-01

# 学生接口里根本不存在这些字段
curl -s http://127.0.0.1:5173/api/problem?id=phy-emi-01 | grep -c solutionGraphs   # 0
```

后端测试（`test/intake.test.js`）里也有一条：
把学生版判断链路的 JSON 全串起来，断言其中不存在 `precondition_gap` / `confidence` / `错因` / `守卫` / `指纹`。

## 三、引导语言：voice 关

守卫保证"不说答案"，**voice 关保证"说的是有用的话"**。
两者都是确定性的，都不依赖模型自觉。

### 3.1 提示词层的三条硬约束（`DRAFT_SYSTEM_PROMPT`）

1. **一次只问一个问题** —— 出现两个问号就是失败（学生不知道该先回答哪个）
2. **不评判** —— 不出现"错""不对""不严谨"；要指出问题就说"值得再确认一下"
3. **至少引用一个学生自己说过的词或题干的量** —— 空话（"再仔细想想""注意审题""加油"）明令禁止

### 3.2 代码层：`polishVoice()`（`src/core/prompt.js`）

| 动作 | 说明 |
|---|---|
| 删除空话与空洞鼓励 | "加油""相信你可以的""这题不难"等，连所在小句一起删 |
| 收敛重复标点 | `？？` → `？` |
| 标记"一句话问了两个问题" | **不擅自改写**（会破坏语义），只报出来给教师视图 |

为什么不自动删掉多余的问句：很容易把"先确认 A，再想想 B？"改成一句没有落点的陈述句。
宁可如实记录，也不做会改变语义的自动改写。

### 3.3 一个被修掉的静默 bug

真模型适配器的 `draftHint` 原本只返回 `parsed.text`，
而引擎的 `draftWithMeta` 按"字符串 ⇒ 尝试 JSON.parse"的约定解析 ——
结果真模型路径下 `nextAsk` 与 `concepts` **永远是空的**。

学生看到的是通用收尾句"【下一步】检查这个规律的前提"，
而模型其实已经给了更贴合的那一句。这个 bug 不报错，只会让提示变差。

### 3.4 另一个被修掉的静默 bug：重试路径从不发生

README 一直写着"模型最多重试一次；两次都不过就用安全兜底模板"，
但代码在第一次被拦下时就采用了守卫重写的结果 ——
于是"重试"这条路径几乎从不执行，学生反复收到万金油模板。

现在的策略按违规类型分流：

| 守卫重写策略 | 含义 | 处理 |
|---|---|---|
| `strip-equation` / `truncate` | 只删掉了越界片段，模型的说法还在 | **直接采用**（更快、也更贴学生） |
| `safe-template` | 整句被换成了通用模板 | **把拦截原因带回给模型重试一次**，两次都不过才用模板 |

## 四、怎么验证这一轮的东西

```bash
node test/run.js           # 123 个用例（新增 26 个：读题 20 + 前端契约/保密 6）
node scripts/eval.js       # 离线评测：安全指标必须全 0
node scripts/eval.js --adapter llm   # 真模型评测（结果见 share/评测报告_DeepSeek.txt）
node server/server.js      # 打开 http://127.0.0.1:5173
```

`test/ui.test.js` 守的两类问题，都是"只有到浏览器里才会炸"的：

- **DOM 契约**：`app.js` 里 `$('#xxx')` 引用的每个 id，`index.html` 里必须存在。
  写错一个字母不报错，只是"点了按钮没反应"——现场演示时才发现。
- **密钥不外泄**：`.env` 里的 API Key 与教师口令，
  不允许出现在任何会被提交 / 会被部署的文件里，
  并且兜底扫描任何形如 `sk-…`（20 位以上）的字面量。

## 五、解析层：原题 ⇄ 解析

### 5.1 它产出什么

`src/core/analysis.js`。**题库题与导入题目走同一条代码路径** ——
题库题没有模型给的解析，就全部按题干与图谱派生；
导入题有模型给的，封闭表只负责补齐它漏的。
这样"解析面板"对任何题目都成立，不会变成只有导入题才有的功能。

| 字段 | 内容 | 来源 |
|---|---|---|
| `variables` | 已知量拆成 `符号 / 值 / 单位 / 它是什么`；待求量单列 | 题干派生 + 模型补充 |
| `keyConditions` | "一句话改变整道题"的条件 + 它为什么重要 | 封闭表 `CONDITION_MARKERS` + 模型 |
| `knowledgeGraph` | 知识点、先后关系、哪些是本题核心 | 模型 + 派生（标 `derived`） |
| `summary` | 这道题在问什么（一句话） | 模型 + 派生 |

条件标记表是**封闭表**而不是让模型自由发挥：
"哪些词算关键条件"是一个可审计的判断 —— 教研看到这张表就能说
"这条该加""这条不该算"，改起来没有歧义。目前覆盖力学 / 电路 / 数学三类共 18 条标记。

### 5.2 两条判据：解析什么时候算"剧透"

「匀速 ⇒ 合力为零」既是**最该讲的解析**，也是**本题的答案**。
所以每条条件都算一个 `reveals`：

| 判据 | 抓什么 | 例 |
|---|---|---|
| ① 结论型 | 命中 `solutionInsights` / `formulaFingerprints` —— **与守卫同一套指纹** | "匀速 ⇒ 合力为零" |
| ② 前提型 | 命中**只存在于解题步骤里的说法**（步骤标题 / 定位关键词 / 路径前提） | "切割式要求 B、L、v 两两垂直"（"两两垂直"是第 3 步的 cue） |

判据 ① 用守卫的指纹，是为了避免"解析里能说、提示里不能说"的口径矛盾。

**判据 ② 是测试逼出来的。** 一开始只做了 ①，结果
`test/analysis.test.js` 的反向断言（学生载荷里不许出现步骤 cues）当场失败。
前提型泄漏比结论型隐蔽得多：说破"结论"容易被发现，
说破"该检查什么"看起来只像是在讲课。

修好之后，那道题的 5 条条件里有 2 条被正确标记为会剧透
（「匀速」「方向/几何关系」），学生看到的是提问而不是结论。

### 5.3 学生图谱为什么只放 topics

`steps[].concepts` 就是解法本身。实测漏过一次：
早期把 concepts 汇总成 `conceptTags` 发给学生，而那道题的概念里有
「电源与内阻」「匀速直线运动合力为零」，**恰好就是本题的两个 `solutionInsight`** ——
等于把答案印在题目下面。

现在：

| | 节点 | 边 |
|---|---|---|
| 学生图谱 | 只有 `problem.topics` | 前置 / 相关 |
| 教师图谱 | topics + concepts（挂在所属步骤上） | 同上 |

`test/analysis.test.js` 用**反向断言**守着这条：
学生版解析的 JSON 里不许出现任何步骤标题 / 只存在于解法里的 cue / intent / 路径名 / 路径前提。
反向断言比正向断言可靠 —— 正向断言（"应该有 3 个节点"）会随数据变化失效，
反向断言只要泄题就一定会失败。

### 5.4 知识图谱的两种渲染

| 形态 | 用在哪 | 为什么 |
|---|---|---|
| 分层列表（HTML） | 学生侧窄栏 | SVG 会被等比缩放到容器宽度，文字缩到 8px 还重叠 —— 图谱退化成装饰 |
| 节点图（SVG） | 教师侧整屏 | 有空间画真实节点关系，还能显示"这个概念出现在第几步" |

同一份数据、两条渲染路径，所以不会出现"学生看到的和教师说的不一致"。

## 六、界面设计系统

### 6.1 取向

NotebookLM 的**分区与留白** ＋ Duolingo 的**手感与反馈**，但克制 ——
这是给中学生和教研用的工具，不是游戏。

### 6.2 四条规则（改样式前先读）

1. **每种颜色只有一个职责。** 主色 = 可点击/当前；绿 = 已经做到；琥珀 = 需要留意；
   红 = 会出错的地方。不为了好看增加第四种语义色。
2. **信息层级靠字号 / 字重 / 留白，不靠颜色。** 颜色一多，界面就变成仪表盘。
3. **所有"能按的东西"必须有按下反馈**（下沉 2px + 底部厚边收窄）。
   这是 Duolingo 那套里最值得抄的一条，它让界面显得"活"。
4. **动效只用来解释状态变化**，不用来装饰，且全部在
   `prefers-reduced-motion` 下退化为"直接显示"（不是变慢，是关掉）。

### 6.3 功能分区

```
左：题目与解析（数据）   中：对话（互动）        右：我的状态（反馈）
「原题 / 解析」开关      模式开关（自主/陪伴）    我读懂了什么
关键变量                 消息流                  我会怎么帮你（层级阶梯）
关键条件（含剧透标记）     输入区                  引擎判断链路
知识图谱                 ───────────            演示剧本
                      引擎这一轮怎么想的
```

三栏在 1440px 以下收成两栏（右侧状态区移到下方横排），1180px 以下收成单栏。

### 6.4 十二条微交互

按钮按下下沉 / 消息上浮入场 / 进度条弹性填充 / 读题骨架 /
知识点逐条入场（55ms 步进）/ 「我读懂了什么」逐条左滑（70ms 步进）/
层级阶梯点亮脉冲 / 原题解析滑块 + 交叉淡入 / 图谱节点逐个放大 /
知识点就地展开 / 卡片 hover 抬升 / Toast 弹入。

### 6.5 深链接

为了让演示能"打开就是某个状态"，支持 URL 参数：

```
?problem=phy-emi-01&pane=parsed&page=chat   直接看这道题的解析
?view=teacher&tab=problem                   直接进教师视图的题目页
?mode=self_training                         默认自主训练
```

不认识的参数一律忽略，不报错。这份链接也让自动化截图/回归有了入口
（本文档的截图就是这样生成的）。

### 6.6 路径轨道（本轮新增）

学生侧状态条上的一排编号点，随对话进度点亮。**只有编号，没有步骤名** ——
步骤名就是解法，悬停才显示"第 N 步"，教师版才带标题。

| 状态 | 外观 | 口径 |
|---|---|---|
| 已走过 | 绿点 + 绿连线 | 定位之前的步骤都算走过 |
| 当前位置 | 靛蓝 + 放大 + 脉冲 | 引擎现在认为你停在这一步 |
| 还没到 | 灰点 | —— |

写"已走过"而不是"已做对"，是因为定位本身是**推断**：
`locate.js` 的口径是"定位到第 N 步 ⇒ 之前的都算走过"，
UI 说得比对错更肯定就是在骗人。

教师侧「本次会话复盘」里是同一条路径的**真实轨迹**：每一步被问了几轮。
这个数字比"最后停在哪一步"信息量大得多 ——
学生可能先走到第 5 步又退回来问第 2 步，只记最后位置会把整条轨迹丢掉。
实测一节课里显示的"第 4 步 × 2 轮"，正好就是那道题的真实卡点。

**踩到的坑**：轨道上的点下面一开始挂了步骤名（`absolute` + `nowrap`），
8 个点挨在一起时 8 个标题全部水平重叠，糊成一团彩色的字 —— 截图里一眼能看到。
而步骤名在下方的列表里已经有了，轨道不必重复这一层。

### 6.7 陪伴方式的介入时机（本轮新增）

首页两张模式卡，列的是**介入规则**而不是功能卖点。
这几条不是宣传语，是 `route.js` 里真实的判断（`src/core/route.js:102-115`）：

| 场景 | 🧘 自主训练 | 🤝 学伴陪伴 |
|---|---|---|
| 你说"卡住了 / 给点提示" | ✅ 出声 | ✅ 出声 |
| 你只是说出思路 | ⏸ 沉默记录 | ✅ 先复述你说了什么，再问一个前提 |
| 你走岔了但没求助 | ⏸ 先说（除非高置信卡点） | ✅ 指出来 |
| 你已经接近完成 | ⏸ 不打扰 | ⏸ 不打扰 |

「当前模式」是**单一状态**，首页模式卡与对话页开关是它的两个视图。
这类"同一状态两个控件"的地方最容易漂移（首页显示 A、对话页显示 B），
而且不报错。`test/ui.test.js` 里有两条断言守着：
两个控件都覆盖两种模式、且 `setMode()` 必须同时更新两边。

### 6.8 语音输入（本轮新增）

对话输入框旁「说思路」按钮，浏览器不支持时**不显示按钮**
（而不是显示一个点了没用的东西）。识别结果**追加**到输入框，
不覆盖学生已经打的字。

为什么值得做：核心动作是"学生交出自己的思路"，
而真实学生在草稿上想问题时的表达是**口语**的。
"实时笔迹观测"需要硬件，语音输入是同一件事里**零硬件成本**的那一半。

> 文案必须与真实交互一致：这里最初写的是"按住说话"，
> 但实现是"点一下开始 / 再点一下结束"。写"按住说话"而实现是点击切换，
> 会让学生一直按着不动 —— 然后用不了。已改成「说思路 / 在听…点一下停」。

### 6.9 产品说明内嵌（已移除）

曾经有过：顶栏入口 → 白名单单文件路由（`serveDeck`），刻意不把 `share/` 挂成静态目录。

**试用后按反馈移除。** 移除清单：`router.js` 的 `serveDeck` 与路由、
`api/index.js` 与 `server/server.js` 的分支、`vercel.json` 的 rewrite、
`index.html` 的顶栏入口、`styles.css` 的 `.top-link`、`test/ui.test.js` 的三条断言。
现在访问那个路径返回 404。

> 取舍：**演示材料不该长在产品里。** 想展示就直接开 `showcase/index.html`。

### 6.10 文案不会被当成纯文本显示（本轮新增的守卫）

在 HTML / JS 模板字符串里写 `**加粗**` 不会生效，只会把星号原样显示出来。
这个坑踩过一次：模式卡下面那句"两种模式**都不会**给你答案"
在页面上就是带着星号的样子。

现在有两条断言：`index.html` 的可见文本、`app.js` 渲染模板（去掉注释后）
都不许出现 `**`。同一份文档习惯被带进渲染层是很常见的失误，
改起来只要一处，但很容易再犯。

## 七、完成判定（"学生答对了"）

### 7.1 一个不对称的设计

来自试用反馈：**"我直接把正确答案说出来了，它还在引导我。"**

原引擎刻意"不判对错"（怕变成对学生的评价），副作用是学生自己走通一步时系统继续追问。
现在（`src/core/verify.js`）：

| 学生这一轮 | 引擎的反应 |
|---|---|
| 说**对**了 | 确认（部分 → 还剩几问；全部 → 庆祝界面） |
| 说**错**了 | **什么都不说**，走原来的引导路径 |
| 只讲思路 | 照常引导 |

"说错了不指出"是刻意的：这个产品不做判卷，只做"陪你想"。

### 7.2 判定按"待求量覆盖"，不是"数了几个数值"

假阳性实测：自由落体题的参考答案含"总时间 t = 2 s"，
朴素抽取会把它当答案 —— 学生一提总时间就弹庆祝界面。**假庆祝比不庆祝更伤。**

修法：把参考答案**按分句挂到待求量上**（只在等号左边找符号）。
"由 h=½gt² 得总时间 t = 2 s" 的左边是 `h`，不属于任何一问 ⇒ 丢弃。

两个实现要点，都是踩出来的：

| 坑 | 现象 | 修法 |
|---|---|---|
| 按数值排除已知量 | `B = 0.4 T` 把答案 `E = 0.4 V`／`P = 0.4 W` 一起排掉了 | 排除必须**同值同单位** |
| 只按 `；` 分句 | `t = 2 s，故 v = 20 m/s` 挤在一句里，左边是 `h`，真答案被整句丢掉 | 中文逗号也要切 |

### 7.3 确认文本的判据比守卫更紧

| | 判据 |
|---|---|
| 守卫 | AI 不许说出**任何**答案 |
| 确认 | AI 不许说出**学生还没说**的答案（`findUnstatedAnswers()`） |

界面上的每个数字都来自学生原话（`matched[].quote`），引擎只负责放大。
返回前断言，失败直接抛错。

### 7.4 确认轮不许污染教学统计

同一个 bug 踩了两次：
① 层级分布里混进确认轮（"L0 澄清 N 次"里掺着"学生答对了"）；
② 卡点清单冒出"第 8 步 · 引导 1 轮 · 已接近完成"。

现在 `report.js` 把 `guidedLogs`（非确认轮）与 `confirmations` 分开：
统计只看前者，后者单独成一项 **"你自己算出的结果"** ——
它反而是个有价值的指标（学生自己走通了几次），且方向与 byLevel 相反。

### 7.5 一个被评测指标抓出来的设计缺陷

第一版把确认路径放在最前面直接 `return`，**跳过了观察与定位**。
评测立刻反映：定位命中率与错因命中率同时下降。

而那是最不该丢信息的一轮：学生说"E = 0.4 V"时，E **确实是对的**（与内阻无关），
但他可能同时漏了内阻（下一步算电流才踩到）。两件事不冲突。

**结论：确认只替代"提示"，不替代"观察"。** 代价是确认轮也调一次 observe。

## 八、语域：一位资深教师的措辞

`DRAFT_SYSTEM_PROMPT` 的身份从"坐在学生旁边的学伴"改成
**"一位有二十年教龄的中学理科教师，以学伴身份陪学生做题"**，并新增语域约束：

| 要求 | 为什么 |
|---|---|
| 规范的学科语言，量写清名称与单位 | "电流为 1 安"而不是"电流是 1" |
| 不用语气词 / 拟声词 / 颜文字 / emoji | 啊、哦、啦、哈、～ 与"资深教师"冲突 |
| 不用夸张与卖萌 | 超级、非常非常、太棒了、好厉害 |
| 句子完整，一句话只做一件事 | 复述 / 提问 / 给方向，不要混在一起 |

另外给了两种"循循善诱"的句式：**先承接再指向缺口**、**把结论变成可回答的问题**。

代码侧同步扩了 voice 关（`polishVoice`），并且**两类黑名单的处理方式不同**：

| 类别 | 处理 | 为什么 |
|---|---|---|
| 空话 / 夸张词（"加油""太棒了"） | 连所在小句一起删 | 它们通常自成小句 |
| 语气词（啦/呀/哦/嗯…） | **只删那个字** | 句尾助词，删整句会丢信息 |
| emoji | 按码点区间删 | —— |

注意**不包含「吗」「呢」**——它们是正常疑问助词，删了会破坏提问。

顺带清掉了一个我一直没注意的东西：组装消息时的 `👉` 前缀。
它同时是"可行动率"指标的检测标记，所以换成了 `【下一步】`（评测的检测式同步改了）。

## 九、布局：不钉住面板

反馈：**"向下浏览时，右侧那一栏固定住了，压住下面的内容。"**

根因是侧栏同时用了 `position: sticky` + `max-height: calc(100vh-…)` + 内部 `overflow` ——
这个组合会产生"钉住的面板盖住后续内容"的观感，而钉住本身只是个锦上添花的效果。

去掉之后整页按普通文档流滚动，遮挡在结构上就不可能发生。
**全站只有顶栏是 sticky**（那是它该有的行为），`test/ui.test.js` 有两条断言守着：
① 除 `.topbar` 外不许有 sticky；② 侧栏不许再用 100vh 的 max-height + overflow。

## 十、题干阅读框与长题目的读题截断

### 10.1 阅读框

需求原话：**"一个特别长的题目会把整个页面拉的特别长，我希望这个题目有一个恰当的显示区域，
超出的部分可以滑动观看。"**

做法：`.stem` 加 `max-height: min(46vh, 420px)` + `overflow-y: auto`，
溢出时给底部渐隐 + 一行提示；不溢出时两者都不出现（JS 按真实溢出量判断）。

**与"面板不许 sticky"是两件事**，见 §九。面板不钉住（防遮挡），
题干有边界（防拉长），两条边界同时成立，各有断言。

**踩到的一个坑**：`enhanceStemBoxes` 一开始挂在 `applyProblemToChat` 里，
而那个时候 `#page-chat` 还是 `display:none` —— `clientHeight` 为 0，
函数按"量不出来就不判断"提前返回，于是滚动提示**永远不出现**。
修法是把测量入口挂到 `showPage`（页面切换的必经之路）并等一帧。
现在有断言钉着这一点。

顺带：已知量在窄栏里改成两列网格（长条件按 flex 换行会一条占一行，七条堆七行）。

### 10.2 长题目的读题截断（做阅读框时顺手发现的）

那道六问的题读题**直接失败**，而报错是"读题阶段无法解析 JSON"。

真实原因是**输出被截断**：六问的图谱撑爆 `max_tokens`，返回半截 JSON。
4000 不够，而 8000 已是 deepseek-chat 上限。

| 修法 | 说明 |
|---|---|
| 错误分类 | `chat()` 带出 `finish_reason`；`=== 'length'` 时报"模型输出被截断（max_tokens 用尽）"，不再误报成格式问题 |
| 提示词压规模 | 路径 ≤2、总步数 ≤10、**多问题合并同类步骤**、cues ≤4、错因 ≤3、参考答案 ≤200 字 |

修完实测：8 步合并路径、6 个正确知识点、3 条错因、11 条指纹、`graphReady: true`。

**为什么这条比阅读框重要**：截断降级的后果不是"图谱糙一点"，而是**整题退回通用骨架** ——
知识点、错因、参考答案、**全部防泄题指纹**一起丢。
换句话说，**题目越长，"守卫对这道题失效"的概率越高**。

## 十一、符号输入

### 11.1 问题

学生反馈：**"一些物理的表达式很难写上去。"**

`²` `₀` `μ` `Ω` `√` `≈` 在普通键盘上打不出来。写不出公式的学生只能用文字绕，
**思路的表达精度直接下降** —— 而"看懂学生说到哪一步"正是这个产品唯一的立足点。

### 11.2 两层机制

| 机制 | 覆盖谁 | 说明 |
|---|---|---|
| 符号面板 | 所有人 | 点一下插到**光标处**（不是末尾），五组：上标/下标/希腊/运算/其它 |
| 自动替换 | 习惯 ASCII 的人 | `v^2`→`v²`、`mu`→`μ`、`>=`→`≥`，可关闭 |

规则放在 `public/mathinput.js`（**纯函数，浏览器与 Node 共用**），
所以 `test/mathinput.test.js` 能直接拿奇怪输入去砸它，规则不会漂移成两份。

**只认显式约定，不猜**：`^` `_` `>=` 这类是声明式的，见到就换；
而 `v0` → `v₀` 这种"猜意图"的一律不做 —— 它会顺手把 `sin53` 变成 `sin₅₃`。

**希腊字母延迟到边界才替换**：替换是逐字触发的，敲到 `pi` 时输入框
分不清 `pi`（圆周率）与 `pilot`（单词）。等非字母字符出现再动手，
失焦/发送前 flush 一次收尾。

> 这个坑只有**逐字测试**能发现：整串测试里 `pilot` 的 `pi` 后面跟着 `l`，
> 规则一开始就不成立，永远测不出问题。

### 11.3 后端对齐（这一半更重要）

前端只帮到"从界面上打字"的学生。真正影响判定的是：
**关键词通道的两边必须折到同一个写法上**。

```
cue:   v²=2aL
学生:  v^2=2aL     ← 不对齐，这条 cue 对他等于不存在，他被判成"没说对"
```

`normalize()` 里加 `foldSuperscripts`：`^2`→`²`、`_0`→`₀`。

### 11.4 这次改动引出的两个漏洞（都是评测发现的）

**① 证据重复计分**

折平后，同一式子的两种拼法（`a²=2b²` 与 `a^2=2b^2`）会同时命中，
那一步的证据数变成 2（实际 1 条）。定位按证据数排序 ⇒
**系统性偏向写得啰嗦的那一步**，两个数学场景卡在"两边平方"不肯往后走。
离线定位命中率 92.9% → 85.7%。
修法：`matchAll` 按归一化后的形式去重。

**② 死指纹**

折平后，写成 `^2` 的指纹永远匹配不上 ⇒ **悄悄失效**。
一条不工作的指纹比一条不存在的更危险（没人知道它没在工作）。
修法：`fingerprintMatches()` 同时试摊平形式（`unfoldScripts` 把 `²` 摊回 `^2`），
guard / verify / intake 三处统一走这个入口。
