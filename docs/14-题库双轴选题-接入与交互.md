### 1.2 缺口（我们正好要补的）

1. **只有"下拉"，没有"浮层"**。全站唯一的覆盖层是页五 `.bar-card .drop-list`：
   ```css
   .drop-list{display:none}                    /* 默认不存在 */
   .bar-card.open .drop-list{display:flex;animation:pop .18s ease both}
   ```
   它没有 overlay、没有焦点圈闭、没有 Esc 关闭、没有滚动锁、没有 `aria-modal`。**抽屉和弹窗在这套代码里是净新增**，不能靠改 `.drop-list` 长出来。
2. **题库还只是"示例列表"**：`#bankCount` 文案写死"6 道"，`renderBank()`（`public/index.html:1387`）把 `S.bank` 全量 `map` 成 `.q-item` 平铺；数据来自 `API.problems()` → `/api/problems`，而该接口的预览只带 `topics`（叶子名字的字符串），**没有 `kg` / `think` 的 id**——双轴筛选在数据面就先断了。
3. **举一反三纯前端**：`relatedProblems()`（`public/index.html:2203`）在 `S.bank` 里按 `topics` 字符串求交集，取前 6 道。152 题全在前端也不行——预览里没有双轴，也没有"为什么这三道算同类"的理由。
4. **`S` 是 IIFE 私有**：所有状态在闭包里的 `var S = {…}`（`public/index.html:1311`），IIFE 结束于 `public/index.html:2323` 且**什么钩子都没往 `window` 上挂**，外部脚本拿不到。要挂第二支脚本，必须由他们开一个明确的钩子口。

### 1.3 冲突风险（这条决定我们怎么动手）

**你说 main 马上要大更新 UI 和设计项目。** 那 `public/index.html` 这 2246 行在几天内会被重写一遍。所以：

> **不要往 index.html 的 `<style>` / `<script>` 里写我们的代码。** 一旦他们重写，我们的改动整块丢失，或者反过来把他们的大更新冲掉。

正确姿势（本文的核心工程决定）：

- 题库的界面代码放**独立文件** `public/qbank.css` + `public/qbank.js`，命名空间 `.qb-*`；
- `index.html` 总共只加 **3 行**：一个 `<link>`、一个 `<script defer>`、末尾一行 `window.BSJ = { S, API, setPage, renderBank, pickBank }`；
- 这 3 行的落地**排到最后一个里程碑**（M7），等他们的大更新合并完再插一次；数据面、服务端、管线、样式、脚本全部可以提前做完，互不冲突。

## 2. 接入总原则

1. **token 唯一来源**：新样式只写 `var(--*)`，不写字面色值、不写 px 字号。唯一例外是浮层需要的尺寸（`470px`、`560px`、`min(820px, 92vw)`），也必须先声明成新 token。
2. **不改他们的组件**：`.q-item`、`.bar-card`、`.tag`、`.btn-primary` 原样复用；需要变体就加 `.qb-` 前缀的新类，不改原类。
3. **不动引擎**：`src/core/{locate,engine,guard,analysis}.js` 除 `guard.js` 加一个选项级拦截函数（§9.1）外不改。
4. **学生端永不出现官方解析**：题库对象的 `officialAnalysis` / `referenceAnswer` / `solutionGraphs` 只走服务端，`qbank.js` 拿到的 preview 里绝无这些字段。
5. **离线优先**：抽屉的分类树、计数都是服务端算好下发的，前端不做聚合；筛选在服务端做（152 题虽小，但口径必须单一）。

## 4. 抽屉（Drawer）：双轴筛选

### 4.1 为什么是抽屉，不是弹窗也不是常驻侧栏

- **弹窗不行**：知识点 6 模块 / 30 章 / 103 叶子 + 思路 9 类 / 37 节点，要滚动、要展开折叠、要多选、要边选边看命中数。弹窗会盖住题库列表，选完才知道 "0 道命中"，来回开关最烦。
- **常驻侧栏不行**：页一一栏已经是 `min(748px,100%)` 的居中列（`.p1-col`），再塞一列会把出题区挤窄，而且页一的首屏任务是"输入题目"，不是"浏览题库"。
- **抽屉正好**：从右侧盖上来 470px（原型实测 380 装思路说明太挤），题库列表仍然可见（被遮罩压暗），选一个条件就实时看到"命中 N 道"，不满意继续勾，满意就关掉。

### 4.2 形态与尺寸

| 断点 | 形态 | 尺寸 | 出现方式 |
| --- | --- | --- | --- |
| `≥900px` | 右侧抽屉 | 宽 `470px`，`top:var(--topbar)` 到底，左侧圆角 `--r-card` | `translateX(100%) → 0` |
| `720–900px` | 右侧抽屉 | 宽 `min(470px, 86vw)` | 同上 |
| `<720px` | 底部 sheet | 高 `min(82dvh, 720px)`，顶部圆角 `--r-card`，把手 `36×4` `--r-pill` | `translateY(100%) → 0` |

坐标基准：`body` 是 `100dvh` + `overflow:hidden`，页容器 `.page` 是 `position:absolute;inset:0`。所以抽屉/弹窗必须 **`position:fixed` 且挂到 `document.body` 下**，不要挂进 `#app` 或 `.page`——挂进去就会被页容器困住（另外 `.page.is-active` 带 `pageIn` 动画，动画期间的非 `none` `transform` 会让它变成 `position:fixed` 后代的包含块，浮层位置会跳）。

│    ▸ 动量 17                       │  ← 章行
│       ○ 动量定理 6  ○ 碰撞 5 …     │  ← 叶子：checkbox 药丸
│  ▸ 电磁学 46  ▸ 实验 19  …          │
├────────────────────────────────────┤
│ 解题思路                         ⌄ │  ← 分区二
│  ▸ 正向递推 82                      │
│      顺着公式一步步往下算…          │  ← 类目下一行小字：这个思路在干什么

- 叶子是**多选**（一题本来就有多个 kg / think 标签，"至少命中其一"是交集语义，符合直觉）。
- 默认只展开**有命中**的分支；全部收起时显示"展开全部"。
- 段落内的计数用 `.tag`（已有样式），不新造徽标。
- 时间/空间都够，不做搜索框——103 个叶子里找"动量定理"靠眼睛比打字快。真需要时在 M6 加一个 `input`，不影响结构。

### 4.7 页五的滚动归属（2026-11-02 补充）

页五**整页不滚**，滚动只发生在"题目列表"里：

- `.p5-col` 加 `overflow:hidden`，`display:flex;flex-direction:column;min-height:0`；两张 `.bar-card` 是 `flex:none`，展开的那张 `flex:0 1 auto`；
- 「重做」的滚动容器是 `#redoStem`（题干长时自己滚，引导语和「重做一遍」按钮始终可见）；
- 「同类题再练」的滚动容器是 `#p5rec`（两个开关、已选范围 chips、说明行始终钉在列表上方）；
- 底栏 `.p5-foot`（当前题 / 换一批 / 返回题库）不参与滚动。

理由：第八屏的位移量一次只来自"换一批"，卡片是骨架、列表才是内容；整页滚会让两张卡和底栏一起漂走，学生会以为界面换了。

### 4.5 无障碍清单（净新增，必须做）

- `role="dialog" aria-modal="true" aria-labelledby="qbTitle"`；打开时焦点落到标题，关闭后回到「筛选」按钮。
- `Tab` / `Shift+Tab` 在抽屉内圈闭（首尾哨兵元素，8 行代码，不引库）。
- `Esc` 关闭；点击遮罩关闭；`aria-expanded` 同步在触发按钮上。
- 滚动锁：**不需要**。`body` 已经是 `height:100dvh;overflow:hidden`，滚动只发生在 `.scroller` 面板内部。要挡的是"面板内滚动"——给浮层遮罩加 `overscroll-behavior:contain` 即可，不改 `body`/`#app` 的样式。

## 5. 弹窗（Modal）：题目预览确认

### 5.1 为什么需要它（这才是弹窗的正当用途）

页一现在点题库条目就 `pickBank(i)` 直接选中、直接可进第 2 页。152 道题进来以后，误点的成本变了：进去就是一次真实会话（`/api/chat`，几秒 + 一份 token 账单），而且 `startSession()` 会清掉上一次的进度。**所以点一下不再等于决定**，中间加一层确认。

### 5.2 三个候选用途，只选一个做主

| 用途 | 判断 | 结论 |
| --- | --- | --- |
| A. 题目预览确认（点列表 → 看清题干和标签 → 就做这道） | 高频、每次选题都触发、成本高、误点代价明确 | **做主** |
| B. 官方解析/来源详情 | 学生端按 C5 不给官方解析；教师视图是独立链路，不该混进学生弹窗 | 不做 |
| C. 举一反三的同类题详情 | 页五已有 `.drop-list` 的选中态与 `#dropCur` 摘要，够用 | 不做，只把摘要写清楚 |

所以：**抽屉负责"筛"，弹窗负责"确认"，两个浮层各司其职，不重叠。**

### 5.3 形态与结构

- 宽 `min(560px, 92vw)`，`--r-card` 圆角，`--shadow-2`，居中；遮罩 `rgba(26,26,26,.32)` + `backdrop-filter:blur(2px)`。
- 头部：题型 / 难度 / 省份 三枚 `.tag`（复用），右侧 ✕。
- 体部：题干（`stemHtml`，公式图原样显示，`.scroller` 最大 `46dvh`）+ 知识点/思路标签行。
- 底部：`换一道`（ghost）+ `就做这道`（primary，初始焦点）。
- **不做"不再提示"开关**：152 道题库是本项目的主路径，跳过确认等于把这个功能关掉。真要减负，是让确认卡更快（`Esc` 即关闭、`Enter` 即确认）。

### 5.4 无障碍

`role="dialog" aria-modal="true"`、焦点圈闭、`Esc` 关闭、关闭后焦点回到被点的 `.q-item`、`aria-describedby` 指向题干首段。

## 6. 动效（Motion）规格

### 6.1 时长梯度（沿用他们已有的数字，只补一档）

| 档 | 时长 | 用在哪 |
| --- | --- | --- |
| D1 | 120ms | hover / press / 勾选反馈 / 遮罩淡出 |
| D2 | 180ms | 遮罩淡入、chips 出现、下拉、列表项选中 |
| D3 | 240ms | 弹窗进出、卡片进出、列表结果 crossfade |
| D4 | 320ms | 抽屉进出（唯一的大位移） |

他们的代码里已经在用 `.16s / .18s / .2s / .22s / .25s / .28s`，**不要回头统一改写**（会和 main 的大更新打架），新代码只用上表四档。

### 6.2 缓动

- 进入：`cubic-bezier(.2,.8,.2,1)`（快出慢停，像抽屉"甩出来"）
- 退出：`cubic-bezier(.4,0,1,1)`（慢慢出去，比进入快——退出的动画 240/320 已经够短，缓动要偏线性）
- 状态色变化：`ease`，180ms

### 6.3 具体动作

| 动作 | 规格 |
| --- | --- |
| 打开抽屉 | 遮罩 opacity 0→1 / 180ms；面板 `translateX(100%)→0` / 320ms / 进入缓动；两段同时开始 |
| 关闭抽屉 | 面板 `0→100%` / 240ms（比打开快）；遮罩 120ms；`transitionend` 后 `hidden`，并挂 400ms 超时兜底（用户中途改窗口尺寸会漏 `transitionend`） |
| 打开弹窗 | opacity 0→1 + `scale(.98)→1` / 240ms |
| 关闭弹窗 | opacity 1→0 + `scale(1→.99)` / 160ms |
| 筛选结果刷新 | 旧列表 `opacity→0` / 120ms，新列表 `opacity 0→1` + `translateY(4px)→0` / 180ms。**不做高度/重排动画**，列表长度变化直接换 DOM |
| 列表项逐项进入 | 首屏最多 8 项做 stagger，每项 +20ms，第 9 项起不加延迟（`.q-item` 上有 `animation-delay`，用 `nth-child` 前 8 条写死，不写 JS 循环） |
| 计数变化 | 数字直接换文本，不做滚动数字（页一 `#bankCount` 是 13px 小字，滚动反而晃眼） |

### 6.4 硬约束

- **只动 `transform` / `opacity`**。不动 `width/height/top/left/margin`，不动 `filter:blur()`（`backdrop-filter` 只放在遮罩上且是静态值）。
- 每一处位移动画都必须有 `@media (prefers-reduced-motion:reduce)` 对应：位移去掉，只留 ≤80ms 的 opacity，或者直接 `animation:none`。
- 抽屉/弹窗打开期间不触发 `layout`（不读 `getBoundingClientRect` 做位置计算，位置全由 CSS 定）。
- 动效不得阻塞交互：`pointer-events` 在打开后立即生效，不等动画结束。

## 8. 数据与接口

### 8.1 preview 加字段（最小改动，无泄漏）

`listProblems()`（`src/core/registry.js:117`）与 `/api/qbank/search` 的条目统一成这个形状：

```js
{ id, source, subject, kind, module, difficulty,
  topics: ['动量定理'],            // 叶子全名，向下兼容现有 UI
  kg: ['k22','k31'],               // 知识点叶子 id
  think: ['t1a','t5b'],            // 思路节点 id
  thinkNames: ['单公式直接代入'],   // 给页五写"为什么同类"用
  province: '云南', type: '单选',
  teachReady: true,
  stemPreview: '…前 60 字…' }
```

**不含**：`referenceAnswer`、`officialAnalysis`、`solutionGraphs`、`misconceptions`、`givens`、`asked`。`toStudentProblem` 的白名单照旧。

### 8.2 三个新接口

> **2026-11-02 增补**：`/api/qbank/related` 用两个独立开关，不做三选一：`kg=1|0`（同类型题）、`th=1|0`（同思路），都缺省 0；手挑范围传 `kgIds=k22,c-力学-动量&thIds=t2d`，会顶掉同一条轴上由开关推导出的标签。每条结果带 `reason: {axes:['kg','th'], ids, text}`（`text` 是「动量 › 碰撞模型、动量守恒」这种给人看的短句，服务端拼好；两个轴同时命中时 `text` 取权重更高的那条轴，`axes` 用来在卡上标「同类型 · 同思路」）。
> 打分用 `log(152 / 节点题量)` 做稀有度权重：共享「动量守恒」（11 题）比共享「牛顿第二定律」（13 题）更能说明同类。
> 只开「同思路」（`th=1&kg=0`）时**知识点重合越少越靠前**——练迁移要换情境，不要换汤不换药。


| 接口 | 作用 | 返回 |
| --- | --- | --- |
| `GET /api/qbank/taxonomy` | 抽屉的两棵树 + 计数 | `{ kg:{modules:[{id,name,count,chapters:[{id,name,count,leaves:[{id,name,count}]}]}]}, think:{groups:[{id,name,count,nodes:[...]}]}, total, teachReady }` |
| `GET /api/qbank/search?kg=a,b&think=c&type=&difficulty=2,3&province=&q=&offset=0&limit=50` | 页一筛选 | `{ total, offset, limit, items:[preview] }` |
| `GET /api/qbank/related?id=xxx&kg=1&th=0&kgIds=&thIds=&limit=8` | 页五同类题 / 重做后的换题 | `{ pool:n, items:[preview], reasons:{ [id]: {axes, text} } }`（`pool` 是当前范围里还能选几道，抽屉底部那句「范围里还有 N 道」用它） |

`related` 的排序（服务端）：同叶子知识点命中数 ↓ → 同思路节点命中数 ↓ → 同模块 → 难度接近。**不用随机**，否则"举一反三"每次点都不一样，学生会以为坏了。

### 8.3 兼容

- `/api/problems` 继续可用，只是 preview 里多带了 `kg/think/...`；页五的 `relatedProblems()` 可以先不改就拿到更好的数据。
- 题库超过 200 道再考虑给页一加分页；152 道一次下 50 条 + 滚动加载就够。

### 8.4 存储与公网部署（2026-11-02 决定：上公网）

按"谁都能看 / 谁都不能看"切成两半，而不是给同一份 JSON 加鉴权：

| 产物 | 内容 | 落点 | 大小 |
| --- | --- | --- | --- |
| `index.json` | 152 条 preview（§8.1 全部字段，不含图） | 对象存储公开桶（或函数包，500KB 以内都行） | ~400–600KB |
| `stem/{id}.json` | `stemHtml`（图片内联 data URL）、`options[]` | 对象存储公开桶 + CDN | 典型 100KB，最重 480KB，合计 ~13MB |
| `teach.data.json` | `solutionGraphs`、`givens/asked`、`referenceAnswer`、`officialAnalysis`、`answerFingerprints`、`correctOptions` | **构建产物进函数包** `src/core/qbank/teach.data.json`，import 使用 | ~600KB–1.5MB |

**为什么图谱进包而不是进对象存储**：Workers 免费版包上限 3 MiB（付费 10 MiB），`teach.data.json` 在 1.5MB 以内、压缩后更小，三平台（Workers / CloudBase / Vercel）都能直接 `import`。它一旦进了对象存储，就得给私有桶配签名 URL，等于多一套鉴权要维护，而且有配错成公开桶的风险；进包则**根本不存在 URL**。

**读取适配器**（`src/core/qbank/store.js`，一个接口三个实现）：

```js
// QBANK_STORE=local | r2 | memory
readIndex()            // → preview[]
readStem(id)           // → { stemHtml, options }
readTeach(id)          // → { graphs, givens, asked, answer, analysis, fingerprints }（只从 import 的包里取）
```

- `local`：读 `data/qbank/{index.json,stem/*.json}`，`npm start` 与 `npm test` 用。
- `r2`：Cloudflare R2 绑定（`env.QBANK.fetch('/index.json')`）；Vercel/CloudBase 走 S3 兼容 endpoint 或直接把 index 打进包、stem 走 `QBANK_BASE_URL`（CDN）**由前端直取**。
- `memory`：测试桩。
- 前端取 stem 走**直连 CDN**（`QBANK_BASE_URL + '/stem/' + id + '.json'`），不经函数转发——既省一次冷启动，也避免 13MB 走 Node 函数。

**上线检查清单**（M4 的出口条件）：
1. `teach.data.json` 不在 `public/`、不被任何 `GET` 路径命中；`curl` 一遍 `/teach.data.json`、`/data/qbank/teach.data.json`、`/src/core/qbank/teach.data.json` 全部 404。
2. 对象存储桶策略：只有 `index.json` 与 `stem/*` 可匿名读，其余 private。
3. `QBANK_STORE` 缺失时自检失败即**退回 5 道手写题**并打日志，不 500。

## 14. 已定决定（2026-11-02，你拍的板）

### 我替你做的、需要你扫一眼的四个小决定

1. **抽屉 + 弹窗各司其职**：抽屉只筛，弹窗只确认，不做"抽屉里也能点题开始"。
2. **不做第六页**：题库是页一的一张卡 + 页五的一张卡。
3. **举一反三服务端排序**（同知识点 → 同思路 → 同模块），不随机，且卡上写同类理由。权重用稀有度 `log(152 / 节点题量)`——共享"动量守恒"比为共享"牛顿第二定律"更像同类；只开同思路时知识点重合越少越靠前（练的是迁移，不是换汤不换药）。
4. **换题范围是两个开关，不是一个三选一**：同类型题、同思路各自独立，都关＝不筛选，两个都开＝交集；手动筛选（抽屉里挑别的知识点 / 思路）顶掉同一条轴上开关推导出的标签，所以四种组合都能走通。
4. **筛选条件进 URL hash**，刷新可恢复，截图回归能直接进某个筛选态。
