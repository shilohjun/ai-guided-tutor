# 学习报告 v7：按学生证据判断

保留报告布局、掌握/待巩固/薄弱三栏、卡点卡片及操作。只把原“正确率”区域改为“本题完成情况”。不新增账号或历史恢复入口，不修改云端部署。

## 计算口径

- 完成数：各小问**最后一次**已核验正确的结果。再次答错会重新打开该问；修改正确后保留首次错误。
- 总数：题目待求小问（选择题为一次完整选择）。缺少待求量时不生成分数。
- 无可信参考答案：可记录“已作答、结果待核验”，不计为错误或已完成，不计算百分比。
- `completion` 同时保留独立完成、提示/示范后完成、待核验数量。前端显示完成数/总数，详细口径在该区域说明中。原首次准确率字段仅保留兼容性，不再展示。

## 知识判断与卡点

新增 `report-checkpoints.js`，为题干/知识标签符合范围的题提供人工审阅的检查点：合力与单力做功、功的正负、恒力做功的条件、平均功率、光电门槛、磁通量变化率。保留原5道电磁感应题的细分规则。它们可用于题库题和上传题，不再只按题目ID判断。

每个检查点记录学生原话、轮次、消息位置、是否经过相关提示、是否曾出错、是否后来修正，并给出该检查点的验证任务。

- 掌握：仅指本题中，学生独立给出符合规则的步骤和依据，不宣称长期掌握。
- 待巩固：公式正确但依据不清，或相关提示后完成，或从错误中修正。保留本次具体表现及迁移任务。
- 薄弱：有学生原话支持的明确错误，尚未修正。并非仅因“不会”或多次提问而判错。
- 无证据/规则未覆盖：不推测。可保留求助过程和待核验项。不要把所有题库标签当作学生薄弱点。

学生带“所以……对吗”的错误推理也可以成为概念检查证据；纯提问、引用、假设和含混表达不直接判错。结果核验与概念判断独立：会列公式不代表数值正确，答案正确也不代表理解原理。

## 一致性

支持“改选/改为/更正为”等表述，以及带中间计算的等式链。聊天采用服务端答案账本：已核验错误的结果不再被模型的赞同覆盖。模型尚未核验的上传题不使用这条硬判定。

报告保存输入版本指纹。新对话正常触发重算；即使旧快照未及时清除，也会在输入版本变化后重算，旧报告归档保留。已有v2/v3报告在题目上下文可用时升级一次。

## 限制与后续扩充

这是可审计的规则基线，**不是全题型语义判卷器**。未配置的知识点、复杂否定、跨句推理仍可能漏判；不应通过降低证据要求制造丰富但不可靠的结论。

后续按内测高频题补充规则与样例。每个新增检查点至少有：范围、正确解释、典型错误、相关提示、针对性练习；测试包括纯提问、引用、否定、错误修正、无关提示、AI原文复述。若接入模型做语义诊断，另需证据引用校验与教师标注评测，不直接采信模型自述“学生已掌握”。

## v5 真实对话修复

- “力乘位移”“把功摊到几秒里”等口语提示计入对应检查点的帮助记录，即使模型误标成低层级。一般鼓励与其他知识点的提示不计入。
- 求助条目逐条关联对应提示和后续正确解释；同组中仍有未解决的求助时，不整体清除。短追问沿用上次明确问题的焦点。已经解决的记录保留原话，状态变为已回应，并给独立验证任务。
- 核验依据不完整时，原统计区域显示“已作答几问/总共几问”，补充已核验与待核验数量；不将待核验显示为未完成百分比。
- 服务端把本轮有依据的概念解释传给起草模型，要求不重复追问已说明的时间、方向和公式前提。这是提示约束，不保证任意表述下都不会出现重复追问；需持续真人复测。
- v4 报告会在上下文可用时升级为 v5，历史报告继续保留。

## v6 否定、修改与分句修复

- 新增报告专用 `report-claims.js`。先切分独立陈述，再处理“不是X，而是Y”、公式前后的否定和替换；不会仅因出现正确公式字符就判掌握。
- 后续明确错误会撤销先前的掌握。后续式子不在可核验范围时，也会撤销旧结论并显示待核验；未识别的式子不自动判错。一轮内互相矛盾且没有明确修正方向的陈述保持待核验。
- 正确解释后另问一个小问，不再因整条输入含“不确定”而丢掉前半句的证据。
- “合外力/合力”“牵引力/拉力”在报告判断中归一化，但证据仍保留学生原话。
- 数值作答按各待求量的标记分开，再识别各自的等式链。`W=60 J P=20 W` 不再把后面的功率当成功；支持“拉力做了60焦耳的功，平均功率是20瓦”这类明确指向物理量的表达。
- v5 及已知旧版本报告在上下文可用时自动升级为 v6，并归档原报告。UI 和云端部署未改。

验证包括常规回归、否定/替换/先对后错/含疑问的分句/相邻数值/同义表述，以及真实 DeepSeek 读题与聊天接口重放。真实重放确认：两类错误均进入薄弱和卡点，后续修正转待巩固，四个无标点分隔的结果核验为4/4完成。规则仍有覆盖边界，不能推断成全题型语义判卷已经可靠。

## v7 单一重点与历史薄弱

- 上方统计卡改为“本次最需巩固”，服务端 `priorityFocus` 只给一个重点：当前未修正错误优先，其次是曾错且已修正但没有独立验证的项目，再其次是提示后完成或尚待回应的求助。没有证据时不虚构重点。
- `knowledge` 继续描述当前表现，新增 `weaknesses` 保存本次明确出现过的错误。已修正项的状态为 `corrected_pending_independent_check`，显示“曾出错，本题已修正，尚待独立验证”；不再因为改对一次就从薄弱记录消失。
- 独立验证记为 `not_recorded`。当前系统没有独立迁移测试的可信记录，不把“懂了”、重复提示或在同一对话里改对自动当成独立验证通过。本改动没有新增验证题或登录流程。
- 三行展示不重复收录同一项目：历史薄弱单列在“薄弱”行，其他提示后完成的内容保留在“待巩固”行。“掌握”无证据时明确显示“本次尚无独立掌握证据”，不为了填满栏目制造掌握结论。
- “卡点与改进”仍保留错误与修正经过。数值结果错误如果尚未定位到概念，保留作答层面的历史记录，不编造具体知识点。
- v6 及已知旧版报告在题目上下文可用时升级为 v7，原报告归档。版式、按钮、聊天交互不变。
